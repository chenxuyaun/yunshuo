# 云说 · Yunshuo

[![CI](https://github.com/chenxuyaun/yunshuo/actions/workflows/ci.yml/badge.svg)](https://github.com/chenxuyaun/yunshuo/actions/workflows/ci.yml)

面向长篇小说团队协作的自托管写作工坊。AI 只提案，人工提交；每一章都要经过五道门禁与完整审计，正典版本可追溯。

云说把“写小说”拆成一条可审计的流水线：**章节租约 → 草稿 → 五道门禁 → 五类审计 → 隔离暂存 → 唯一提交链 → 正典版本**。在人工主流程之上，逐步加入 AI 续写提案、混合检索、显式授权的无人值守逐章生成、团队账号与工作区、预算与账单对账，以及单机 Docker 部署。

**核心原则**

- AI 不能直接写草稿或正典，也不能申请或批准豁免；无人值守只在所有者/主笔显式授权后运行。
- 未接入的能力显示“未接入”；无嵌入服务时索引显示“未配置”；导入章节的门禁是“未评估”。不伪造成功、数据或 ready 索引。
- 成本是按价表与 token 用量计算的估算值，不是供应商账单；未知费用不猜造数字。
- 密钥加密存库，接口与审计不返回明文；开发登录仅限本机，生产必须关闭。

## 功能

- **单章闭环**：15 分钟章节租约，保存、暂存、提交都要求持租；五道硬门禁与五类审计。
- **修订、回滚与豁免**：版本全量保留；回滚需匹配证据或一次性豁免；申请人不能自批，AI 没有豁免入口。
- **AI 提案**：SSE 流式续写/加厚，多服务商优先级路由、重试与故障转移；采用后仍需人工保存并过门禁。
- **混合检索**：中文 bigram 词法 + pgvector 向量，RRF 融合；未配置或低置信时如实降级为词法。
- **设定与角色账本**：工作区级设定条目与角色档案、不可变版本、草稿/发布/归档/回滚、字段级差异与搜索；角色状态绑定“截至第 N 章”，写作台按上一章展示并提示死亡复活、死亡后出场与关系冲突；审阅者只读，计费角色不可见。
- **无人值守作业**：零模型调用预检，逐章生成并过门禁，全部通过才以 `batch` 入库；支持暂停、恢复、停止与撤销。
- **团队与账号**：本地密码账号、邀请、角色与工作区隔离、密码重置、OIDC/SSO。
- **预算与对账**：工作区月度生成预算、按用途/成员/作业/章节的费用归属、供应商账单 CSV 导入与逐模型对照。
- **部署与导入**：Docker Compose 单机全栈，含迁移、bootstrap、健康检查、nginx 反代与备份脚本；支持旧章 Markdown 批量导入。

## 技术栈

TypeScript + Node 24 + Fastify 5 + PostgreSQL 17/pgvector + Drizzle（迁移）+ React 19/Vite/TanStack Query + 原生 CSS。

## 启动

```bash
pnpm install
pnpm db:up
pnpm db:migrate
pnpm db:seed
pnpm dev
```

- Web: http://localhost:5173
- API: http://localhost:3100
- Postgres: localhost:5433

开发登录：登录页可用邮箱密码，或选择种子用户（owner / author / lead）直接进入。开发身份依赖 `DEV_AUTH=1`，仅限本机验证；生产环境必须设置 `SESSION_SECRET` 并关闭开发登录。种子用户没有默认密码；密码账号由邀请接受或“忘记密码”创建。

OIDC/SSO：设置 `OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_REDIRECT_URI` 后，登录页显示“使用 {提供方名称} 登录”。一个部署只接一个 IdP；首次登录要求 IdP 返回 `email_verified=true` 且邮箱已存在，或存在待接受邀请并开启 `OIDC_AUTO_PROVISION=1`。详细约束见 `.env.example`。

邮件投递：非生产默认 `MAIL_MODE=memory`（进程内开发邮箱，不真实投递），生产默认 `off`；生产设置 `memory` 会启动失败。真实发信需 `MAIL_MODE=smtp` 并至少配置 `MAIL_HOST` 与 `MAIL_FROM`，发送结果如实记为 `sent / failed / not_configured`。开发内存邮箱只在 `DEV_AUTH=1` 且 memory 模式下通过 `GET /api/dev/mailbox` 可读，详见 `.env.example`。

API 进程默认启用 M4-B 作业 runner（`AUTOMATION_RUNNER=1`，轮询间隔 `AUTOMATION_POLL_MS` 默认 2000 ms，范围 250–60000）。只想跑单章流程时可设 `AUTOMATION_RUNNER=0`；runner 与 API 同进程，API 重启会中断正在执行的章节，作业需人工恢复。

pnpm test        # 串行跑各 workspace；集成测试会写入真实数据库

GitHub Actions 在 push 到 `main` 和 pull request 时运行同一套检查：PostgreSQL 17 + pgvector 服务容器、迁移与种子、类型检查与全量测试。

**M4-B 起必须使用独立测试库跑集成测试。** M4-B 测试会创建真实作业；若与开发 API 共用主库，开发进程里的 runner 可能领取测试作业并调用真实模型。测试库只需建一次：

```bash
docker exec yunshuo-db createdb -U yunshuo yunshuo_test
DATABASE_URL=postgres://yunshuo:yunshuo@localhost:5433/yunshuo_test pnpm db:migrate
DATABASE_URL=postgres://yunshuo:yunshuo@localhost:5433/yunshuo_test pnpm db:seed
pnpm test
```

浏览器验收：登录 → 取得租约 → 填入演示草稿 → 保存 → 跑五门禁 → 运行审计 → 暂存 → 勾选目标章 → 写入正典 → 查看版本证据。

M2 验收：打开已正典章节 → 开始修订（自动取租约）→ 第二人写入得到租约冲突 → 放弃修订回到正典；提交新版本后从版本列表选择旧版本回滚 → 复用门禁证据或使用已批准豁免 → 确认新版本 `source=rollback`、旧版本全部保留；作者申请回滚豁免 → 主笔批准（申请人不能自批）→ 界面永久显示“已豁免”。

## 单章提交链（M1）

- 一个工作区、一个作品、两章演示数据；章节目录与单章写作台。
- 章节租约：15 分钟 TTL，同一时间一名人类编辑；保存、暂存、提交都要求持租约。
- 草稿保存：空稿拒绝；保存后显示字数与 sha256 哈希。
- 五道硬门禁：字数、AI 腔调、核心实体、章末钩子、因果律；规则集 `dev-v0`，界面标注“非生产”。
- 五类审计：AI 味、错别字、标点、敏感词、文内连贯度；只提示，不改正文；未接入的检测器显示“未接入”。
- 隔离暂存：绑定门禁证据与正文哈希；修改正文后旧证据失效。
- 提交：显式目标章、期望当前版本、幂等键、二次确认；单事务写版本、当前指针、章节状态、元数据、事件、审计、outbox。
- 索引：提交后 outbox worker 异步切块与嵌入；嵌入服务未配置时如实显示“未配置”并保留正典，检索只跑词法且说明原因。
- 导入章：来源“迁移导入”，门禁“未评估”，不补造通过结论。

## M2 修订 / 回滚 / 豁免

- 修订：仅正典章节可开始；开始即取得 15 分钟租约并生成基于当前正典的草稿副本。放弃修订回到正典并释放租约；持租约者之外的人保存、暂存、提交均返回租约冲突。
- 回滚：仅所有者/主笔可执行；要求目标属于本章、比当前更早、期望当前版本匹配，并阻止活跃租约。写入新版本 `source=rollback`，旧的导入/提交/回滚版本全部保留。
- 证据复用：目标版本若存在内容哈希与上下文哈希均匹配的“通过”门禁评估，可直接回滚并记录 `evidence=reused`。
- 回滚豁免：无匹配证据时，必须引用已批准且未使用的 `rollback` 豁免，记录 `evidence=waived`；同一豁免只能使用一次。目标版本本身仍保持“未评估”，不会因回滚被补造成“已通过”。
- 豁免审批：仅支持 `rollback` 门禁；仅所有者/主笔可批准或驳回；申请人不能审批自己的申请；同一版本同时只能有一个待审批或已批准未使用的豁免。
- 幂等：提交与回滚共用幂等键命名空间但以 `operation` 区分，跨操作复用幂等键返回 409；相同操作重放返回 `alreadyCommitted=true`。
- 迁移：`0003_m2_waivers_rollback.sql`（豁免状态/决策人）与 `0004_commit_intent_operation.sql`（提交意图操作类型）。

## AI 提案（M3）

写作台内生成续写或加厚提案，流式展示，人工采用后才进入编辑区；AI 不保存草稿、不跑门禁、不暂存、不写正典。

- 入口：写作台“AI 提案 · 不自动落盘”。要求持租约、章节可编辑、编辑区无未保存修改；加厚模式还要求已有非空草稿。
- 生成：`POST /api/chapters/:id/ai/proposals`，SSE 返回 `meta / delta / attempt / done / error`；客户端断开即中止上游请求，并记录 `CLIENT_ABORTED`。
- 生成锁：`ai_generation_locks` 以章节为主键，跨用户、跨进程互斥，5 分钟过期。锁被占用时返回 409 `AI_GENERATION_IN_PROGRESS` 并提示持锁人与剩余时间；进程中断留下的过期锁会在下一次生成时回收，旧提案与在途调用标记为 `failed / AI_ABANDONED`。正常结束（成功、失败、客户端断开）都会释放锁。
- 服务商路由：按 `priority` 升序（同优先级按创建时间）加载最多 3 个已启用服务商，逐个尝试；单个服务商最多 2 次，总尝试最多 4 次，退避 600/1200/1800 ms，整体 120 秒截止。没有已启用服务商返回 `NO_MODEL_PROVIDER`；全部启用项密钥都无法解密返回 `PROVIDER_KEY_UNREADABLE`，不会伪造输出；单个密钥不可读的候选会跳过并记录。
- 重试与故障转移：仅当尚未输出任何正文增量时重试。HTTP 408/429/5xx、空输出与网络错误可在同一服务商重试；401 等明确错误不原地重试，直接切换下一个候选；若 400 明确因不支持 `stream_options`，同服务商去掉该参数重试一次（此时可能拿不到用量，成本显示未知）。已输出正文后失败不再重试或切换，保留部分正文供审阅但不可采用。切换通过 `attempt` 事件告知界面。
- 成本：服务商可配置每百万 token 的输入/输出价与币种（CNY/USD），两项必须同时填写。成本仅由已配置价表与服务商返回的 token 用量计算，保留四位小数；价表缺失或上游未返回用量时记为未知（`null`），不估造数字。界面明确标注为“估算”，不代表供应商实际账单。
- 上下文包：本章计划、作者补充要求、上一章结尾、当前草稿结尾（续写取尾段，加厚取全文且限 8000 字）、正典检索片段（M4-A）；每段带原字符数/实际使用数/是否截断。检索只使用本章计划关键词与作者补充要求，排除当前章；引用格式 `[R1] 第N章《标题》·vX·第a-b段`。设定库已可维护（M6-1），角色档案与状态时间线已可维护（M6-2），伏笔台账已可维护（M6-3），但三者尚未进入 AI 上下文；界面显式标注这一边界。
- 用量与审计：`ai_proposals` 保存提案正文、哈希、字数、上下文、尝试次数、用量、成本、延迟与失败码；`model_calls` 每次尝试一行，记录 `attempt_no`、状态、token、成本与错误。成功/失败都写 `events` 与 `audit_log`，审计不含正文与密钥。
- 采用：续写追加到编辑器末尾，加厚替换编辑器；只标记未保存。提案基于旧草稿时二次确认。采用后仍须保存草稿 → 五门禁 → 暂存 → 提交。
- 历史：列本章最近 10 份提案，含失败记录、尝试次数与成本；迁移前的旧提案显示“尝试次数未知”。可载入历史提案查看，但同样必须经人工保存与门禁。
- 迁移：`0005_m3_runtime.sql`（服务商优先级/价表、提案与调用尝试/成本、生成锁表）。

## 模型服务商配置（M3 前置）

登记端点、拉取模型列表并测试连接；生成调用使用同一服务商配置，并参与优先级路由与成本估算。

- 入口：页头“模型服务商”。所有者可新增、修改、删除；主笔可查看、拉取与测试；作者无入口（API 返回 403）。
- 用途：`chat`（生成）与 `embedding`（索引/检索）分离；创建后不可修改。生成路由只取 `chat`，嵌入路由只取 `embedding`。同一端点可以建两行；嵌入行可通过 `reuseKeyFromProviderId` 复制已保存的密钥密文，不经过明文。
- 价表：`chat` 的输入/输出价必须同时填写或同时留空；`embedding` 只允许输入价，输出价必须为空。成本仍只在有价表且有 token 用量时计算。
- 模型列表：表单里的“拉取模型列表”请求 `GET {baseUrl}/models`，返回的模型 ID 可点选填入。新增时可使用刚输入的 API Key；编辑时留空则复用已保存的加密密钥，显式“清除密钥”后不再复用。
- 嵌入探测：所有者可对任意 OpenAI 兼容端点调用 `POST /api/model-providers/probe-embedding`，发送固定短文本“云说嵌入连通性探测。”，10 秒超时、不重试、不创建或修改服务商；只写审计，不记密钥与探测文本。返回是否支持、维度、延迟与用量。
- 本地嵌入：2026-10-21 使用 Ollama 的 OpenAI 兼容端点 `http://127.0.0.1:11434/v1` 与 `bge-m3:latest`（1024 维，无需密钥，输入价 0）。该行 `purpose=embedding`，只在本机可达；换机器或远程部署时需改为基础地址可访问的嵌入服务并重建索引。
- 连接测试：同样请求 `GET {baseUrl}/models`，8 秒超时；不发送正文，也不消耗生成额度。结果记录状态、消息、延迟与时间。
- 鉴权目前只支持 `Authorization: Bearer`；Azure 等非 OpenAI 兼容鉴权不在当前范围。
- API Key：AES-256-GCM 加密存库，接口只返回是否已保存与尾号，审计只记名称、端点、模型与测试结果，不记密钥。
- 加密主密钥优先 `MODEL_KEY_SECRET`；开发环境未设置时回退 `SESSION_SECRET`，界面会显式提示。生产环境必须设置独立值且不能与 `SESSION_SECRET` 相同，否则 API/worker 拒绝启动。轮换密钥后需重新录入 API Key。
- 修改基础地址、模型或密钥会清空旧测试结果，避免旧结论冒充新配置；删除已被模型调用引用的服务商返回 409。
- 已保存但未测试的服务商显示“尚未测试连接”，不会冒充可用。
- 优先级与价表：优先级 1–999，数字越小越先尝试；输入/输出价同时留空表示“未配置价表”，此时生成成本显示为未知。
- 远程出站：嵌入会把正典片段发送到所配置的端点；检索查询只发送本章计划关键词与作者补充要求，不发送草稿。界面显式提示这一点。M4-B 的自动作业另有远程策略：授权未勾选“允许远程模型”时，预检与 runner 都只接受本机端点。

## 正典索引与混合检索（M4-A）

范围只覆盖正典片段，不检索设定库、角色档案或伏笔台账（账本已可维护，检索集成属于 M6-4）；不包含批量写作与无人值守入库（M4-B）。

- 数据：`canon_chunks` 绑定工作区/作品/章节/正典版本，保存块序号、段落与字符区间、原文、CJK bigram 词法文本和内容哈希；`chunk_embeddings` 保存 provider/model/维度与无固定维度声明的 pgvector 向量。旧版本块保留，但检索同时绑定 `canon_current`、`index_status.ready` 与块自身版本，旧版本永不返回；草稿不进入索引。
- 入队：提交/回滚/手工重建统一使用稳定键 `dedupe_key=index:<versionId>:reindex`。已有 `pending/processing` 任务时不重复入队、不重置索引状态，返回 `alreadyQueued`；仅当现有任务为 `processed/failed` 时重新激活。重复点击不再产生重复嵌入费用或片段 UUID 抖动。单章重建限所有者/主笔，工作区重建限所有者。
- worker：启动与每次 tick 回收 `processing` 超过 5 分钟的任务；只领取 `next_attempt_at <= now()`。切块目标 500 字、单块上限 800、重叠 80；每批 16 块，20 秒超时；同模型最多 3 个候选、每个 2 次尝试，退避 600/1200 ms；不同模型不混合故障转移，维度不一致直接失败。
- 写入：全部批次成功后用单事务锁 `index_status`、复核当前正典版本、删除同版本旧块、写入 chunks/embeddings 并置 `ready`；期间出现新提交则丢弃旧结果，不覆盖新状态。`ready` 是终态：迟到的 `markIndexing`、失败/重试写回和重复任务都不能把已就绪索引降级或重写片段。
- 重试：可重试错误按 1/5/15/60 分钟退避，最多 5 次；无可用服务商时置 `not_configured` 并消费任务；401、空正文、维度不符或次数耗尽置 `failed` 并保留原因。
- 检索：`GET /api/search?q=&workId=&excludeChapterId=&mode=auto|lexical&limit=`。`mode=lexical` 是诊断用强制词法模式，不调用嵌入服务并返回明确原因；默认 `auto`。中文词法用 bigram + GIN `to_tsvector('simple', lexical_text)` 与 `ts_rank_cd`，单字/无 token 退回转义后的 `ILIKE`；向量用当前启用的首个嵌入服务商嵌入查询，按 `model + dimensions` 过滤后精确余弦取前 30；词法/向量各取前 30，RRF(k=60) 融合取前 8，同章重叠段落只保留排名更高的一条。
- 相似度下限：向量邻居逐条按 `SEARCH_VECTOR_MIN_SCORE`（默认 0.4，环境变量可覆盖）过滤；最高分仍低于阈值时整条向量通道弃用，返回 `mode=lexical` 并在 `semanticReason` 写明最高分与阈值。该阈值来自本机 `bge-m3` 最初 13 条查询的实测分界（两条域外负例最高 0.385、正例最低 0.436）。后续加入的近域/混合负例最高 0.508，与正例区间重叠，0.4 不能区分；它只是噪声下限，不是“无答案分类器”。换模型或换语料需重测。
- 覆盖度：返回 ready/indexing/pending/failed/not_configured/stale、可检索块数与当前向量模型。没有向量索引或服务商、查询嵌入失败、模型与索引不一致、最高相似度低于阈值时，`mode=lexical` 并给出原因，绝不标成 hybrid；索引模型与当前模型不一致时提示重建。
- 成本：每次嵌入 HTTP 尝试写一行 `model_calls`（`embedding` 或 `embedding_query`），记录 provider、模型、token、成本、延迟与状态，不写正文；价表/用量缺失时成本为未知。
- 审计完整性：`0007_audit_metadata_object.sql` 将历史字符串 metadata 规范化为对象（无法解析的包成 `legacyValue`），并加 `CHECK (jsonb_typeof(metadata) = 'object')`；插入字符串 metadata 会被数据库拒绝，避免再次出现双重编码。
- AI 上下文：检索查询只用本章计划（实体/目标/阻碍关键词）+ 作者补充要求，不把草稿发给嵌入服务，并排除当前章；取前 6 块、总 2400 字、单块 500 字、每章最多 2 块，写入 `canon_retrieval` 段与 `[R1]` 引用。检索失败/降级不阻断生成，提案上下文与历史记录显示检索状态、原因、引用与覆盖度；`contextHashOf` 不变，检索是非确定性的展示上下文，不进入门禁证据。
- 测试：`packages/retrieval` 覆盖切块/词法/RRF/摘要；`apps/worker/src/pipeline.test.ts` 覆盖索引管线与幂等；`apps/api/src/m4-retrieval.test.ts` 覆盖检索、诊断词法、相似度下限整通道降级与低分邻居过滤、隔离、降级、权限、去重重建、审计约束与 AI 引用。
- 检索评估：`scripts/retrieval-eval-queries.json` 是 11 条关键词正例 + 8 条无答案对照（2 条域外 + 6 条近域/混合）的自拟查询集；`scripts/retrieval-eval.mjs` 输出词法/自动模式的 hit@1、hit@3、hit@8、MRR、无答案对照返回章节数与原始结果。2026-10-21 实测（阈值 0.4）：词法 hit@1=100%、MRR=1.000，对照 1/8（仅“林默 咖啡”命中人物片段）；自动模式 hit@1=81.8%、MRR=0.909，对照 6/8。0.4 只让两条域外对照降级，6 条近域/混合对照仍返回章节；纯语义改写“年轻人用鲜血守住街口”最高分 0.473，反而低于近域负例“雨夜 咖啡馆”的 0.508，说明单一相似度阈值无法分离相关与不相关。阈值未按新增硬负例重调；该结果只用于回归对比，**不能据此调参或代表真实检索质量**。

## 无人值守自动作业（M4-B）

范围是“显式授权 + 逐章无人值守 + 全门禁入库”，只支持 `continue`（续写）模式。不做备份自动化、dry-run、扩展写（扩写/改写既有章）或多 runner 调度；预算采用调用级 `max_tokens` 上限与章节检查点累计，仍不是供应商账单级硬保证。

- 权限：仅所有者/主笔可创建授权、创建/暂停/恢复/停止作业与撤销授权；作者、审阅者、读者、计费管理员与 AI 均被拒绝（403）。AI 没有豁免申请/批准入口，runner 也不存在绕过门禁的分支。
- AI 服务主体：每个工作区一个 `kind='ai'` 用户（`ai+<workspaceId>@service.yunshuo.local`，名称“AI 写作引擎”），没有成员关系，不能开发登录；runner 以它取得章节租约、生成、保存草稿、跑门禁、暂存与提交，审计 actor 类型为 `ai`。
- 授权：绑定作品、起止章号、单次最多章节数（1–50）、每章目标字数（300–4000）、续写指令、有效期（1–720 小时）、可选预算与币种、是否允许自动入库、是否允许远程模型、是否显式接受非生产门禁规则集。授权可撤销；过期后不能创建或恢复作业。
- 预检：`POST /api/automation/preflight` 只读数据库，不发起任何模型调用；13 项检查为 `mandate / chapter_scope / chapter_status / conflicting_job / gate_feasibility / providers / remote_policy / budget / human_lease / auto_commit / waiver_policy / backup / connectivity`。失败项阻止启动；提醒项（无预算、备份未接入、连通性未验证等）如实展示。当前唯一规则集 `dev-v0` 非生产：开启自动入库时，`gate_feasibility` 在授权未显式接受非生产门禁时失败；仅暂存时只提醒。
- 远程策略：未勾选“允许远程模型”时，预检在出现非本机端点服务商时失败；runner 生成前还会按同一策略过滤候选，不会把上下文发到未授权端点。
- 作业：`queued / precheck_failed / running / paused / stopped / completed / failed / interrupted`；章节：`pending / running / committed / staged / gate_failed / no_output / failed / skipped / interrupted`。同一工作区同一时间只允许一个排队、运行或暂停中的作业；一次只处理一个章节。
- 执行：runner 默认随 API 进程启动，每 2 秒轮询；以 `runner_id` + 20 秒心跳标记存活，心跳超过 5 分钟视为中断，只能人工恢复。每章依次取 AI 租约 → 生成 → 保存草稿 → 五门禁 → 暂存 → 全部通过才提交正典，来源 `batch`；任一门禁失败保留草稿与评估但不入库。提交幂等键 `job:<jobId>:<chapterId>:commit`，重试不会产生重复版本。
- 人工优先：章节有其他人持有的有效租约时 runner 跳过（`external_state`）；暂停、停止在章节边界生效；撤销授权会停止该授权下排队/暂停的作业。
- 预算：每次模型调用按剩余授权预算、服务商输入/输出价表与保守输入预留（2 token/字）计算 `max_tokens`；额度不足以覆盖最低 128 个输出 token 时在调用前中止，章节保持待办并暂停作业。失败尝试的已计费用会从后续可用额度扣除；上游未返回用量、价表缺失或币种不一致时停止后续尝试。章节检查点仍累计已花费金额，达到上限或存在未知费用时暂停。费用是按价表与 token 用量的估算，不是供应商账单；输入 token 预留与供应商 tokenizer 可能有偏差，**不构成账单级保证**。
- 门禁复核：runner 在领取作业后再次检查规则集；若自动入库使用非生产规则集且授权未确认，会直接终止作业，避免预检后修改授权绕过。
- 测试：`apps/api/src/m4b-automation.test.ts` 15 个用例；M4-B 阶段全量 91 项通过（M5-A 两轮复审后为 108 项），类型检查通过。浏览器验收使用独立测试库并关闭 runner，覆盖授权、预检、排队、暂停、恢复、停止、撤销与作者无入口，全程未调用模型。
- 迁移：`0008_m4b_automation.sql`（授权、作业、作业章节、预算/心跳/暂停停止标记）；`0009_automation_guards.sql`（非生产门禁确认）。

**备份**：自动备份仍未接入。启动无人值守前执行 `bash scripts/backup-db.sh`，脚本通过 `docker exec yunshuo-db pg_dump -Fc` 生成 `backups/yunshuo-<时间>.dump`，并用 `pg_restore --list` 校验可读；可用 `YUNSHUO_DB_CONTAINER / YUNSHUO_DB_USER / YUNSHUO_DB_NAME / YUNSHUO_BACKUP_DIR` 覆盖默认值。恢复前先停止 API 与 worker，再按脚本输出的 `pg_restore --clean --if-exists` 命令执行。`backups/` 已加入 `.gitignore`。

尚未实现：自动备份/快照、dry-run、扩展写、定时/多作业调度、多 runner 高可用、AI 提案与最终正文差异审批。预算硬上限依赖服务商遵守 `max_tokens`，输入成本按估算预留，不能替代供应商账单；也没有在流式输出中途按实际 token 扣费的强制中断。API 重启会中断正在执行的章节；`precheck_failed` 状态保留在 schema 中，但当前创建作业时预检失败会直接返回 409 而不落作业。开发登录仍只限本机，不能部署为公网服务。

## 本地账号、邀请与工作区（M5-A）

范围是本地密码账号、邀请注册/加入、成员角色管理与工作区切换。M5-A 本身不含密码重置/修改、邀请邮件投递、计费归属与 Studio 部署，也不以占位界面冒充已接入；其中密码修改/重置与邀请邮件已由 M5-B 阶段一补齐，计费归属由阶段二补齐，OIDC/SSO 由阶段三补齐，供应商账单对账由阶段四补齐。

- 密码：scrypt（N=16384 / r=8 / p=1，64 字节派生，16 字节随机盐），存 `scrypt$N$r$p$salt$hash`，不存明文；未知邮箱也执行一次等价开销的 dummy 校验，失败统一返回 `LOGIN_FAILED`，不泄露账号是否存在。密码至少 10 位。
- 限流：同一“邮箱+IP”10 分钟内失败 8 次后返回 429 `LOGIN_RATE_LIMITED`；计数在进程内存中，重启清空、多实例不共享；键表设有上限，超出时淘汰最旧键，避免任意邮箱把内存撑大。成功登录清空该键。
- 会话：签名 httpOnly Cookie `yunshuo_session`，SameSite=Lax，7 天；会话绑定 `workspace_id`，每次请求按该工作区重新加载成员关系，因此改角色立即生效；移除成员会删除该工作区的会话。生产使用 Secure Cookie，且必须设置 `SESSION_SECRET`。
- 开发登录：`DEV_AUTH=1` 时才提供 `GET /api/dev/users` 与无密码登录；关闭后该接口 404，登录页只保留邮箱密码。`NODE_ENV=production` 下无论 `DEV_AUTH` 如何设置都强制关闭。开发身份仅限本机，不能作为公网部署方式。
- 邀请：仅所有者/主笔可见入口与调用成员接口；所有者可邀请任意人类角色，主笔只能邀请作者/审阅者/读者/计费管理员。令牌为 32 字节随机数（base64url），服务端只存 SHA-256 哈希，链接只在创建时显示一次；默认 72 小时，可选 24/72/168 小时；一次性、可撤销，同工作区同邮箱同时只能有一个待接受邀请。并发创建由部分唯一索引兜底并返回 409 `INVITE_PENDING`，不会落成 500。M5-B 起创建邀请会尝试投递邮件，状态如实返回 `sent/captured/failed/not_configured`；同时仍返回一次性接受链接，可由邀请人通过可信渠道转交。
- 接受：未登录且平台无该账号时填写称呼与密码创建账号；已有账号时直接填写该账号密码，服务端在邀请事务内校验通过后把会话绑定到邀请工作区，不再要求先登录——因此被移出全部工作区的账号也能通过新邀请回归。仍有其他工作区的账号也可先登录再接受，登录邮箱必须与邀请邮箱一致，否则要求退出。错误密码统一返回 401 `LOGIN_FAILED`，并计入“邀请令牌+IP”的 8 次/10 分钟限流；已登录接受不受影响。密码哈希在邀请状态与账号存在性校验通过后才计算，无效令牌不会触发 scrypt。预览时已使用/已撤销/已过期返回 410；接受时已使用/已撤销返回 409、已过期返回 410；已是成员返回 409，AI 主体不可邀请；并发注册同一新邮箱由邮箱唯一索引兜底并返回 409 `ACCOUNT_EXISTS`。
- 成员：所有者可改角色与移除成员；最后一名所有者不能降级或移除；改角色/移除先锁工作区行再锁目标成员关系，避免两名所有者并发降级或移除时把所有者清零。AI 服务主体（`kind='ai'`）不能被邀请、改角色或移除。成员操作写 `audit_log`（`member.invite.create/accept/revoke`、`member.role.update`、`member.remove`），不含令牌明文。
- 工作区切换：页头在有多个成员关系时显示选择器；切换只更新当前会话的 `workspace_id`，不新建会话。当前工作区无权限时界面入口随角色消失，API 仍返回 403。
- 迁移：`0010_m5_identity.sql`（`users.password_hash/password_updated_at`、邮箱大小写唯一索引、`sessions.workspace_id/auth_method`、`workspace_invites` 与待接受唯一索引）。
- 验收（2026-10-21，独立测试库）：密码登录/错误密码、邀请注册与复用 410、角色修改（author→reviewer）及审计、最后一名所有者保护、主笔视角无改角色/移除入口且邀请角色受限、主笔发邀请/撤销、API 直连改角色/移除/邀请 owner 均 403、第二工作区切换后角色与章节目录随之变化；并发回归覆盖两名所有者互相降级、同邮箱重复邀请与同新邮箱并发注册。第二轮复审另在独立 3101/5176 端口验证“被移出全部工作区的账号用密码直接接受新邀请”：错误密码显示提示，正确密码加入并把会话绑定到邀请工作区。验证用户/邀请/会话/审计与临时工作区已清理。
- 回顾审计：[docs/云说-M5-A回顾审计报告-2026-10-21.md](docs/云说-M5-A回顾审计报告-2026-10-21.md)，含两轮并发缺陷复现、测试库误连开发库的更正、孤儿账号接受修复、浏览器验收证据与未修复风险。

## 邮件、密码修改与重置（M5-B 阶段一）

范围是本阶段可本地完整验收的部分：邮件投递三模式、邀请邮件、密码修改与一次性重置、账号级安全事件。本阶段不含计费归属（已由阶段二补齐）与 OIDC/SSO（已由阶段三补齐）。

- 邮件模式：`smtp` 真实发送（需 `MAIL_HOST`、`MAIL_FROM`）；`memory` 开发内存邮箱，仅进程内可读、不真实投递，非生产默认；`off` 不发送，生产默认。生产设置 `memory` 会启动失败；`smtp` 缺配置时状态为 `not_configured`，不伪造成功。
- 投递状态：`sent / captured / failed / not_configured`。`mail_messages` 只存收件人、模板、provider、状态、错误码/消息与时间，不存正文、邀请令牌或重置令牌；内存邮箱最多保留 50 封。
- 开发邮箱：`GET /api/dev/mailbox` 仅在 `DEV_AUTH=1` 且 `MAIL_MODE=memory` 时可用，API 绑定 127.0.0.1；登录页可按需读取并打开邀请/重置链接。
- 邀请邮件：包含邮箱、角色、邀请人、工作区、有效期与一次性接受链接。邮件失败不回滚邀请，界面如实显示状态并保留可复制链接。
- 修改密码：`POST /api/auth/password/change`，需登录与当前密码，新密码至少 10 位；成功后撤销该账号其他会话、作废未使用重置令牌，当前会话保留。无密码账号返回 `PASSWORD_NOT_SET`；按用户+IP 限流。
- 忘记密码：`POST /api/auth/password/reset-request` 无论邮箱是否存在都返回同一提示，不泄露账号存在性；32 字节随机令牌只存 SHA-256，30 分钟、一次性，重新申请作废旧令牌；按邮箱 5 次/15 分钟与 IP 30 次/15 分钟限流。
- 重置：`POST /api/auth/password/reset` 在事务内锁定令牌、更新密码、标记该用户全部令牌已用并删除全部会话；过期令牌标记已用并返回 `RESET_TOKEN_INVALID`；按 IP 20 次/15 分钟限流。
- 事件与审计：`auth_events` 记录账号级请求/成功/失败，含 IP、UA、邮件状态与撤销会话数，区别于工作区 `audit_log`；不记录密码、密码哈希或令牌。
- 前端：登录页“忘记密码”、`/reset/<token>` 重置页、页头“账号”修改密码、团队面板显示邀请邮件状态；开发内存邮箱只在开发登录页显示。
- 迁移：`0011_m5b_account_security.sql`（`auth_events`、`password_reset_tokens`、`mail_messages`）。
- 测试：`apps/api/src/m5b-account-security.test.ts` 11 个用例；当时全量 119 项通过。浏览器验收（2026-10-21，独立测试库、`MAIL_MODE=memory`、`DEV_AUTH=1`、关闭 runner）：无密码账号申请重置 → 开发邮箱读取重置邮件 → 设置新密码 → 新密码登录 → 账号内修改密码 → 旧密码被拒、新密码可用 → 邀请成员并显示“已写入开发内存邮箱，未真实投递”。临时用户/工作区/会话/邀请/邮件/安全事件与临时进程已清理。
- 诚实边界：内存模式明确不真实投递；SMTP 真实发信路径尚未对真实邮件服务器验收；数据库只保留投递元数据，邮件正文与令牌不落库。

## 费用归属、工作区预算与计费管理员（M5-B 阶段二）

范围是本地可验收的月度计费闭环：工作区生成预算、费用归属报表、价表维护与计费角色边界；供应商账单对账与发票导入已由阶段四补齐，自动分账仍未实现（OIDC/SSO 由阶段三补齐）。

- 迁移 `0012_m5b_billing.sql`：`workspace_budgets` 每个工作区一条，保存月度上限与币种（CNY/USD）；`model_calls` 增加 `job_id`、`reserved_cost`、`reserved_currency`、预留成对约束与索引。统计窗口是服务器本地自然月。
- 预算是生成闸门：手工提案与自动作业共用 `reserveGenerationCall`，在 `workspace_budgets` 行锁内按“已计生成费用 + 进行中预留”计算可用额度，再按价表与保守输入预留推导本次 `max_tokens` 和预留上限。额度不足、价表不完整或币种不一致时在调用前拒绝，并写入 `blocked` 调用记录。
- 范围只拦 `chapter_proposal`：`embedding` / `embedding_query` 照常运行，费用单独计入报表；这正是“预算耗尽时生成停止、索引与检索继续”的口径。
- 自动作业：预检新增 `workspace_budget` 项；runner 在章节检查点再次检查工作区预算，达到上限时暂停并记录原因。授权预算仍然独立生效，两者取更严格者。
- 预留清算：成功按上游 token 用量写实际估算费用并清空预留；失败/中止清空预留并保留失败记录；超过 15 分钟仍未完成的 `streaming` 调用会在下一次预算计算或报表读取时标记 `CALL_STALE` 并释放预留，实际费用保持未知。
- 币种边界：存在其他币种的在途预留时，预算币种切换返回 409 `BUDGET_CALLS_IN_PROGRESS`，需等调用结束或中断后再改；阻断调用不参与“其他币种调用”统计。
- 报表：`GET /api/billing/report` 按用途、成员、作业、章节拆分，按币种分组；未知费用单独列出且不估算；阻断调用不计入费用合计；同时返回预算状态、已计、预留、剩余和价表完整度。报表中的金额全是估算值，不是供应商账单。
- 权限：所有者、主笔、计费管理员可读报表；所有者与计费管理员可改预算和价表；作者、审阅者、读者与 AI 无权。计费管理员不能读取章节、草稿、检索、AI 提案、服务商配置或自动化授权；价表接口只返回名称、型号、用途与价格，不返回端点或密钥。端点与密钥仍由所有者管理。
- 审计：`billing.budget.update` 与 `billing.provider_price.update` 记录前后值、币种与对象，不记录密钥；价表变更不会冒充连接测试结果。
- 前端：所有者/主笔页头“计费”弹窗；计费管理员登录后进入独立计费台；作者无入口。报表每 20 秒刷新，预算与价表保存后就地反馈。
- 测试：`apps/api/src/m5b-billing.test.ts` 8 个用例；当前全量 151 项通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 104 + worker 10）。
- 浏览器验收（2026-10-21）：临时计费账号进入独立计费台，确认无正文/服务商入口；所有者弹窗完成预算保存、价表保存、清除预算与价表还原；主笔只读；作者无入口。临时账号、会话与验收审计已清理，演示预算恢复未设置、价表恢复原值。
- 诚实边界：输入 token 为保守估算，输出依赖服务商遵守 `max_tokens`，无法在流式途中按实际用量硬中断；并发预留能防止同一进程/数据库内的预算穿透，但不是供应商账单级保证；未知费用可能让实际支出超过预算上限；币种不一致时拒绝生成而不是换算。

## OIDC/SSO 登录（M5-B 阶段三）

范围是单部署接一个 OIDC IdP 的登录与账号绑定，不保存 IdP 令牌、授权码或客户端密钥，也不冒充企业级 MFA/SCIM。

- 配置：`OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_REDIRECT_URI` 必填；`OIDC_CLIENT_SECRET` 可选（公共客户端走 PKCE，无密钥）；`OIDC_SCOPES` 必须包含 `openid`；`OIDC_PROVIDER_NAME` 只影响登录按钮文案；`OIDC_AUTO_PROVISION` 默认关闭。生产要求 issuer 与 redirect URI 为 HTTPS，客户端密钥只从环境变量读取。
- 流程：`GET /api/auth/oidc/start` 生成一次性 `state`、`nonce` 与 PKCE S256 `code_verifier`，写入 10 分钟有效的签名 httpOnly 状态 Cookie 后跳转 IdP；回调先校验状态 Cookie 与 state，再用授权码换令牌，验证 ID Token 的 issuer、audience、有效期、nonce 与签名算法（只接受非对称算法，拒绝 HS*）。失败只带 `?oidc_error=<CODE>` 回到登录页并记录代码，不把上游令牌错误或响应体暴露给浏览器。
- 绑定：以 `(provider, subject)` 为稳定身份。已有绑定优先于邮箱，IdP 改邮箱不会串号；首次登录要求 `email_verified=true`，按小写邮箱关联既有账号。无既有账号时，只有开启自动开户且存在待接受邀请才创建用户并接受邀请；否则返回 `OIDC_ACCOUNT_NOT_FOUND` / `OIDC_INVITE_REQUIRED`。同一邮箱的并发开户用事务级 advisory lock 串行化。
- 会话：登录成功沿用现有签名会话 Cookie，`auth_method='oidc'`，仍绑定工作区、按请求重载成员关系。退出仍是本地注销当前会话，不调用 IdP 的 end-session 端点。
- 数据：迁移 `0013_oidc_identity.sql` 新增 `user_identities`；数据库不存 ID Token、access token、授权码或客户端密钥，身份表只保留提供方、subject、邮箱、验证状态与登录时间。
- 前端：登录页公开读取 `GET /api/auth/config`（仅 SSO 开关、提供方名称、是否自动开户），显示 SSO 按钮；OIDC 错误按码映射为可读提示，未知错误不编造原因。
- 测试：`apps/api/src/m5b-oidc.test.ts` 9 个用例，使用本地模拟 IdP 走完整授权码 + PKCE 流程，覆盖公开配置不泄露密钥、既有邮箱登录、subject 稳定绑定、邀请自动开户、无邀请拒绝、未验证邮箱拒绝、state/Cookie 篡改拒绝、错误 audience/nonce 拒绝与授权码重放不出第二份会话。当前全量 151 项通过。
- 诚实边界：本地注销不等于 IdP 单点登出；不实现 MFA 策略、SCIM 供给、多 IdP 并存或组织级域名发现；`email_verified` 的可信度取决于 IdP；SSO 按钮的浏览器验收尚未对真实 IdP 执行，模拟 IdP 只验证协议与绑定逻辑。

## 供应商账单对账与发票导入（M5-B 阶段四）

范围是“导入供应商账单 CSV → 与本地估算逐模型对照 → 人工标记复核/争议”的对账闭环；不做自动分账、发票 OCR、税务合规或付款。

- 迁移 `0014_provider_bills.sql`：`provider_bills`（服务商、发票号、账期、币种、申报总额、状态 imported/reviewed/disputed、复核人/时间、导入人）与 `provider_bill_lines`（模型、输入/输出 token、金额、备注）；同一工作区+服务商+发票号唯一，账期结束不早于开始。金额最多 6 位小数，token 为非负整数。
- 导入：`POST /api/billing/bills/import` 由所有者/计费管理员提交服务商、发票号、账期、币种、可选申报总额与 CSV（≤1MB、≤5000 行）。服务端解析带引号字段、BOM 与 CRLF，校验表头、列数、金额/token 格式，整批事务写入并写 `billing.bill.import` 审计；重复发票返回 409 `BILL_ALREADY_IMPORTED`，不部分落库。
- 对账：`GET /api/billing/bills/:id/reconciliation` 在同一服务商、账期 `[开始, 结束+1 天)` 内按模型聚合本地 `model_calls`，与账单逐模型对照，返回 match / amount_mismatch / bill_only / local_only / local_unknown / currency_mismatch，以及账单明细合计、申报总额差、本地估算、差异模型数、未知费用/其他币种/预算阻断计数。
- 权限：所有者、主笔、计费管理员可查看；仅所有者与计费管理员可导入与复核；作者/审阅者/读者/AI 无权。跨工作区账单返回 404，跨工作区服务商导入拒绝；计费接口仍不返回端点或密钥。
- 复核：`PATCH /api/billing/bills/:id` 只能标记 reviewed / disputed，争议必须填写说明；审计 `billing.bill.review` 记录前后状态与说明，不混入账单金额。
- 前端：计费弹窗新增“发票导入与估算对账”。导入后自动选中账单，展示汇总、逐模型差异、未知/其他币种/阻断提示与复核表单；账单金额来自人工导入，本地金额仍是估算值。
- 测试：`apps/api/src/m5b-billing-reconciliation.test.ts` 7 个用例，覆盖角色边界、导入元数据与审计、重复发票、逐模型对照、CSV/日期校验、复核状态与工作区隔离。当前全量 151 项通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 104 + worker 10）。
- 浏览器验收（2026-10-22，开发库）：以所有者导入 Atria 账单（2 行），界面显示明细合计 ¥15.00、申报总额 ¥15.20、与明细差 +¥0.20、本地费用未知 5 次、2 个差异模型；保存“已复核”与说明后状态、复核人与时间正确回显。验收账单、明细与审计已清理。
- 诚实边界：账单金额由人工导入，系统不验证发票真伪、税额或付款状态；本地金额是价表与 token 用量估算，未知费用不猜造；差异不会改写调用记录、价表或预算；账期按服务器本地日期解释；不提供自动分账、账单提醒或发票文件归档。

范围是单机 Docker Compose 试点，不是高可用生产平台；完整步骤、排障与诚实边界见 [docs/云说-Studio部署说明.md](docs/云说-Studio部署说明.md)，本轮交付复审记录见 [docs/云说-Studio交付回顾审计报告-2026-10-22.md](docs/云说-Studio交付回顾审计报告-2026-10-22.md)。

- 交付：`deploy/api.Dockerfile`（API/worker/migrate/bootstrap 共用）、`deploy/web.Dockerfile`、`deploy/nginx.conf`（SPA 回退、SSE 关缓冲、20MB 请求体）、`docker-compose.studio.yml`、`.env.studio.example`、`apps/api/src/bootstrap.ts`。
- 启动：`cp .env.studio.example .env.studio` 并填写数据库密码、会话密钥、模型密钥加密主密钥与首个所有者；`docker compose --env-file .env.studio -f docker-compose.studio.yml up -d --build`。只有 web 发布 `${STUDIO_HTTP_PORT:-8088}:80`，api 与 db 不对宿主机开放。API 等待 migrate 与 bootstrap 都成功后才启动；worker 显式注入与 API 相同的 `MODEL_KEY_SECRET`。

- 导入编码与大小：前端只接受 UTF-8 文件（非 UTF-8 会提示转码，不再静默替换为乱码），单文件上限 18MB，提交前另按 JSON 请求体检查 20MB 上限；服务端与 nginx 的上限均为 20MB。标题解析只识别阿拉伯数字章节号（`第一章` 不会被识别）。
- 备份恢复：沿用 `scripts/backup-db.sh`（`YUNSHUO_DB_CONTAINER=yunshuo-studio-db`）；恢复前停止 api/worker/web。备份含加密后的服务商密钥密文，恢复必须使用同一 `STUDIO_MODEL_KEY_SECRET`。
- 验收（2026-10-22，Docker Desktop）：镜像构建、迁移、bootstrap、健康、登录、空工作区导入两章、未评估/未配置索引展示、重复章节 409、备份与临时库恢复均实际通过；复审修复后重新构建全栈，API 等待 bootstrap 后 healthy、worker 带密钥启动、移除 bootstrap 密码二次执行仍退出 0；`pnpm typecheck` 与 151 项测试通过。验收后已 `down -v` 并删除临时 `.env.studio` 与备份，开发库未受影响。
- 边界：无内置 TLS/WAF、多副本、零停机、自动备份或数据库 RLS；API/worker 镜像使用 `tsx` 与开发依赖；worker 无 HTTP 健康端点；Linux 主机、真实 SMTP、真实 IdP 与外部反向代理未实测；导入前端无自动化测试，未做 1000 章/20MB 压力测试，自动索引只提示费用、未增加二次确认。

## 设定库与连续性账本（M6-0 / M6-1 / M6-2 / M6-3）

- 数据：`ledger_entries` 保存工作区/作品归属、种类、状态、当前/草稿版本指针；`ledger_entry_versions` 只追加不可变快照。M6-1 界面开放 `setting`（世界观、地点、组织、规则、物品与能力），M6-2 开放 `character`，M6-3 开放 `foreshadowing`；三类条目共用草稿/发布/归档、版本历史、差异与回滚基础。
- 权限：读取口径与正典一致（所有者、主笔、作者、审阅者、读者）；计费角色不可读；写入仅所有者、主笔、作者；AI 主体不能写。审阅者/读者在界面显示“只读”，不出现新建、编辑、发布、归档或回滚按钮。
- 版本流：草稿 → 发布 → 归档；发布把草稿快照设为当前版本并递增工作区 `settings_version`（设定）或 `ledger_version`（角色/伏笔），使门禁上下文哈希失效；已发布版本不可修改。回滚把旧快照复制成新草稿，仍需人工再次发布，不直接改当前版本。归档保留全部历史、默认列表隐藏、名称可复用，当前不提供取消归档。
- 并发与冲突：保存草稿必须携带 `expectedDraftVersionId`，不匹配返回 409 `LEDGER_DRAFT_CONFLICT`；名称与别名在工作区内按种类去重（未归档条目）。存在待发布草稿时归档必须先发布或显式丢弃草稿。
- 审计：创建、保存草稿、发布、归档、回滚分别写入 `audit_log` 与 `events`，记录变更字段、版本号与原因；不记录正文副本之外的敏感信息。
- 界面：页头“设定库”打开工作区级账本，支持名称/别名/摘要搜索、状态与作品筛选、创建、编辑草稿、发布、归档、回滚、版本历史与字段级差异；设定、角色与伏笔分页，角色详情展示角色卡、状态时间线、当前正典出场与警告，伏笔分页显示只读报告与回收状态筛选；空状态不显示示例数据。
- 校验：来源章节必须属于当前工作区且属于同作品；作品归属不能跨工作区；角色档案要求作品与章节关联；伏笔必须绑定埋设章节，计划回收窗口为正整数且不早于埋设章，回收章节必须属于同作品、不早于埋设章并落在计划窗口内，已回收/已放弃必须填写至少 4 个字的说明。导入章节可作为来源，但不会因此补造门禁结论。角色状态同一章节只能登记一条；状态章节必须属于角色所属作品。
- 角色档案：静态字段包括身份、外貌、性格、目标、阵营、能力、语言风格与人物关系；状态时间线逐条绑定“截至第 N 章”，记录存活/死亡/未知、地点、已知信息、持有物与关系变化。已发布状态不会被草稿修改；草稿改名与未来状态不会提前出现在时间线。
- 出场扫描与警告：只扫描当前正典正文，按名称与别名统计每章命中次数并给出首次/最近出场。警告包括死亡后复活、死亡后仍在后续正典出场、同一对象存在多种关系描述；全部为非阻断提示，不改变发布结果。死亡后的 `unknown` 状态不视为复活；多个死亡区间分别检查后续出场。
- 写作台上下文：只读取已发布角色，按上一章及之前的最新状态展示，并标记状态停留在更早章节的“过期”；开篇章节不展示任何角色状态，未登记状态的角色以计数隐藏。为避免剧透，写作台不展示身份、别名、摘要或未来状态。该卡片只接写作台，不进入 AI 上下文、检索或门禁。
- 伏笔台账：字段包括名称/别名、摘要、埋设章节、计划回收窗口、重要度、说明与来源章节；状态只向前流转 `已埋设 → 已强化 → 已回收/已放弃`，已回收/已放弃不能重新打开，只能通过账本回滚恢复历史快照。回收必须绑定同作品章节并落在计划窗口内；放弃必须填写原因。服务端按当前生效版本再次校验流转，客户端禁用选项只用于提前提示。
- 逾期与提醒：伏笔报告只读取生效版本，按未回收/逾期/已回收/已放弃计数；逾期只在有结束章且当前正典最大章号超过结束章时判定，只是提示，不改变状态、不判定失败。写作台章节计划卡只展示同一作品、已生效、未回收、埋设章不晚于本章、带计划窗口且已进入窗口或逾期的伏笔，逾期优先；它不会自动回收伏笔，也不会改写章节或门禁结论。草稿的逾期标记会明确标注“草稿”，避免冒充生效版本。
- 验收（2026-10-22）：创建伏笔草稿 → 发布 v1 → 强化 v2 → 回收 v3（绑定第 3 章、填写回收说明）→ 报告从未回收 1/逾期 0 变为已回收 1，逾期筛选为空；编辑终态条目时状态下拉只剩“已回收”；新建一条第 3 章埋设、窗口 4–4 的临时伏笔后，第 3 章提醒为 0 条，第 4 章显示 1 条“进入回收窗口”。验收条目、版本与审计已删除，开发库账本恢复为空。
- 未接入与限制：设定库、角色档案与伏笔台账尚未进入检索索引、AI 上下文或门禁提示/校验，也不会自动关联导入章节；这些属于 M6-4。地点跳变未做自动检测（需要人工判断是否属于合理转场）；警告不记录人工确认结论、也不阻断发布；时间线每次请求扫描整部作品当前正典，性能未压测。AI 对三类账本只有读权限，**没有“建议状态变更/伏笔回收”的生成与人工确认流程**，只验证了 AI 写入被拒绝。逾期与提醒目前只在账本和写作台只读展示，未接入自动作业、通知或检索。
- 迁移与测试：`0015_m6_ledger.sql`；`apps/api/src/m6-ledger.test.ts` 7 个用例覆盖权限、隔离、发布/版本、回滚、并发冲突、归档与角色/伏笔校验；`apps/api/src/m6-character.test.ts` 6 个用例覆盖时间线、当前正典出场、三类警告、草稿隔离、截至上一章上下文、开篇隐藏、权限与跨作品拒绝；`apps/api/src/m6-foreshadowing.test.ts` 6 个用例覆盖报告口径、提醒过滤与排序、空作品正典章号、流转与回收校验、终态不可重开、权限与工作区隔离。

## 诚实边界

- 开发种子只有演示两章，不代表《规则档案馆》真实正文或真实门禁；Studio 全新工作区默认无章节，需通过“旧章导入”或修订流程进入主流程。`pnpm db:reset` 只生成两章种子；本机验收可能留下主题外的新增或修订章节，可用 `pnpm db:reset` 恢复。
- `dev-v0` 是演示规则，阈值仅用于验证链路，不是生产标准。无人值守自动入库默认拒绝非生产规则集；只有所有者/主笔在授权中显式接受后才允许，runner 会再次复核。该确认不把 `dev-v0` 变成生产规则。
- 未接入的审计与索引会显示“未接入 / 未配置”，不会伪装成就绪。没有嵌入服务或最高向量相似度低于阈值时检索只跑词法并说明原因；旧版本片段永远不会被检索返回。相似度下限只过滤极低相似度噪声，**不能判断一个问题在正典里有没有答案**；近域/混合负例仍可能返回无关章节。
- AI 只生成提案，不直接写草稿或正典；生成失败、停止、超时都会留下失败记录，不补造成功结论。已输出正文后的失败不会重试或切换，避免把两段不同来源的正文拼成一份提案。
- 成本是按已配置价表与服务商返回 token 用量计算的估算值，不是供应商账单；价表缺失或未返回用量时显示未知，不填猜测数字。M5-B 阶段二增加工作区月度生成预算：手工与自动生成共用行锁预留，自动作业在章节检查点复核；嵌入与检索不阻断、单独计费。输入成本按保守估算预留，输出依赖服务商遵守 `max_tokens`，流式途中不能按实际 token 硬中断，**不是账单级硬保证**。M5-B 阶段四增加供应商账单导入与估算对账，但账单金额与本地估算仍分开呈现，差异不会自动改账。
- 尚未接入：设定库、角色档案与伏笔台账的检索、AI 上下文与门禁关联（M6-4）；三类账本均已可维护，但均未进入检索、AI 上下文或门禁，地点跳变与人工确认留痕也未实现，伏笔逾期与提醒不会自动改变状态或自动回收。发票 OCR/税票归档与自动分账同样未实现。邮件已接入三模式，但 SMTP 真实发信路径尚未对真实邮件服务器验收；非生产默认内存邮箱不真实投递，生产默认关闭。M4-B 只实现 `continue` 模式的单作业无人值守；自动备份、dry-run、扩展写、定时调度与多 runner 高可用仍未实现，备份需手动执行 `scripts/backup-db.sh`。Atria 当前端点不支持 `/embeddings`（实测 404），嵌入由本机 Ollama `bge-m3` 提供；它不是远程高可用方案，远程部署前必须替换。演示数据没有伪造 ready 索引。
- 回滚豁免目前只覆盖 `rollback` 门禁；字数、AI 腔调、核心实体、章末钩子、因果律不提供豁免入口。AI 不能申请或批准豁免，自动作业也没有豁免路径：任一门禁失败都不入库。
- 尚未实现：跨作者草稿共享与实时协作、自动分账、自动备份与高可用。Studio 单机 Compose 已交付并完成本机验收，但不含内置 TLS/WAF、多副本、零停机或数据库 RLS；正式对外仍需前置 HTTPS 反向代理与运维加固，因此不宣称可直接公网部署。认证已有密码与 OIDC 两条路径，开发身份仍仅限本机。
