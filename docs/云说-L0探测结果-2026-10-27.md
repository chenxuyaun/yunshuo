# 云说-模型侧基座 L0 探测结果（2026-10-27）

> 依据：`docs/云说-模型侧基座分层设计-2026-10-26.md` §七「第一步仍然只做 L0」、§五 的失败与回退表。
> 状态：**本机一轮完成，远端一轮未完成**（缺少服务商凭据）。这不是能力规划，是一次实测记录。

## 一、L0 要回答什么

设计文档 §五 把 L0 的止损条件写得很硬：**服务商不支持 `tools`，则 L2 起全都不开工，损失止于一个探针。**
所以 L0 只问一件事——请求里带 `tools` 时，端点接受还是拒绝（`rejected_field`）；顺带记录同一次探测里能顺手拿到的能力（结构化输出、`tool_choice` 的降级档是否可用）。

## 二、方法

- 端点：Ollama 的 **OpenAI 兼容路径** `/v1/chat/completions`。选它而不是 Ollama 原生 `/api/chat`，因为仓库的 chat 调用走的是 OpenAI 兼容口径（`apps/api/src/services/ai-service.ts` 里的 `fetch(.../chat/completions)`）。
- 环境：本机 Ollama（服务已重启并确认生成路径可用）。
- 判定口径：HTTP 200 且返回体里的 `choices[0].finish_reason` / `message` 形状。
- 所有探测都是 `temperature: 0`、小 `max_tokens`，不写库、不改仓库。

## 三、结果

### 3.1 能力矩阵

| 能力 | `qwen2.5:3b` | `qwen2.5:14b` |
| --- | --- | --- |
| `tools` 字段 | **接受**。返回 `finish_reason:"tool_calls"`，`message.tool_calls[0]` 带完整 `{id, index, type:"function", function:{name, arguments}}` | **无法探测**（见 3.2） |
| `response_format:{type:"json_object"}` | **支持**。返回内容为合法 JSON | 未探测 |
| `tool_choice:"none"`（带 tools 但不许调） | **执行**。不返回 `tool_calls`，`finish_reason:"stop"` | 未探测 |
| 冷启动耗时 | 约 5–8 秒（3B / 1.9GB） | — |

`tools` 实测返回体（节选，已去掉无关字段）：

```json
{"choices":[{"finish_reason":"tool_calls",
  "message":{"role":"assistant","content":"",
    "tool_calls":[{"id":"call_…","index":0,"type":"function",
      "function":{"name":"noop","arguments":"{}"}}]}}]}
```

`tool_choice:"none"` 这一项单独有价值：设计文档 §五 给成本失控留的降级方案就是「禁工具单步档」（`tool_choice='none'` + `max_steps=1`，等价于今天的单发），这条退路在本机模型上**已验证可用**。

### 3.2 环境约束（不在仓库里，但决定下一步能做什么）

1. **本机只能跑 3B 级模型。** `qwen2.5:14b`（8.9GB）请求 300 秒超时、零字节，`/api/ps` 自始至终不加载它。更麻烦的是它挂住时会把后续 3B 请求一起堵死，要等超时或卸载才恢复。
2. **没有远端服务商凭据。** `.env` 里只有 `DATABASE_URL`、`API_PORT`、`SESSION_SECRET`、`WEB_ORIGIN`、`DEV_AUTH`，没有 Atria 或任何 OpenAI 兼容服务商的密钥，所以「Atria 那一轮」无法执行。
3. **Ollama 出现过「元数据接口活着、生成路径全挂」的状态**：`/api/tags`、`/api/ps` 正常响应，但生成请求 240 秒零字节。重启服务后恢复。**再遇到同样症状，先怀疑服务状态，不要先归因于模型太大。**

## 四、对路线的影响

**不触发止损。** 没有探到 `rejected_field`，设计文档 §五 里「L2 起全都不开工」的分支不成立，`L0 → L1a → L2 → L2b → L3 → L5` 可以按序推进。

但要把结论的范围说准：**工具调用能力目前只在本机 3B 模型上被证实，不能外推到生产服务商。** 生产要用的服务商（Atria）能力仍是未知，这一格必须先补探测再开工 L2b——循环一旦跑起来，能力未知的服务商就是成本和行为的双重不确定性。

## 五、尚未交付的两项

设计文档 §七 说 L0 的产出是「按模型的能力元数据 + 界面一行状态 + README 边界」，本轮只完成了边界这一项（`README.md` 的「诚实边界」）：

- **能力元数据落到哪**取决于 D1（`docs/adr/0001-model-capabilities-storage.md`，待拍板：新建 `model_capabilities` 小表 / 服务商表加 JSONB 列 / 只在 `model_calls` 留 `purpose='probe'` 记录），未拍板前不实现存储，避免把结构押在未定的决策上。
- **界面一行状态**依赖同一决定，同样未做。

## 六、复现方式

```bash
curl -sS http://127.0.0.1:11434/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"model":"qwen2.5:3b","messages":[{"role":"user","content":"请调用 noop 工具。"}],
       "tools":[{"type":"function","function":{"name":"noop","description":"noop",
         "parameters":{"type":"object","properties":{}}}}],
       "max_tokens":64,"temperature":0}'
```

判据：看 `choices[0].finish_reason` 是 `tool_calls` 还是报错；报 `rejected_field` 类错误即为 L0 止损。
