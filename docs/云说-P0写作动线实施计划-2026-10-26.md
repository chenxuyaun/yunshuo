# 云说 P0 写作动线实施计划

日期：2026-10-26
范围：① 章节计划可写 + 计划/正文分离不变量；② 作品/卷/章创建与排序
性质：实施计划（本文档不含代码改动；确认后按 W1–W5 顺序落地）

## 一、要解决的洞

当前云说只能"导入旧稿"，不能从零开书：

- 唯一写入 `chapters` 的产品代码是导入服务（`apps/api/src/services/chapter-import-service.ts:117`），没有 `POST /api/chapters`，也没有作品/卷路由（`apps/api/src/routes/chapters.ts` 全部端点清单可核对）。
- `chapters.plan` 是门禁的真实输入（`packages/gates/src/evaluate.ts:95`、`:131`），但没有任何接口能写它；`ChapterStudio` 只读展示（`apps/web/src/components/ChapterStudio.tsx:453`）。
- 列表把所有作品混排且只按章号排序（`apps/api/src/services/chapter-service.ts:83`），多作品时顺序不可控。
- 空工作区只提供"导入旧章"（`apps/web/src/App.tsx:382`）。

本轮把"开书 → 建卷 → 建章 → 写计划 → 写正文"这条动线补齐，不碰 AI、检索、账本、计费。

## 二、边界

做：

1. 章节计划（摘要、节拍、三项门禁关键词）可编辑、可版本化、可回溯。
2. 计划变更与正文分离的不变量：改计划绝不写草稿、暂存、正典、正文版本。
3. 有正典时改计划必须显式选 `plan_only` 或 `mark_body_for_revision`；标记只能由作者显式确认清除。
4. 作品、卷、章的创建、改名、移卷、排序（章号重排）。
5. 前端：计划编辑弹窗 + 历史、待改稿横幅、作品结构弹窗、空态入口。

不做（本轮明确不宣称）：

- 不删除作品/卷/章，不做归档（没有软删除列；硬删会带走正典、版本与审计）。误建只能改名保留。
- 不做自动保存（仍是手动保存 + 未保存警告），不做 IndexedDB 草稿。
- 章号重排**不改写正文里的"第 X 章"字样**，只改 `chapters.number` 与目录顺序。
- 不做段落级 `pid`、不做逐段批注、不做导出（后续项 3–6）。
- 不引入 Moshu 的场景卡、故事时间线、claim/证据层。
- 不改 Studio 容器（8088 仍停在 `0014_provider_bills`）；本轮只在 dev 栈与 dev/test 库验证。

## 三、领域与数据

### 3.1 计划文档与门禁计划分离

`chapters.plan` 是门禁的唯一输入，且被 `contextHashOf` 整体哈希（`apps/api/src/services/chapter-data.ts:70`）。如果摘要/节拍写进这一列，改一句摘要就会让在途暂存草稿失效，也会让既有正典的回滚证据复用（`rollback-service.ts:209`）立刻退化成"必须申请豁免"。因此**不动现有哈希公式**，在域层拆成两个类型：

```ts
// 门禁契约，保持原样（packages/domain/src/types.ts:50）
export interface ChapterPlan {
  requiredEntities?: string[];
  goalKeywords?: string[];
  obstacleKeywords?: string[];
}

// 作者维护的完整计划文档，用于界面、历史与生成上下文
export interface ChapterPlanDocument extends ChapterPlan {
  summary: string;
  beats: string[];
}
```

存储口径：

- `chapters.plan` 仍只放三项门禁关键词 → 哈希公式、`context_hash` 语义、回滚证据复用全部不变。
- 新增 `chapters.plan_summary`、`chapters.plan_beats` 两列存散文部分。
- `chapter_plan_revisions.plan` 存**完整文档**（五个字段），历史与差异只读它。
- `ChapterDetail.plan` 升级为 `ChapterPlanDocument`；`ChapterRow.plan` 仍是门禁子集，另带两列供服务读取。

新增 `packages/domain/src/plan.ts`：

- `emptyChapterPlanDocument()`
- `normalizeChapterPlanDocument(input): ChapterPlanDocument`：trim、丢空、精确去重、缺省补齐；只保留五个键。
- `toGatePlan(doc): ChapterPlan`：只取三项门禁关键词，供写 `chapters.plan`。
- `planDocumentsEqual(a, b)`：`hashJson(normalize(a)) === hashJson(normalize(b))`，空与缺省视为相同。
- `diffChapterPlan(prev, next)`：按字段返回 `{ added: string[], removed: string[], changed: boolean }`，摘要与节拍返回是否变更；供弹窗历史与测试复用。
- `reorderIds(ids, movedId, afterId | null)`：纯函数，返回新顺序或 `null`（非法输入）。

`ChapterPlanDocument extends ChapterPlan` 对 `packages/gates` 是安全扩展：门禁继续只读三项，新增字段被忽略。

### 3.2 迁移 `packages/db/migrations/0021_plan_and_structure.sql`

```sql
ALTER TABLE chapters
  ADD COLUMN plan_revision integer NOT NULL DEFAULT 0,
  ADD COLUMN plan_summary text NOT NULL DEFAULT '',
  ADD COLUMN plan_beats jsonb NOT NULL DEFAULT '[]'::jsonb,
  ADD COLUMN plan_updated_at timestamptz,
  ADD COLUMN body_needs_revision boolean NOT NULL DEFAULT false,
  ADD COLUMN marked_plan_revision integer,
  ADD COLUMN marked_canon_version_id uuid REFERENCES canon_versions(id),
  ADD CONSTRAINT chapters_plan_beats_chk CHECK (jsonb_typeof(plan_beats) = 'array'),
  ADD CONSTRAINT chapters_plan_marker_chk CHECK (
    (body_needs_revision
      AND marked_plan_revision IS NOT NULL
      AND marked_canon_version_id IS NOT NULL)
    OR ((NOT body_needs_revision)
      AND marked_plan_revision IS NULL
      AND marked_canon_version_id IS NULL)
  );

CREATE TABLE chapter_plan_revisions (
  id uuid PRIMARY KEY,
  chapter_id uuid NOT NULL REFERENCES chapters(id) ON DELETE CASCADE,
  revision integer NOT NULL CHECK (revision >= 1),
  plan jsonb NOT NULL CHECK (jsonb_typeof(plan) = 'object'),
  body_policy text CHECK (body_policy IN ('plan_only', 'mark_body_for_revision')),
  canon_version_id uuid REFERENCES canon_versions(id),
  created_by uuid REFERENCES users(id),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (chapter_id, revision),
  CHECK (body_policy IS NULL OR canon_version_id IS NOT NULL)
);

CREATE INDEX chapter_plan_revisions_chapter_idx
  ON chapter_plan_revisions (chapter_id, revision DESC);
```

口径：

- `chapters.plan` 仍是门禁读的唯一值（三项关键词），`plan_summary` / `plan_beats` 只服务界面、历史与生成提示，不参与 `context_hash`。
- `chapter_plan_revisions.plan` 存完整文档；只追加，不更新、不删除。
- 存量章节 `plan_revision = 0`（无历史），首次编辑提交 `basePlanRevision: 0` 并写入 revision 1；列表显示"初始计划（无历史）"。
- `plan_updated_at` 为 NULL 表示从未编辑过计划（存量章节与新建章节）；保存草稿、确认改稿都不改它，界面据它显示"计划最后修改时间"。
- `body_policy` 仅在"编辑时有正典"时写入；`canon_version_id` 记录当时的正典版本，便于事后回答"当时基于哪版正文"。
- 标记三列由 CHECK 强制同生同灭，避免出现"有标记无版本"的脏行。

## 五、服务层

### 5.1 `apps/api/src/services/plan-service.ts`（新）

`updateChapterPlan(auth, chapterId, input)`：

1. `assertCanManageStructure(auth)`：人类主体 + owner/lead/author；AI 主体拒绝。
2. 事务内 `loadChapter(tx, auth.workspace.id, chapterId, true)`（已带 `FOR UPDATE OF c`）。
3. 不存在 → `CHAPTER_NOT_FOUND`；`archived` → `CHAPTER_ARCHIVED`。
4. `input.basePlanRevision !== chapter.plan_revision` → `PLAN_REVISION_CONFLICT`，details 带当前计划与 revision。
5. `normalizeChapterPlanDocument(input.plan)`；与当前文档（`chapters.plan` + 两列散文）归一后相同 → 原样返回，不写行、不推 revision。
6. 有正典（`current_version_id != null`）且没给 `bodyPolicy` → `BODY_POLICY_REQUIRED`。
7. 无正典却给 `mark_body_for_revision` → `BODY_POLICY_NOT_APPLICABLE`；给 `plan_only` 接受，但行内 `body_policy` 存 NULL（无正文可标记）。
8. 插入 `chapter_plan_revisions`（revision = 当前 + 1，`plan` 存完整文档）。
9. 更新 `chapters`：`plan = toGatePlan(doc)`、`plan_summary`、`plan_beats`、`plan_revision`、`updated_at`；若策略是 `mark_body_for_revision`，同时把标记写成**本次** revision 与当前正典版本（重复标记时以最新一次为准；`plan_only` 永不清除既有标记）。
10. 写 `events`（`chapter.plan_updated`）与 `audit_log`（`chapter.plan.update`），payload 含 `{ revision, bodyPolicy, changedFields }`。
11. 返回计划状态视图。

不改：`draft_branches`、`draft_revisions`、`staged_drafts`、`gate_evaluations`、`canon_versions`、`canon_current`、`chapter_metadata`、`index_status`。

生成上下文：`ai-service.ts:139` 的 `planText` 增加摘要与节拍（只改提示词，不参与门禁哈希）。

`resolveBodyRevision(auth, chapterId, input)`：

1. 写权限同上；事务内锁章节。
2. `chapter.status !== 'canon'` → `CHAPTER_NOT_CANON`。
3. `!body_needs_revision` → `PLAN_MARKER_NOT_SET`。
4. `input.planRevision !== marked_plan_revision` 或 `input.addressedCanonVersionId !== current_version_id` → `PLAN_MARKER_CHANGED`，details 带当前标记。
5. 清空三列标记；写事件 `chapter.body_revision_resolved` 与审计，payload 记录标记时的正典版本、本次确认时的正典版本，以及二者是否相同（相同意味着"计划变了但正文未改"，界面必须提示过这一点）。

`listPlanRevisions(auth, chapterId, before?, limit=20)`：读权限；按 revision 倒序；不返回正文。

计划编辑**不要求租约**：租约保护的是草稿并发，计划用 `plan_revision` 乐观锁。写进接口注释与文档。

### 5.2 `apps/api/src/services/work-structure-service.ts`（新）

- `listWorks(auth)`：`works` + `volumes` + 章节数/正典数；按 `works.created_at, volumes.number` 排序。
- `createWork(auth, { title })`：插入作品；`work.created` 事件 + 审计。
- `renameWork(auth, workId, { title })`：同名视为无操作。
- `createVolume(auth, workId, { title, number? })`：`number` 缺省 `max+1`；唯一冲突映射 `VOLUME_NUMBER_TAKEN`。
- `renameVolume(auth, volumeId, { title })`。
- `reorderVolumes(auth, workId, { volumeIds })`：先校验是全集排列，否则 `VOLUME_ORDER_INVALID`；两段式改号（先写负数，再写目标号）绕过 `UNIQUE (work_id, number)` 的即时约束。
- `createChapter(auth, workId, input)`：
  - 卷必须属于该作品（`VOLUME_NOT_FOUND`）。
  - 无 `insertAfterChapterId`：`number = max(work)+1`，插到卷末。
  - 有 `insertAfterChapterId`：目标必须同作品（否则 `CHAPTER_NOT_FOUND`）、不能是自身，且必须与 `volumeId` 指向同一卷（否则 `POSITION_TARGET_INVALID`）；`reorderIds` 算出新顺序后两段式重排全书章号，再插入。
  - 新章 `status='planned'`、`plan='{}'`、`plan_revision=0`；不建草稿、不建 `chapter_metadata`、不建索引状态——列表如实显示"尚无正典"。
  - 事件 `chapter.created`、审计 `chapter.create`。
- `updateChapterMeta(auth, chapterId, input)`：
  - `title` 单独给 → 只改标题，不动章号、不动卷、不碰正文。
  - `volumeId` 单独给 → 只改归属卷，章号不变（目录按全书章号排序，仍落在正确位置）。
  - `insertAfterChapterId` 给（含 `null`）→ 只重排章号；若同时给 `volumeId` 且与目标章所在卷不同 → `POSITION_TARGET_INVALID`（不做静默改卷）；`null` 表示移到全书最前，卷归属只由 `volumeId` 决定。
  - 任何分支都不写草稿/正典/版本；`archived` 章节拒绝（`CHAPTER_ARCHIVED`）。

章号重排算法（≤1000 章，两次 UPDATE）：

```sql
-- 1) 目标顺序先写成负数（避开正数唯一键）
UPDATE chapters SET number = v.n
FROM unnest(${ids}::uuid[], ${negativeNumbers}::int[]) AS v(id, n)
WHERE chapters.id = v.id;
-- 2) 负数还原成 1..N
UPDATE chapters SET number = -number
WHERE work_id = ${workId} AND number < 0;
```

卷号同理（`volumes` 表）。两段式在单事务内完成，失败整体回滚。

权限：所有结构写操作用新增的 `assertCanManageStructure(auth)`（`apps/api/src/auth.ts`：人类主体 + owner/lead/author；`actorKindOf(auth) === 'ai'` 直接 403）；读用 `assertCanReadManuscript`；`billing` 读不到，`ai` 主体不能写。
