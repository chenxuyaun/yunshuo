## 二、先摆事实：三个候选今天各自"有几分"

### 2.1 (a) 伏笔回收建议：实现最弱，是真的——五条代码级证据

- **依据面只有一章**：`loadBasisChapter`（`apps/api/src/services/ledger-suggestion-service.ts:298-334`）单条 SQL、`LIMIT 1`，章节 id + work + workspace 三条件取一章正典。多章证据今天不存在。
- **正文面被裁切**：`CHAPTER_TEXT_LIMIT = 6000`（`:42`）；账本快照 `SNAPSHOT_TEXT_LIMIT = 800`（`:43`）。
- **检索面为零**：`ledger-suggestion-service.ts` 全文不引用 `packages/retrieval`（grep 0 命中）。伏笔回收历史读不到，模型只能硬猜——与分层设计 L5 行的描述一致（`docs/云说-模型侧基座分层设计-2026-10-26.md:170`："现在最弱：单发、800 字账本快照、6000 字正文，模型看不到回收历史就硬猜"）。
- **证据面固定两条**：`evidence` 数组固定为"依据章（含裁切详情）+ 生效版本"（`:878-891`），没有"相关历史章"这类证据类型。
- **写入面已被门框住**：建议只写提案表；`acceptLedgerSuggestion`（`:1273`）采纳后也只写该条目的**草稿版本**（`saveLedgerDraft`，`apps/api/src/services/ledger-service.ts:819`），发布仍需人工（`publishLedgerEntry`，`ledger-service.ts:951`）——ADR 理由 3 的代码级证据（原文是"只写草稿"，ADR `:26`）。

### 2.2 (b) 门禁改稿定位：今天零实现

"定位/改稿位置建议"在仓里 grep 零命中（无服务、无端点、无契约）。选它等于 L5 里同时含"从零做一个新功能"——对拍的是"新功能单发 vs 循环"，不是"现有能力搬上循环"。

### 2.3 (c) 章纲正文生成：已有单发生成，缺独立模式与独立验收

`AI_PROPOSAL_MODES = ['continue', 'expand']`（`packages/contracts/src/index.ts:203`）——提案没有名为"按章纲生成"的独立模式；但章纲驱动的单发正文生成已存在：续写模式无草稿时提示词明写"请按本章计划写出本章开头"（`apps/api/src/services/ai-service.ts:416`），且固定注入【本章计划】（`:428-429`）；唯一强制草稿的是加厚模式（`:505-506`）。章纲数据面刚补齐（`chapter_plan_revisions`，migration `0021_plan_and_structure.sql`）：缺的是独立模式与独立验收。

### 2.4 对拍标的的公共前提

L5 验收要求"同 prompt、同正文、**真实章长 2500–3500 字**"（设计文档 `:171`）。据此：(a) 的现路径天然是跨章证据需求，循环的多步/检索能力有发挥空间（ADR 理由 2）；(b)/(c) 连"单发版"都不存在，先要发明基线再搬循环，且 ADR 的三条理由都不适用。

## 三、真实的分界线：冲突到底是什么

ADR-0004 的核心不是三选一，而是这条冲突：

- M6 结论拒收"AI 建议质量评估"（`docs/云说-M6覆盖分析结论汇总-2026-10-26.md:145` 原文："AI 建议质量评估 | 无评估集，`m6s-v1` 提示与 token 估算系数未标定 | 不建评估集（原 §15.3 建议①不再排期）"）；
- M6 `:124` 的规矩："重启任一拒收项必须先重新决策……不能以「补一条测试」名义顺带恢复"；
- 而 L5 的"单发 vs 循环对比"**形态上就是一次质量对比**。

口径区分（ADR-0004 `:34-35` 原文；分层设计无此区分）：

- **运行路径黄金集**（L2b/L5 的验收物）：固定输入 + 固定断言，验证"循环的路径与终止是否如设计所愿"，**不评文字质量**。
- **提示标定评估集**（已拒收）：用标注数据调提示与 token 系数，**不做**。

**如实说**：L5 验收里的"引用命中率、事实一致性"（设计文档 `:171`）比"路径与终止"更靠近质量评估。它能不能站住，取决于判据形态：

- 判据若是**确定性可判**的（引用命中率 = 引用章号是否出现在检索结果/账本里；事实一致性 = 与正典/账本的确定性比对），它属运行路径黄金集；
- 判据若变成"人读两份稿子打分"，它就已经踩进被拒收的领域。

ADR-0011 的"提示标定 vs 安全对抗"判断表（判断什么 / 判据 / 需要模型判断吗 / 结果形态）是同一把尺子——D4 与 D11 签的是这句话的两个面。

**要人确认的那一句**：L5 对比口径限定为**确定性可判指标**（引用命中率、步数、token、成本、终止原因、按程序化比对的事实一致性），**不做人工打分**；报告只写"在这些确定性指标下循环 vs 单发"。

## 四、建议：取 (a) 伏笔回收建议，与 §三 口径限定一起签

理由（ADR 三条 + 本仓证据）：现有实现最弱（2.1）；跨章证据最需要工具，且检索面为零意味着改进空间是结构性的（2.1）；写入面已被门框住（2.1）。(b)/(c) 今天零实现（2.2/2.3）——对拍前先要发明"单发版"，对比会混入"新功能本身的成败"。

**代价如实标注**：

- 若循环质量不优于单发——**这是合法结论**（ADR `:41`），写进 README 诚实边界后停在 L5；前四层仍有独立价值。要接受"投入最重的一块可能产出负结果"。
- 真实章长对拍是真金白银的 token 消耗；"几百字测试章过不了这条线"（设计文档 `:171`）。
- (a) 被选中不等于循环已赢：今天它是单发用例，L5 的任务恰恰是把"单发做不到的多章证据"交给循环去证明。
