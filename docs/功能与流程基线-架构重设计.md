## 一、产品定位

**一句话**：面向单作者的本地优先 AI 长篇小说工作室，把“超长篇连载”拆成可计划、可生成、可质检、可入库、可回滚、可观测的章节生产线。

**当前作品状态**

| 项 | 当前值 |
| :--- | :--- |
| 作品 | 《规则档案馆》 |
| 正典章节 | 203 章 |
| 物理分卷 | 8 个 |
| 故事结构 | 1 卷内 13 单元（9 个副本 + 3 个幕间 + 1 个尾声） |
| 规划总量 | 800 章 |
| 下一目标章 | 第 204 章起，卷九《人世间》 |
| 当前连载口径 | 仍在连载 |

**参与者**

| 角色 | 职责 |
| :--- | :--- |
| 作者 | 做设定裁定、选择分支、确认计费、确认入库、决定发布 |
| AI 模型 | 生成分支、扩写、定向补实体、润色 |
| 确定性质检器 | 5 道硬门禁 + 5 类审计，不依赖模型 |
| 自动写作作业 | 批量生产，可预检、暂停、恢复、清理 |
| 工具生态 | MCP 工具、技能库、沙箱、思维链、分支打分 |
| 系统 | 健康自检、成本账本、备份、版本历史、验收 |

**三条产品原则**

1. **作者是最终决策者**：AI 产出不自动覆盖正文，所有入库、回滚、计费、清理都必须由作者确认。
2. **质量结论必须可验证**：只基于真实文件与确定性规则，禁止模型自评分数。
3. **拿不到就如实说**：不用假数据、模板、旧快照或猜测数字凑数。

## 二、功能全景

### 2.1 总览与导航

- **项目总览**：当前章数、卷数、总字数、下一目标章、连载进度。
- **十二工位星图**：以 3D 星图展示创作流程各工位，点击进入对应模块。
- **任务流控制台**：展示阶段、进度、日志，支持开始、暂停、重置。
- **系统拓扑**：展示各组件状态；其中部分拓扑与耗时属于**演示数据**，不能当作真实运维指标。
- **数据来源标注**：每个数字都标注出处；取不到时显示“未接入”，不保留旧假值。

### 2.2 创作准备

- **题材立意与时代基调**：书名、阶段里程碑、视角、文风、当前进度。
- **故事梗概与完整简介**：由八卷真实战果合成，并标注“合成口径”。
- **章节大纲与细纲**：卷 → 单元 → 章三层结构 + 逐章剧情节拍表 + 开篇节选。
- **长程大纲推演**：设置起始章与章数，逐章链式推演；默认使用本地启发式，零计费；结果可一键送入 AI 工坊。
- **人物关系与世界观**：角色档案、持有物、关系边、五层世界观。
- **完结管理**：账本结局态与运行态对照，主动暴露冲突，不静默取舍。

### 2.3 正文生产

- **项目上下文与状态表**：章节、卷、字数、角色运行态、神器、小队状态。
- **设定集与伏笔台账检索**：全库正文命中，每条结果带文件与行号锚点，回报真实命中总数与截断状态。
- **AI 工坊**
  - 多分支推演：策略、评分、风险、侵蚀增量、章末种子。
  - 三种扩写模式：续写、加厚、**定向补实体**。
  - 真实模型生成；可选**思考与正文分两路流式展示**。
  - 润色：五种取向 + 自定义指令；**只返回、不落盘**。
  - 上下文包：设定、角色、伏笔、结构、知识库五段可配。
  - 计费确认 + 零计费本地模式。
- **草稿箱与落盘**：门禁预检 → 隔离暂存 → 二次确认入库 → 丢弃。
- **五项审计中心**：AI 味、错别字、标点、敏感词、文内连贯度。
- **分镜表与视频画布**：按真实正文切场景、统计对白/动作/出场角色，生成抽帧建议与张力时间轴。
- **全本导出**：把全部章节拼成单文件；有界并发、顺序正确、缺章不冒充。

### 2.4 设定与角色

- **世界观**：五层架构、七曜地锁八环、阵营图谱、作者裁定表。
- **设定变更**：草案 → 预览差异 → 校验 → 应用 → 撤销。
- **待设计分区**：128 条死律等未核验内容**不水合**，不得显示为既定事实。
- **角色状态**：主角侵蚀度、SAN、神智阶段、三人小队状态。
- **侵蚀度危机**：85% 警戒、90% 红线，触发不同分支。
- **手动推进/压制侵蚀**：通过终端命令执行，变更类操作需确认。
- **势力战力与纪律**：阵营、地锁封印链、侵蚀度多源对照、设定一致性自动核对。
- **标签与实体索引**：24 个正典实体 × 203 章的逐章命中统计，可跳章。

### 2.5 质检与模型

- **五道硬门禁**：字数、AI 腔调、核心实体连续性、章末悬念钩子、底层因果律。
- **五类审计**：AI 味量化、错别字、标点规范、敏感词、文内连贯度。
- **可配阈值**：AI 味阈值由作者维护，越界拒绝并说明来源。
- **单章 / 全库扫描**：审计与门禁都支持。
- **只提示不改写**：审计结论不自动修改正文。
- **模型中心**
  - 服务商：新增、编辑、删除、启用/停用。
  - 模型：能力、上下文长度、采样参数。
  - 多密钥与轮询策略：轮询、随机、故障转移。
  - 五类场景路由：写作、推演、润色、审计、嵌入。
  - 分级体检：可达 → 鉴权 → 模型列表 → 深度对话。
  - 体检结果落盘；未体检显示“未知”，绝不当绿灯。
  - 激活服务商“可用性”按“已启用 + 有凭据或本地端点”判断。
  - 成本账本：真实用量，不估算 token、不编造单价。
  - 限流状态：每服务商 RPM 与并发，如实上报是否生效。
  - 导入导出：导出零密钥，导入保留本机密钥。

### 2.6 阅读、伏笔与发布

- **大纲与正文**
  - 卷/单元/章三层树 + 203 章列表 + 搜索与筛选。
  - 阅读/写作双栏。
  - 章级历史、逐版差异、二次确认回滚。
  - 章级操作：门禁预检、扩写、定向补实体、批量补写。
  - 分享阅读纯净模式：隐藏写作控件，正文单栏放大。
  - 跳至最新章节。
- **伏笔**
  - 七曜地锁封印链（八环）。
  - 真实账本：新增、回收、修订。
  - 版本冲突检测：冲突时要求重新读取。
  - 每条伏笔可跳转到目标章。
  - 历史口径（如 88 处提及）与账本条目（9 条）并列标注，不互相覆盖。
- **发布**
  - 目前是“阅读态 + 分享模式 + 全本导出 + 分镜/视频画布”。
  - **不接第三方发布平台**，产品文案需与此一致。

### 2.7 系统能力

- **知识库**
  - 索引范围仅限作品资料，不含内部文档。
  - 默认词法检索，可选本机语义检索。
  - 七类作用域：全部、正文、大纲、账本、审计规则、文明义理、其他。
  - 结果显示作用域、文件行号、小标题、高亮片段、上下文。
  - 正文结果可跳章，非正文可打开原文。
  - 向量覆盖率不足时，语义通道**主动不参与融合**，并如实标注。
- **MCP 工具**
  - 8 项内建工具，每项暴露参数说明。
  - 三种传输：进程内、子进程、流式 HTTP。
  - 子进程白名单；出站凭据隔离。
  - 变更类工具需确认。
  - 未实现能力如实列出，不假装成功。
- **自动写作**
  - 三种模式：续写、加厚、定向补实体。
  - 干跑预检、真实运行、停止、恢复、历史查看与清理。
  - 结构上不可能通过门禁的模式，**在花钱之前零调用拒绝**。
  - 结果逐章记录去向、字数、门禁结论。
- **推演与编排**
  - 思维链：开分支、打分、剪枝、回溯、对比。
  - Jev 分支打分：动作概率、熵、类型安全校验。
  - 集群：节点拓扑与流水线演示（**模拟**，不是真实集群执行）。
- **技能库**：扫描本地/全局技能包，运行态约 31 项。
- **版本与备份**
  - 章级版本历史，覆盖前自动留档。
  - 快照 + 清单 + 逐文件哈希校验。
  - 灾难恢复演练（同机还原）。
- **系统自检与验收**
  - 健康自检七项。
  - 单元/集成测试。
  - 真实浏览器端到端验收：结构、视图切换、控制台零错误。
  - 一键自检：健康、测试、端到端、文档一致、备份、写作通道、静态闸门、围栏配对、工作区边界等。
  - 源码指纹与二进制新鲜度校验。
  - 可选预提交钩子。
- **终端**
  - 单一引擎，命令历史、Tab 补全、日志导出。
  - 13 条命令：状态、校验、审计、角色状态、推进/压制侵蚀、工具清单、思维链、技能、集群、帮助等。
  - 变更类命令必须二次确认。

## 三、四条主循环

所有页面与面板，本质上都是这四条循环的视图。

### 循环 1：章节生产循环（主轴）

```
计划 → 上下文装配 → 写作/生成 → 质检 → 暂存 → 正典入库 → 账本/元数据同步 → 发布/观测
```

### 循环 2：设定与账本循环

```
检索 → 提出变更 → 校验/差异预览 → 应用（留备份）→ 撤销/追溯
```

### 循环 3：模型与成本循环

```
接入服务商 → 配模型/密钥/路由 → 体检 → 调用 → 计量 → 限流 → 优化或停用
```

### 循环 4：质量与运维循环

```
自检 → 验收 → 备份 → 恢复演练 → 发现缺陷 → 修复 → 更新基线
```

## 四、端到端流程

### 流程 1：人工创作一章

**触发**：作者想写或修订某一章。

1. 打开项目，水合全部章节元数据。
2. 查看上下文：进度、角色状态、未回收伏笔、上一章结尾。
3. 检索设定与伏笔。
4. 在阅读台或工坊写正文。
5. 门禁预检。
6. 五类审计。
7. 不通过则修改；通过则暂存到隔离草稿区。
8. 二次确认后正典入库。
9. 系统留历史版本、同步伏笔账本、更新元数据。
10. 看板与进度更新。

**失败分支**

- 门禁不过：拒绝入库，正文保留在编辑区或草稿区。
- 空草稿：直接拒绝，一字不落盘。
- 入库时账本同步失败：当前仍会报“成功”，但属于半完成态（重构需解决）。
- 并发修改：版本冲突，要求重新读取。

**产物**：正典章节 + 历史版本 + 账本更新 + 元数据更新。

---

### 流程 2：AI 辅助创作一章

**触发**：作者需要分支灵感、扩写、补实体或润色。

1. 输入写作目标与角色焦点。
2. 选择“本地推演（零计费）”或“在线推演（需确认计费）”。
3. 得到多分支：策略、评分、风险、侵蚀增量、建议开头。
4. 选择一个分支，送入扩写。
5. 选择模式：续写 / 加厚 / 定向补实体。
6. 系统装配上下文包：设定、角色、伏笔、结构、知识库。
7. 解析模型路由与采样参数。
8. 真实生成；可实时看到“思考”和“正文”两路增量。
9. 产出**不自动进编辑器**，作者先预览。
10. 可选润色；润色只返回结果，不落盘。
11. 对比润色前后的审计与门禁结论。
12. 作者点“采用到编辑器” → 暂存 → 入库。

**失败分支**

- 无可用模型：如实失败，正文为空，不拿模板冒充。
- 门禁不过：不写正典。
- 模式与门禁结构性冲突：**零调用拒绝**，不先花钱再失败。
- 流式中断：编辑器一字不动。

**产物**：AI 草稿（可选正典）+ 审计/门禁对比 + 真实用量记录。

---

### 流程 3：自动写作一批章节

**触发**：作者希望批量推进。

1. 配置作业：模式、起始章、数量、目标字数、是否入库、重试次数、加厚轮数、目标、模型、是否干跑。
2. 预检：
   - 模式是否合法；
   - 是否已有作业在跑；
   - 目标章节是否存在；
   - 所选模式是否**结构上可能**通过门禁。
3. 逐章执行：
   - 读取上一章结尾与未回收伏笔；
   - 装配上下文包；
   - 调模型生成；
   - 按需加厚；
   - 跑五道门禁。
4. 成功：落隔离暂存区；若允许入库，走与人工相同的入库流程。
5. 失败：记录明确原因（无产出 / 门禁失败 / 结构上不可能 / 拒绝保底引擎），不污染正典。
6. 作业结束：完成 / 失败 / 停止 / 中断。
7. 作者可查看每章去向、字数、门禁结论，可删除或清理历史。

**失败分支**

- 作业中断：历史记录标“中断”，不会自动续跑。
- 恢复：只重做没有结果的章，必须作者手动触发。
- 历史清理：干跑记录优先淘汰；真实作业不得被干跑挤出；已付费产出先取回再判去向。

**产物**：批量草稿或正典 + 作业历史 + 用量账本。

---

### 流程 4：作业中断与恢复

1. 进程重启后，未完成作业被标记为“中断”。
2. 系统列出哪些章已有结果、哪些还没有。
3. 作者查看“可恢复”状态与恢复入口。
4. 作者手动确认恢复。
5. 系统只重做缺失章，已有结果不重复生成。
6. 合并结果，更新作业历史。

**保护规则**：恢复会真实调用模型，**绝不自动发生**。

---

### 流程 5：世界观变更

1. 作者编辑设定草案。
2. 系统预览差异。
3. 校验：
   - 裁定一致性；
   - 待设计分区不得水合；
   - 未核验数字不得写入“已核验总数”。
4. 应用变更：版本校验 + 自动备份 + 回读自校验。
5. 所有下游读取同一真相源。
6. 可撤销到指定版本。

**失败分支**：版本冲突、校验不过、备份失败 → 拒绝应用，原文件不动。

**产物**：新设定版本 + 备份 + 撤销点。

---

### 流程 6：伏笔闭环

1. 检索现有伏笔与正文提及。
2. 新增伏笔：记录内容、目标章、状态、锚点。
3. 写作推进到目标章时，系统提示未回收伏笔。
4. 作者确认回收，状态改为“已回收”。
5. 需要修订时走“修订”动作，版本递增。
6. 冲突检测：版本不一致时要求重新读取。
7. 每次写入自动备份并回读校验。
8. 伏笔页、上下文包、长程大纲读取同一账本。

**产物**：账本新版本 + 备份 + 可追溯记录。

---

### 流程 7：章节修订与回滚

1. 打开章级历史。
2. 查看逐版差异。
3. 选择目标版本。
4. 二次确认回滚。
5. 系统覆盖当前正文，并留档被覆盖版本。

**当前缺口**：回滚是**第二条正典写入路径**，不经过五道门禁。重构时应决定：回滚也必须过门禁，或至少显式标注“未过门禁的回滚”。

---

### 流程 8：模型接入与体检

1. 新增服务商：类型、地址、密钥、启用状态。
2. 拉取真实模型列表。
3. 配置模型能力、上下文长度、采样参数。
4. 配置五类场景路由。
5. 测试连接：可达 → 鉴权 → 模型列表 → 深度对话。
6. 深度对话未确认计费时自动降级。
7. 一键体检，结果落盘。
8. 设置激活服务商。
9. 系统判断“激活项是否可用”：已启用 + 有凭据或本地端点。
10. 查看用量、限流、成本。
11. 导出配置（零密钥）或导入配置（保留本机密钥）。

**保护规则**：保存配置时，若无新密钥且选择不保留旧密钥，必须拒绝并说明，防止静默抹掉凭据。

---

### 流程 9：知识库建设与检索

1. 选择索引范围（仅作品资料）。
2. 建立词法索引。
3. 可选建立语义索引：本机嵌入模型，分批、可中断、可续做。
4. 查看文档数、分块数、覆盖率、当前引擎。
5. 检索：关键词 + 作用域过滤。
6. 结果展示作用域、文件行号、标题、高亮、上下文。
7. 正文结果可跳章，非正文可打开原文。
8. 新增/修改章节后增量更新。
9. 覆盖率不足时，语义通道不参与融合，并明确提示。

**产物**：可检索索引 + 覆盖率报告 + 检索结果引用。

---

### 流程 10：工具调用

1. 查看工具清单与参数说明。
2. 选择传输方式：进程内 / 子进程 / 流式 HTTP。
3. 变更类工具先确认。
4. 调用并展示原始响应与延迟。
5. 子进程工具受白名单约束；出站凭据隔离。
6. 流式 HTTP 会话有界，超界拒绝；未实现能力如实列出。

**产物**：工具响应 + 调用记录 + 可追溯的失败原因。

---

### 流程 11：分享、导出与发布

1. 进入分享阅读模式：隐藏写作控件，正文单栏放大。
2. 跳至最新章节。
3. 全本导出：有界并发收集，顺序正确，缺章不冒充。
4. 分镜表：按真实正文切场景，统计对白、动作、出场角色。
5. 张力时间轴：按对白比例、动作密度、章末钩子计算，可点击跳章。
6. 目前不向第三方平台发布。

**产物**：分享链接/阅读态、导出文件、分镜与时间轴。

---

### 流程 12：系统验收

1. 健康自检：服务、工作区、密钥、备份、写作通道等七项。
2. 单元与集成测试。
3. 端到端浏览器验收：页面结构、视图切换、控制台零错误。
4. 一键自检：测试、端到端、文档一致、备份、静态闸门、工作区边界等。
5. 文档锚点与数字一致性核验。
6. 源码指纹与二进制新鲜度校验。
7. 可选预提交钩子。
8. 任何写作类探针必须零计费，或走“计费安全跳过”。

**产物**：验收报告 + 截图 + 可复查的基线数字。

---

### 流程 13：备份与恢复

1. 创建快照：复制正典与关键数据。
2. 生成哈希清单。
3. 副本自校验。
4. 保留最近若干份。
5. 恢复演练：逐文件哈希比对。
6. 恢复后验证章节数与内容一致。

**当前风险**：备份与正典在同一块磁盘，属于单机单点。

## 五、功能状态模型

当前系统有一部分状态是隐式的，重构时建议补齐为一等状态。

| 对象 | 当前状态 | 建议补齐 |
| :--- | :--- | :--- |
| 章节 | 有正文 / 无正文；草稿 / 正典 | 计划中、生成中、待校验、门禁未过、已暂存、正典、修订中、已归档 |
| 作业 | 声明 9 个阶段，实际还会出现失败、停止、中断 | 配置、预检、运行中（读取/规划/生成/加厚/门禁/暂存）、完成、失败、停止、中断、可恢复、已清理 |
| 草稿 | 已暂存 / 已入库 | 增加“已丢弃”“已过期” |
| 伏笔 | 未回收 / 已回收 | 增加“已修订”“已失效” |
| 模型通道 | 未配置 / 已配置 / 可用 / 不可用 / 停用 | 增加“未体检”“降级” |
| 设定变更 | 草案 / 已应用 / 已撤销 | 增加“待预览”“校验失败” |
| 知识库 | 未建 / 词法 / 语义部分 / 混合 | 增加“覆盖率不足”“索引过期” |
| 发布 | 阅读态 / 分享态 / 已导出 | 明确“未对外发布” |

**核心建议**：把“章节生命周期”做成系统主轴。当前很多面板各自推断章节状态，容易出现“看板说完成、正典没写、账本没同步”的不一致。

## 六、业务规则与硬约束

### 内容与质量

1. **单一真相**：世界观、结构、账本、连载计划各有唯一权威源，其他位置只能引用或并列标注。
2. **正典写入保护**：必须过五道门禁 + 二次确认；草稿只能进隔离区。
3. **门禁不放宽**：存量章可按原字数豁免，但差距必须可见，永不得标“达标”。
4. **审计只提示**：不自动改写正文。
5. **AI 不自动覆盖**：生成、润色、流式增量都不得直接写编辑器。

### 计费与模型

6. **默认本地**：分支推演默认零计费；远程调用必须显式确认。
7. **验收零计费**：端到端验收中的写作探针必须走本地或安全跳过。
8. **结构上不可能满足门禁的模式，零调用拒绝**：不能先花钱再失败。
9. **失败如实**：无模型产出时返回空正文和真实原因，不拿模板/原文冒充。

### 数据与安全

10. **不造假**：取不到数据就显示“未接入”，不保留旧数字。
11. **来源可追溯**：每个展示数字都应有出处。
12. **写前留档**：覆盖正文、账本、设定前必须备份并可回滚。
13. **密钥安全**：不读取、不展示、不写明文密钥；保存配置不得静默抹掉凭据。
14. **工作区隔离**：所有操作限制在项目工作区内。
15. **变更需确认**：入库、回滚、触发模型、清理作业等不可逆或有成本的操作必须确认。

## 七、功能依赖关系

```
作者
 ├── 总览与导航（看进度、进模块）
 ├── 创作工坊（准备 + 生产 + 分析）
 ├── 阅读台（读、写、修订、回滚）
 └── 设定/伏笔页（维护约束源）
            │
            ▼
   章节生产主链
   计划 → 上下文 → 生成/写作 → 质检 → 暂存 → 入库 → 同步 → 发布
      ▲          ▲            ▲
      │          │            │
  结构/设定/账本  知识库     模型/成本
      │                       │
      └──── 历史/备份/验收 ◄───┘
```

**依赖解释**

- **结构、设定、账本**是约束源：决定“这一章该写什么、不能写什么”。
- **知识库**是上下文源：为生成和检索提供可引用的素材。
- **模型与成本**是生产能力：决定能不能生成、花多少钱、是否可用。
- **质检门禁**是写入门：所有进入正典的内容必须经过它。
- **历史与备份**是安全网：保证任何覆盖可回退。
- **作业引擎**是批量化：把单章流程自动化，但不改变流程规则。
- **总览与验收**是观测面：不产生内容，只消费真实状态。

## 八、现有功能缺口（重构必须解决）

### A. 创作闭环断点

1. **41 章被“核心实体锚点”门禁卡住**，而“加厚”模式结构上补不上锚点，自动写作对这些章难以成功。
2. **阅读台批量补写只发“加厚”**，没有“定向补实体”入口，也不展示每章结果；对这些章会先花钱再被门禁拦。
3. **视角声明与正文不符**：设定声明“第一人称”，但约一半章节实际是第三人称；扩写提示仍要求第一人称，属于错误引导。
4. **入库目标由标题推断**，缺少显式“目标章”确认，存在误覆盖风险。
5. **回滚绕过门禁**，是第二条正典写入路径。
6. **入库不是事务**：正文、账本、元数据任一步失败可能留下半完成态，且当前账本失败仍报成功。
7. **章节缺少一等状态**，无法统一回答“这章现在处于什么阶段”。
8. **作业状态声明不完整**，失败/停止/中断等状态未进入统一状态机。

### B. 安全与计费

9. **同一个“仅本地/零计费”开关，在三个写作能力上缺省值不同**：分支推演默认安全，扩写与润色默认允许出站。
10. **临时探测仍是计费盲区**：测试套件有护栏，但手工命令、脚本、浏览器控制台不受约束。
11. **无鉴权、单机单点**：仅靠本机监听与来源限制；备份与正典同盘。

### C. 数据一致性

12. **陈旧兜底快照**：前端保留 105 章 / 5 卷的旧数据，接口失败时可能误导。
13. **多处口径重复**：字数门槛、审计数量、路由数量、视角声明等存在多份说法。
14. **模拟集群指标看起来像真实指标**，容易被误读。
15. **成本账本真实，但价格表不完整**；系统选择“不猜价”，需要产品层明确展示“未知成本”。

### D. 前端与入口

16. **后端有能力、页面无入口**的情况仍存在（批量定向补实体是典型）。
17. **视图之间靠全局函数互调**，没有统一状态与模块边界，改一处容易影响多处。
18. **错误提示形态不统一**，同一类失败在不同页面表现不同。

### E. 运维与验收

19. **无持续集成**；预提交钩子需手动安装，且不包含端到端验收。
20. **文档与基线数字容易漂移**，需要机械核验。
21. **作业历史保留策略**曾把作者真实作业挤出且无副本；现已修复，但仍需产品化保留规则。
22. **“长程大纲推演”默认只是本地启发式**，不是模型推演，产品定位需说清。
23. **“发布”不是发布**，目前只是阅读、分享与导出。
24. **知识库语义通道依赖本机嵌入服务**，服务不在时只能退回词法。

## 九、重构时的功能边界建议

建议把系统拆成 10 个功能域，每个域只对自己的真相负责。

| 功能域 | 核心职责 | 不承担 | 关键输入/输出 |
| :--- | :--- | :--- | :--- |
| 作品与结构 | 卷、单元、章、连载计划、元数据 | 不负责生成正文 | 结构表、计划、章节索引 |
| 设定与账本 | 世界观、阵营、地锁、裁定、伏笔账本、角色状态 | 不负责写章 | 设定版本、账本版本、冲突报告 |
| 章节生产 | 写作、生成、扩写、补实体、润色、暂存、入库 | 不定义质量规则 | 草稿、正典章节、生产记录 |
| 质量与门禁 | 五道门禁、五类审计、阈值、存量豁免 | 不改写正文 | 通过/不通过、问题清单、阈值来源 |
| 模型与成本 | 服务商、模型、密钥、路由、体检、用量、限流 | 不决定写什么 | 可用模型、真实调用、成本账本 |
| 知识检索 | 索引、作用域、检索、引用定位 | 不生产内容 | 检索结果、行号引用、覆盖率 |
| 作业自动化 | 作业定义、运行、状态、恢复、保留策略 | 不绕过生产/质检规则 | 作业状态、逐章结果、历史 |
| 工具集成 | MCP、技能、沙箱、思维链、分支打分 | 不直接写正典 | 工具响应、推演结果、执行记录 |
| 阅读与发布 | 阅读、分享、导出、分镜、时间轴 | 不改变正典 | 阅读态、导出文件、分镜 |
| 观测与验收 | 健康、测试、验收、备份、指纹、文档一致性 | 不产生业务内容 | 自检报告、验收基线、备份清单 |

### 横切能力

- **作者身份与确认**：谁批准了计费、入库、回滚、清理。
- **事件与审计轨迹**：每次生成、校验、入库、同步、变更都可追溯。
- **配置与密钥**：统一管理，写入 fail-closed。
- **进度与通知**：长任务、作业、体检的进度与失败原因。

### 以“章节生命周期”为中心的功能主线

建议围绕一个章节聚合，定义明确的命令与事件：

**命令**

- 计划章节
- 装配上下文
- 生成草稿
- 校验草稿
- 暂存草稿
- 正典入库
- 同步账本与元数据
- 修订章节
- 回滚章节
- 导出/分享

**事件**

- 章节已计划
- 草稿已生成
- 门禁已评定
- 草稿已暂存
- 章节已入库
- 账本已同步
- 设定已变更
- 作业状态已变化
- 模型调用已记账
- 备份已创建

这样，工坊、阅读台、看板、自动写作都只是“命令的入口”或“事件的视图”，不再各自维护一套流程。

## 十、需要作者先定的产品决策

1. **AI 的定位**：建议器、代笔，还是允许无人值守自动连载？目前三种都存在。
2. **自动写作是否允许无人值守入库**？当前默认只落隔离区，入库需显式开启。
3. **41 章锚点门禁怎么办**：手改、定向补实体、放宽存量章，还是暂时跳过？
4. **视角统一**：全书第一人称、按卷声明，还是明确“混合视角”？
5. **回滚是否必须过门禁**？
6. **入库是否必须事务化**：失败时回滚正文，还是保留正文并明确标“半完成”？
7. **成本策略**：所有写作能力是否统一“默认本地、远程显式确认”？
8. **发布边界**：只做阅读/导出，还是要接第三方平台？
9. **多用户与鉴权**：保持单机单作者，还是需要登录与权限？
10. **模拟模块**：集群拓扑、3D 拓扑中的模拟指标，保留并明确标注，还是删除？
11. **知识库语义通道**：是否要求本机嵌入服务常驻？
12. **作业历史保留规则**：保留多少条、真实作业是否永不自动淘汰？

## 十一、一句话重构主线

**以“章节生命周期”为主轴，以“设定与账本”为约束源，以“质检门禁”为写入门，以“模型网关”为成本闸门，以“作业引擎”为批量化，以“事件与历史”为可追溯；所有页面都只是这些能力的入口与视图。**
