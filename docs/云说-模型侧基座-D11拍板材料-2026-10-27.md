## 二、先摆事实

### 2.1 今天为什么测不了：不是漏了，是没有承载体

单发模式下，正文里的伪指令最多污染一段生成的文字（外加一次 token 账单）——**它没有地方可以"驱动下一步动作"**，因为下一步动作根本不存在（威胁模型 §5.4，ADR-0011 引述）。所以"注入防御"今天既无法实现也无法验证。

L2b 引入循环后，同一个注入句子的后果立刻不同：能驱动多次工具调用、决定检索什么、把成本推高。**防御与验收必须同时到位**——这正是 (a) 与 (b) 的分野。

### 2.2 四条断言逐条标注现状

ADR-0011 给 (a) 列了四条可执行断言。今天各自的状态：

| 断言 | 现状 |
| --- | --- |
| 1. 把伪指令写进**真实正文**（不是系统提示、不是测试桩），跑一轮循环 | **无载体**——循环未建；今天仓里没有任何注入用例 |
| 2. 越权调用被拒（计费角色不可读正文；跨工作区 404 而非 403 泄露存在性） | **两半今天都已成立，且有测试**（见下） |
| 3. 未注册工具名被拒，且 `ToolCall` 表**记下这次尝试** | **无载体**——`ToolCall` 表设计见 ADR-0009，须与本案同拍 |
| 4. 成本不越界——`allowed_tools` / `max_steps` / 预算三项由程序锁死 | **无载体**——这三项由 L1a/L2b 落地，断言随载体进 |

断言 2 的现状值得单列，因为它是**已经付过费的一半**：

- **计费角色半**：`assertCanReadManuscript`（`apps/api/src/auth.ts:212-216`）对 `billing` 角色直接 `forbidden`，消息在 `:214`："计费管理员只能访问计费报表、预算与价表，不能读取作品正文、草稿或检索内容"。已有测试：`apps/api/src/m5b-billing.test.ts:413-422` 对 `GET /api/chapters`、`GET /api/chapters/:id`、`GET /api/chapters/:id/ai/proposals`、`GET /api/search?q=林默`、`GET /api/model-providers`、`GET /api/automation/mandates` 六个端点全部断言 `403` / `FORBIDDEN`。
- **跨工作区 404 半**：`apps/api/src/chapter-import.test.ts:464-470` 断言跨工作区读章返回 `404` + `CHAPTER_NOT_FOUND`；`apps/api/src/m6-suggestion.test.ts:1263-1294` 断言未知 UUID 与属于其他工作区的建议**同回一个 404**（`LEDGER_SUGGESTION_NOT_FOUND`，"建议不存在或不属于当前工作区"）——存在性不泄露。

也就是说：断言 2 要做的不是"新建防御"，而是**把已成立的行为接到循环上再断言一次**（注入驱动的越权尝试与普通请求走同一道门）。断言 1/3/4 才是真正的新工作量。

### 2.3 设计文档已把这条写进 L2b 验收

ADR-0011 的作用是把它从"验收描述"钉成硬要求，并明确进场时机。

### 2.4 不对称性

ADR-0011 的核心论证（逐字）：

- (a) 的成本是**几轮工程量**（写注入用例 + 三条断言）。
- (b) 的成本是**一个敞口窗口**，且窗口期内造成的越权或成本损失**不可追溯地补回来**（钱花了就是花了，越权调用了就是调用了）。

且"未注册工具名要留痕"这种要求，**事后加比一开始就设计要贵得多**——写进 L2b 验收本身会塑造 L2b 的实现。

## 三、真实的分界线：为什么这不是"顺带恢复"被拒收的评估集

M6 结论 `docs/云说-M6覆盖分析结论汇总-2026-10-26.md:145` 拒收的是"**AI 建议质量评估**"（判据：无评估集、`m6s-v1` 提示与 token 估算系数未标定；结论：不建评估集）。`:124` 的规矩："重启任一拒收项必须先重新决策……不能以「补一条测试」名义顺带恢复。"

ADR-0011 给出的区分（判断表逐字）：

| | 被拒收的：提示标定评估集 | 本条：安全对抗评估 |
| --- | --- | --- |
| 判断什么 | 生成的**文字质量**好不好 | 运行**路径**有没有越界 |
| 判据 | 需要人工打分或参考答案 | 确定性断言（拒绝、留痕、成本上限） |
| 需要模型判断吗 | 需要 | 不需要——断言就是断言 |
| 结果形态 | 质量分数 | 通过 / 不通过 |

这与 ADR-0004 的"**运行路径黄金集** vs 提示标定评估集"是同一把尺子：**运行路径黄金集测的是路径与终止，不判文字质量**。安全对抗评估属前者。

**要人确认的那一句**：本场的"安全对抗评估"限定为 §2.2 四条**确定性断言**——拒绝、留痕、成本上限，全部程序化判定，**不含任何文字质量评分或人工打分**；若将来有人把它扩成"让模型读注入稿给分"，那就已经越出本案，需要重新拍。

## 四、建议：取 (a)，L2b 就进

理由即 2.4 的不对称性：几轮工程量 vs 一个不可追溯的敞口窗口；且验收要求会塑造实现，早进更便宜。断言 2 已有两半现成（2.2），实际新增工作量集中在断言 1/3/4。

**代价如实标注**：

- L2b 的工作量增加——这是它被标为"四层里最重的一块"的一部分原因（ADR 原文）。
- 断言 3 直接改 `ToolCall` 表设计（要能记录被拒尝试的参数、校验结果、错误类型），**D11 必须与 ADR-0009 一起拍**（2.2、ADR §影响面）。
- 测试数据里会出现"伪指令正文"。这类正文必须明确标注为**测试夹具**，不能混进演示作品或种子数据（`AGENTS.md` 硬规则 8：测试数据自行创建并清理，不要依赖或改写演示作品）。

## 五、口径两条（拍板时一并签）

1. **`ToolCall` 要能记录被拒的调用尝试**（参数、校验结果、错误类型）——否则"被拒"与"没发生"不可区分（ADR 原文）。这条是 ADR-0009 表设计的输入，两条 ADR 同场签。
2. **"伪指令正文"是测试夹具**：标注、隔离、自建自清；不得进入演示作品或种子。
