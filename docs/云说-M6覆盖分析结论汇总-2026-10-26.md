# 云说 M6 覆盖与验证分析结论汇总（2026-10-26）

> 本文汇总到 2026-10-26 为止的分析结论、口径与未覆盖清单。逐轮操作、枪表与证据在 `docs/云说-M6回顾审计报告-2026-10-22.md`（§一–§八十八），本文不复述执行过程。文中的数字均为本机实测；未实测的项写明"未验证"。

## 一、口径：这里的"覆盖"指什么

- **覆盖 = 断言口径**：测试里对行为或归因码有字面量断言，并用变异枪证明断言有杀伤力。**不是**行覆盖率或分支覆盖率——仓库没有接入 c8/istanbul，也没有覆盖率报告。
- **两个筛子是粗筛**：错误码筛子只判断"码是否在测试里以字面量出现"；端点筛子只判断"路由是否被测试按完整路径形状引用"。
- **真实依赖**：API/worker 集成测试跑真实 PostgreSQL（强制 `yunshuo_test`），不 mock 数据库；API 测试文件串行（`fileParallelism: false`），根测试单并发。
- **变异枪**：临时脚本放在仓库外（`C:\Users\yuesh\.qoder\tmp\`），每轮结束按 md5 逐字节还原源文件；枪架不进仓库。

## 三、错误码：176 个，172 个被断过，4 个未断

### 3.1 四个未断码的结论（详见 §八十八）

| 码 | 抛点 | 结论 | 要钉住缺什么 |
| --- | --- | --- | --- |
| `AI_NO_ATTEMPT` | `ledger-suggestion-service.ts:1064` | **结构不可达**：服务商列表非空前置（`NO_MODEL_PROVIDER` / `PROVIDER_KEY_UNREADABLE`）+ 调用前已解引用 `providers[0]` + 循环非空必执行一轮 | 产品测试缝（把列表在读后置空）；否则只能造假前置 |
| `LEDGER_WORK_REQUIRED` | `ledger-service.ts:329`、建议侧 `846/1326` | **数据库 + 契约双重不可达**：`ledger_entries` 两条 CHECK、`createLedgerEntrySchema` 必填 `workId`、三处调用点都过不了；建议侧 setting 先被 `KIND_UNSUPPORTED` 拒掉 | 放开 CHECK 或绕过 schema 直调服务（都不做） |
| `INTENT_RACE` | `commit-service.ts:99`、`rollback-service.ts:123` | **当前单进程测试构造不出**：`ON CONFLICT DO NOTHING` 后同键查询必能看到胜者；产品无删除 `commit_intents` 的路径 | 语句间带外删除（临时触发器 / 产品缝） |
| `OIDC_IDENTITY_CONFLICT` | `oidc-service.ts:414/423/431` | **需要并发回调或异常上游**：入口短路使 413 条件恒假；422 需并发同 subject 且邮箱不同以绕过 advisory lock；431 被锁与唯一索引堵住 | 并发回调注入 / 产品缝，或依赖 IdP 同 subject 返回异邮箱（测不稳） |

共同口径：不宣称"永不可能"，只宣称"当前产品路径 + 单进程真实 DB 测试构造不出"。四码继续留在筛子空白名单，没有为了归零去改产品、放开约束或加白盒假入口。

### 3.2 最近关闭的五条空白

- `AI_TIMEOUT`、`CLIENT_ABORTED`：服务层注入截止时间与中止信号（§八十五）。
- `WORKSPACE_NOT_FOUND`：合成不存在的工作区 id 复现陈旧会话守卫（§八十六）。
- `COMMIT_FAILED`、`ROLLBACK_FAILED`：真实事务互锁，PostgreSQL 判 `40P01`（§八十七）。

### 3.3 这个指标不能说明什么

- **字面量命中 ≠ 每个抛出点都测过**：同一个码常打在多个路由/分支，断其中一处不代表其余。
- **码集只来自 `apps/api/src` 的 46 个非测试文件**；worker、packages、web 里的码字面量不进这张表。
- **筛子不扫 web 测试**，web 里的码断言不计入 172。
- **14 处动态码位点已人工定性**（构造器本体透传、两个限流码、`exchangeCode(input.code)` 同名不同义等），明细见 §二十六；本轮未再改动筛子。

## 四、端点：87 条全部被引用，但引用不代表分支覆盖

- 87/87/0 指：每条路由至少被某个测试按完整路径形状调用过一次。参数化路径按"`:param` 视为一段通配、参数后的字面段也要出现"匹配（早期假命中已在 §十四 修正）。
- **不代表 87 条的所有分支都测过**：仍有一批只走正常路径；错误分支靠错误码筛子与单独用例覆盖。
- 端点层的补充结论：两条 dev 端点、`/api/health` 的 200/503、生产 `Set-Cookie` 的 `Secure`、`OIDC_DISABLED` 等都已有专门断言（§二十八–§三十一、§三十五、§三十七）。

## 五、真实依赖与故障注入的边界

- **主路径**：真实 DB + `app.inject` 走 HTTP；少数最难构造的分支直接在服务层调用（AI 超时/中止、预算守卫不可用、工作区缺失、提交/回滚死锁）。
- **服务层断言的代价**：HTTP 响应形状不保证。例如 `40P01` 原样重抛后路由仍答 500 `INTERNAL`，这个形状本轮没断；`CLIENT_ABORTED` 仍不发往客户端（§二十六 判定不变）。
- **已做的真实故障注入**：提交/回滚事务死锁。两个事务互锁、由 PostgreSQL 判 `40P01`，牺牲者靠 `SET LOCAL deadlock_timeout` 的先后选定；12 支枪全击毙，G3/G5 另做过滤重放（§八十七）。
- **未做的注入**：连接中断、序列化失败、语句级带外删除、OIDC 并发回调、多进程竞争。

## 六、Web：316 项全部在静态层

- web 单包没有 jsdom / happy-dom / @testing-library；组件断言用 `renderToStaticMarkup`，另有纯函数、SSE 客户端、请求封装、时间格式化用例。
- 因此**没有覆盖**：事件处理与回调、effect、mutation 触发、禁用态真实可点性、Escape/滚动锁、焦点、CSS/视觉、响应式布局。
- 已覆盖的是"默认态 + 注入错误态/空态/徽标分叉"的展示语义；交互链路仍没有自动化回归。

## 七、方法结论（影响数字怎么读）

1. **整文件变红 ≠ 新用例钉住**：失败用例留下的状态会连累后续用例（§八十七 的 G3/G5 必须过滤重放才拿到独立证据）。
2. **`toContain` 可能被页面别处同词兜住**：多处改成整段全等（§八十四）。
3. **SSR 断言对空格、属性顺序敏感**：出过假红与假绿；夹具取同值（决定人=批准人、同时间）会让回退分支假存活。
4. **默认重试会掩盖错误态**：`retryOnMount` 等必须显式关闭（§六十八）。
5. **枪架锚点必须唯一、源文件必须逐字节还原**：还原靠 md5，不靠"看起来没改"。
6. **枪只证明"这条断言能杀死这个变异"**：不证明产品没有别的错误路径，也不等于分支覆盖。

## 八、未覆盖 / 未验证清单（如实）

1. 四个错误码（§三），原因见 §八十八。
2. 死锁两条链的 HTTP 响应形状（500 `INTERNAL`）未断言；只断了服务层归因与整笔回滚。
3. 其它基础设施故障族：连接中断、序列化失败、连接复用异常等。
4. worker 只有 15 项 / 2 个文件（`pipeline.test.ts` 10 项、`ledger-pipeline.test.ts` 5 项），覆盖索引管线与账本索引管线的若干分支；没有 API + worker 的真实并发编排回归。
5. 没有浏览器自动化回归或 E2E；历轮界面验收是人工浏览器点验 + SSR 断言，React 交互没有可重复的回归网。
6. 没有行/分支覆盖率工具；本文所有"覆盖"都是断言口径。
7. 性能只有既有合成基线（单 API、无 worker 参与的两类，以及千章索引排空/检索；详见 README「诚实边界」），不覆盖多用户并发写、长稳、故障恢复。
8. 产品未接入项不变：地点跳变检测、通知、发票 OCR/自动分账、自动备份与高可用等（README「诚实边界」）。

## 九、产品侧顺带结论

- `LEDGER_WORK_REQUIRED` 的四处应用层检查在当前 DB 约束与契约下打不到，属于防御性代码（不是 bug）。
- `AI_NO_ATTEMPT` 的尾部兜底分支当前不可达，同样属于防御性代码。
- `INTENT_RACE` 与 OIDC 的 431 兜底只在极窄竞态/异常上游下可能出现，属于最后一道防线。
- 这些都不构成本轮改产品的理由；若未来要补钉，先决定是否接受"产品测试缝"。

## 十一、一句话结论

到 2026-10-26，M6 的测试网在"错误码字面量归因、87 条路由可达性、界面默认/注入态、提交与回滚死锁"四个面上有可复查证据；但它是断言覆盖，不是行/分支覆盖。四个错误码已有明确分诊结论，不再是待办；真正敞开的边界是交互链路、真并发、其它基础设施故障、worker 编排与浏览器级回归。
