## 一、四项决策与架构结论

| 决策 | 架构含义 | 必须补的护栏 |
| :--- | :--- | :--- |
| 正典正文收进向量数据库 | 正典正文、版本、账本、权限、向量同库；检索与正典不再两套数据 | 必须是事务型、带版本与访问控制的向量能力；纯向量库不能单独当正典主库 |
| 允许无人值守入库 | AI 作业可在授权策略内自动提交正典 | 自动化授权、AI 服务主体、门禁全过、不得自批豁免、事后抽样复核 |
| 回滚允许显式豁免 | 回滚走统一提交链，可凭豁免单跳过门禁 | 豁免单可追溯、审批分离、只生成新版本、界面显示“已豁免”而非“已通过” |
| 多用户作者 | 工作区、角色、租约、草稿分支、评论、审计、计费归属 | 租户隔离、章节租约、职责分离、AI 主体权限上限、按工作区备份 |

**一句话边界**：提案面（AI/工具）只能产出候选；决策面（章节生命周期/门禁/正典）是唯一提交者；证据面（检索/审计）不能改正文；观察面（看板/报表）只读投影；身份与治理面横切所有面。

## 二、需求与冲突

### 2.1 不能丢的三条原则

1. **作者是最终决策者**：多用户下变为“作者集体通过角色与策略授权”。AI 的自动入库必须有可撤销的人类授权，但不需要每次弹窗。
2. **质量结论必须可验证**：门禁仍然是确定性的；豁免是显式例外，不是放宽规则。
3. **拿不到就如实说**：多用户和向量化后仍然保留来源、时间、验证态；不回落旧快照。

### 2.2 四项决策与原则的冲突及解法

- **无人值守 vs 作者最终决策**
  把“每次确认”改为“策略授权 + 事后复核”。Owner/主笔授权一个自动化范围；AI 在范围内执行；越界、门禁失败、需要豁免时停下来找人。AI 不能给自己授权，也不能批准豁免。

- **回滚豁免 vs 门禁不放宽**
  门禁默认仍强制执行；豁免是绑定具体章节、版本、规则的一次性审批，必须由非申请人批准；界面和报表永久显示“已豁免”。

- **正典入向量库 vs 可验证、可回滚**
  选择事务型向量能力（正文、版本、权限、向量同库），而不是把纯向量索引当唯一主库。向量检索是正典库的一种能力，不是另一份真相。

- **多用户 vs 本地优先**
  改为“数据主权优先 + 两种部署形态”：Solo（单机本地）与 Studio（工作区服务器，可局域网或私有云）。默认不把正文发给第三方模型；远程调用需工作区策略与花费授权。

### 2.3 架构驱动

1. 唯一章节状态；
2. 唯一正典写入路径；
3. 确定性门禁与证据；
4. 模型调用与成本封口；
5. 多用户隔离与职责分离；
6. 无人值守的可授权、可审计、可撤销；
7. 800 章规模的检索与版本；
8. 不造假、可追溯。

## 三、总体架构

### 3.1 五个平面

| 平面 | 负责 | 不能做 |
| :--- | :--- | :--- |
| 身份与治理 | 工作区、成员、角色、策略、授权、审计 | 不生成内容、不裁决质量 |
| 决策面 | 章节生命周期、正典/账本、门禁裁决、作业状态 | 不生成内容 |
| 提案面 | 上下文装配、模型调用、AI 作业、工具/Hermes | 不能写正典 |
| 证据面 | 检索、确定性审计、门禁证据、引用 | 不能改正文 |
| 观察面 | 看板、成本、健康、备份、报表 | 不能推断状态、不能回退旧数据 |

```text
作者 / 审阅者 / 所有者
          │ 命令
          ▼
┌──────────────────────────────────────────────┐
│ 身份与治理：工作区 · 角色 · 策略 · 授权 · 审计 │
└──────────────────────────────────────────────┘
          │
          ▼
┌──────────────────────────────────────────────┐
│ 决策面（唯一提交者）                          │
│ 章节生命周期 · 正典/账本 · 门禁 · 作业状态     │
└───────▲──────────────────────┬───────────────┘
        │ 提案                  │ 事件
┌───────┴──────────┐   ┌───────▼─────────────┐
│ 提案面            │   │ 观察面（只读投影）   │
│ 上下文/模型/作业/ │   │ 看板/成本/健康/备份  │
│ 工具/Hermes       │   └─────────────────────┘
└───────▲──────────┘
        │ 证据
┌───────┴──────────┐
│ 证据面            │
│ 检索/审计/门禁证据 │
└──────────────────┘
```

### 3.2 部署形态

- **Solo**：单机；本地数据库（带向量能力）；本地模型；单用户；无外部依赖；适合个人作者。
- **Studio**：工作区服务器；数据库 + 向量；对象存储（导出/备份）；模型网关（本地 GPU 或远程 API）；本地账号或 OIDC；多作者并发；按工作区隔离。
- 两种形态共用同一套领域模型与提交链，不做两套产品。

### 3.3 运行时边界

| 组件 | 职责 | 边界 |
| :--- | :--- | :--- |
| 应用核心 | 身份、作品结构、章节生命周期、正典、门禁、作业、协作 | 模块化单体；唯一正典写入者 |
| 数据库 | 正典正文、版本、账本、权限、正文块、嵌入、事件 | 事务型；向量检索是其中一种能力 |
| 模型网关 | 所有模型调用的唯一入口 | 独立进程/服务；屏蔽本地与远程差异 |
| AI 工作进程 | 生成、扩写、润色、工具调用、提案 | 可选 Hermes；不持有正典状态 |
| 索引/嵌入进程 | 切块、嵌入、索引新鲜度 | 异步、可重建、不阻塞提交 |
| 沙箱 | 工具执行隔离 | 工作区级限额与白名单 |
| Web 界面 | 角色化视图、进度、审阅 | 只读投影 + 命令 |

### 3.4 边界规则

1. 任何正典写入只能经过提交链；导入也算一种提交。
2. 任何模型调用只能经过模型网关；界面、命令行、作业、工具不得直连供应商。
3. 任何视图只能读投影；不得跨视图调用内部逻辑。
4. 任何 AI 产出都是提案；AI 不能成为正典状态的持有者。
5. 任何豁免必须有人类批准；AI 只能申请，不能批准。

## 四、领域模型与数据所有权

### 4.1 领域清单

| 领域 | 拥有 | 不拥有 |
| :--- | :--- | :--- |
| 身份与工作区 | 用户、工作区、成员、角色、策略、会话 | 作品内容 |
| 作品与结构 | 作品、卷、单元、章节目录、计划、元数据 | 正文版本、门禁结论 |
| 章节生命周期 | 章节状态机、当前正典指针、草稿/分支引用、租约 | 正文内容本身、规则实现 |
| 正典与向量 | 正典版本、正文块、嵌入、索引状态、引用锚点 | 结构计划、门禁规则 |
| 设定与账本 | 世界观、阵营、地锁、裁定、伏笔、角色状态、事实验证态 | 章节状态 |
| 质量与门禁 | 门禁/审计规则版本、评估结果、证据、豁免 | 正文修改 |
| 模型与成本 | 供应商、模型、路由、花费授权、用量、限价 | 作品内容 |
| 上下文与检索 | 上下文包、检索结果、覆盖度、来源引用 | 正典写入 |
| 作业自动化 | 作业定义、状态机、预检、检查点、恢复、保留 | 章节状态（只推动，不拥有） |
| 协作与审阅 | 评论、审阅请求、通知、章节租约的协作视图 | 正典版本 |
| 工具与推演 | MCP 工具、技能、沙箱、分支打分、思维链 | 正典写入 |
| 阅读与导出 | 阅读态、分享、导出、分镜、时间轴 | 正典修改 |
| 观测与运维 | 事件日志、审计、指标、健康、备份、验收 | 业务内容 |

### 4.2 概念数据模型（只列实体与关系）

- 工作区 → 成员 → 角色；工作区 → 作品 → 卷 → 单元 → 章节。
- 章节 → 正典版本（不可变）→ 正文块 → 嵌入；章节 → 草稿分支 → 提案。
- 章节 → 门禁评估 → 证据；门禁评估 → 豁免（可选）。
- 工作区 → 自动化授权 → 作业 → 逐章结果 → 模型调用/花费。
- 工作区 → 设定版本/账本版本/事实；事实带验证态。
- 工作区 → 事件/审计；事件 → 投影（章节状态、作业状态、成本、覆盖率）。
- 章节 → 租约；章节 → 评论/审阅。

### 4.3 数据所有权规则

- 每个事实只有一个写入者；跨域只能发命令/事件，不能直接改表。
- 正典版本不可变；修订/回滚产生新版本。
- 嵌入是正典版本的派生数据，可重建；不得成为唯一真相。
- 投影可重建；不得作为写入依据。
- 审计日志只追加；不得修改或删除（保留策略除外）。

## 五、多用户身份、角色与权限

### 5.1 角色

| 角色 | 定位 |
| :--- | :--- |
| Owner（所有者） | 工作区所有者；成员、计费、策略、最终裁决 |
| Lead Author（主笔） | 正典审批、设定/账本重大变更、豁免审批、自动化授权 |
| Author（作者） | 创建/编辑草稿、提交审阅、在策略允许时提交自己的章节 |
| Reviewer（审阅者） | 阅读、评论、跑审计/门禁、批准/驳回审阅；不直接入库 |
| Viewer（读者） | 只读 |
| Billing Admin（计费管理员） | 预算、价格表、费用归属报表；不碰正文、服务商端点与密钥 |
| AI Principal（AI 主体） | 服务账号；在授权范围内生成/提交；权限上限固定 |

### 5.3 职责分离

- 申请人不能批准自己的豁免；AI 永远不能批准豁免。
- 自动化授权只能由 Owner/Lead 发出；AI 不能修改授权、不能扩大范围。
- 计费授权与内容审批分离：Owner 与 Billing 管预算、价表和费用归属，Billing 不读正文、草稿、检索、AI 提案、服务商端点与密钥；Lead 可读报表但不改预算/价表，Lead 管质量。
- 计费报表只含调用元数据（用途、成员、作业、章节标识、模型、token、费用与状态），不因计费权限获得正文或检索访问。
- 高风险操作（回滚、批量入库、删除成员、改门禁）应双人可见或审批，按工作区策略配置。

### 5.4 租户隔离与检索权限

- 所有数据带工作区标识；查询默认按工作区过滤；跨工作区访问一律拒绝。
- 检索结果必须遵守访问权限：读者不能检索到草稿；作者不能检索到其他作者的私有分支；AI 只能检索授权上下文源。
- 向量检索先过滤工作区/权限，再排序；不得先取全局结果再过滤。
- 导出、备份、日志都按工作区隔离。

### 5.5 协作并发

- **章节租约**：同一章同一时间只有一个人类编辑者；租约有有效期与心跳；主笔可强制收回；AI 作业也要拿租约，不能覆盖正在编辑的章节。
- **草稿分支**：每个作者或提案可有独立分支；分支可对比、评论、选定；未被选中的分支归档，不删除。
- **不做自动正文合并**：同一章冲突用租约避免；跨分支由主笔选择。实时协同编辑作为后续能力，预留操作同步接缝，不在首版实现。
- **审阅流**：作者请求审阅 → 审阅者评论/通过 → 主笔提交；或按策略由作者直接提交。
- **评论锚点**：按章节/版本/段落锚定；版本变更后旧评论标记“已过期”，保留历史。
- **通知**：站内 + 邮件/Webhook；按用户偏好；不伪造进度。

### 5.6 署名与归属

- 每个版本记录：人类作者、AI 主体、模型、上下文包、提示/指令、授权策略。
- AI 辅助不抹掉人类作者；自动入库显示“AI 自动入库（授权人/策略）”。
- 导出/阅读态可显示署名与生成方式；可按工作区策略隐藏模型细节。

## 六、正典与向量存储

### 6.1 选型结论

**推荐：事务型正库 + 向量能力（如 PostgreSQL + pgvector）作为正典主库。** 正典正文、版本、账本、元数据、权限、正文块、嵌入同库；检索是正库能力，不是第二份真相。

- 纯向量库（Milvus、Qdrant 等）不作为唯一正典主库：缺多实体事务、版本/回滚语义、复杂访问控制、与账本/门禁的连接能力；备份恢复也更复杂。
- 若坚持专用向量库：只能做派生索引，正典仍在事务库；这与“正文收进向量库”的字面要求不完全一致，但一致性最好。
- 规模判断：800 章 × 约 3,000–5,000 字 ≈ 240–400 万字；按 500 字块加重叠 ≈ 1 万块；即使保留 10 个版本 ≈ 10 万块。这个量级用正库向量索引足够，不需要独立向量集群。

### 6.2 正典版本

- 每个正典版本不可变：内容、内容哈希、父版本、作者/主体、提交时间、门禁证据/豁免、提交策略、正文块与嵌入的版本引用。
- 章节只有一个“当前正典”指针；历史版本全部保留。
- 修订/回滚都产生新版本；不覆盖、不删除。
- 导入的历史章节标记“迁移导入”，不伪造门禁结论；缺失证据显示“未评估”。

### 6.3 向量与索引

- 正文按章/场景/段落切块；块保留章节、版本、段落锚点、工作区、可见范围。
- 嵌入绑定具体版本；版本变更后旧嵌入标记过期，新嵌入进入队列。
- 索引状态：未索引/排队/就绪/失败/过期；按章可见。
- 提交不被嵌入阻塞：正典提交先完成；嵌入异步生成；检索只使用“就绪”的当前版本；未就绪的章节在检索覆盖度中如实显示，不拿旧版本冒充。
- 索引是可重建投影；重建不影响正典。

### 6.4 检索

- 混合检索：词法 + 向量；可选交叉编码器重排；不逐查询调用大模型重排。
- 结果带：工作区、章节、版本、段落锚点、片段、来源、时间、可见范围。
- 覆盖度不足时，语义通道主动退出并标注；不静默融合。
- 检索权限：先访问控制过滤再排序；草稿/私有分支默认不进入共享索引。
- 引用：从“文件 + 行号”改为“作品/章/版本/段落”；导出时可映射回文件。

### 6.5 文件与导出

- 正典主库是数据库；文件降级为导出/归档格式。
- 作者外部编辑流程：导入文件 → 生成草稿分支 → 差异/门禁 → 提交；不能直接改正典文件。
- 每版可导出 Markdown/纯文本快照；导出是只读副本，不是真相。
- 备份：数据库全量 + 增量 + 导出快照；清单 + 哈希；异地副本；定期恢复演练。

## 七、章节生命周期

### 7.1 状态机

```text
计划中
  ├─ 人类写作 → 写作中 ─┐
  └─ AI 生成 → 生成中 ──┤
                        ▼
                    草稿就绪 → 待校验
                                 ├─ 门禁未过 → 修订 → 待校验
                                 └─ 门禁通过 → 已暂存
                                                   ├─ 人工确认 → 提交中 → 正典
                                                   └─ 自动授权 → 提交中 → 正典
正典 → 修订中 → 待校验 → … → 正典（新版本）
正典 → 回滚请求 → 证据复用/豁免审批 → 提交中 → 正典（新版本）
正典 → 归档
异常态：提交失败待修复、已放弃、待豁免
```

### 7.2 不变量

1. 没有对当前正文哈希有效的门禁结论或豁免，不能提交正典。
2. 目标是显式章节，不从标题推断；提交前再次确认或按策略校验。
3. 正文、账本、元数据、提交事件、审计事件一次成功；否则不报成功。
4. 正典版本不可变；回滚/修订产生新版本。
5. 模型输出不能直接进编辑器或正典；必须经过提案、校验、提交。
6. AI 自动提交必须有有效授权、全门禁通过、无 AI 豁免；否则停在暂存/待审。
7. 同一章同一时间只有一个写租约；提交使用乐观并发校验。
8. 任何豁免必须由非申请人的有权人类批准；AI 不能批准。
9. 索引未就绪不影响正典，但检索必须显示覆盖度，不能用旧版本冒充。

### 7.3 所有正典写入路径

- 人工入库；
- AI 自动入库；
- 回滚；
- 修订；
- 迁移导入；
- 批量补写。

全部走同一条提交链；没有例外。导入也必须生成版本、证据/豁免、审计事件。

## 八、唯一提交链

**准备 → 校验 → 提交 → 发布 → 确认**

### 8.1 准备

- 冻结草稿/目标版本；计算内容哈希；记录目标章、父版本、作者/主体、策略/授权、门禁证据/豁免、账本增量、元数据增量。
- 生成提交意图（幂等 ID）；申请章节租约或确认持有；确认备份可用。

### 8.2 校验

- 门禁证据是否对当前哈希 + 规则版本有效；豁免是否有效且已批准。
- 目标章是否正确；父版本是否仍是当前正典（乐观并发）；是否有并发提交。
- 账本/设定变更是否冲突；权限是否满足；自动化授权是否覆盖本章/本模式/预算。
- 校验失败：不写任何东西；返回明确原因。

### 8.3 提交

- 在同一事务中：写正典版本、更新当前指针、应用账本/元数据变更、写提交事件/审计事件、写嵌入 outbox。
- 任一步失败：全部回滚；章节保持原状态；显示失败原因。
- 幂等：同一提交意图重试不产生重复版本。

### 8.4 发布

- 正文块/嵌入/索引等外部副作用走 outbox；异步执行、可重试。
- 章节在发布完成前显示“提交中”；不能显示“成功”。
- 发布失败：进入“提交失败待修复”；阻止后续提交；提供修复/重试；不静默成功。

### 8.5 确认

- 回读正文哈希、账本、元数据、审计事件；全部一致才标记“正典”。
- 通知相关作者/审阅者；更新投影；记录索引状态。

### 8.6 提交者与归属

- 人类提交：作者/主笔；记录审批人。
- AI 提交：AI 主体 + 授权策略 + 授权人；记录模型、上下文包、门禁证据、花费。
- 回滚：申请人、批准人、豁免单、目标版本、原因。
- 导入：迁移操作者、来源、原始哈希、证据状态。

## 九、门禁、豁免与回滚

### 9.1 门禁

- 五道硬门禁 + 五类审计保持确定性；规则版本化。
- 评估结果不可变，绑定：内容哈希、规则版本、上下文指纹（设定/账本/视角/实体集）。
- 结果状态：通过/未通过/豁免/不适用/错误；“错误”不得当作通过。
- 门禁服务提供**可行性查询**：给定模式、章节、门禁集，回答“能否满足/缺什么/是否结构上不可能”。作业预检用它零调用拒绝。
- 41 章存量：迁移时逐章评估；不能通过的，走定向补实体、人工修订、显式豁免三选一；不得静默标记通过。

### 9.2 豁免

- 一次性、绑定章节 + 目标版本 + 规则 + 原因；不是长期权限。
- 申请人与批准人分离；AI 只能申请，不能批准；Owner/Lead 批准。
- 界面、版本历史、报表永久显示“已豁免”；“已豁免”不等于“已通过”。
- 豁免不覆盖数据一致性、权限、事务失败；只覆盖质量门禁。

### 9.3 回滚

1. 选择目标版本，填写原因；检查权限、租约、并发。
2. 若目标版本有有效门禁证据（哈希 + 规则版本 + 上下文指纹一致），可复用，无需豁免。
3. 否则重新跑门禁；仍不通过则申请豁免；批准后提交。
4. 回滚作为新版本提交；保留被覆盖版本；更新账本/元数据；解决冲突后才能提交。
5. 通知受影响作者；旧评论标记过期但保留；索引异步更新。
6. 审计：申请人、批准人、豁免、目标版本、差异摘要。

### 9.4 自动入库的门禁规则

- 必须全门禁通过；不允许 AI 自动豁免。
- 门禁失败 → 暂存 + 创建人工审阅任务；作业可按策略继续其他章或暂停。
- 门禁错误/不适用 → 视为未通过，不得自动提交。
- 规则版本在作业开始时固定；规则变更不影响已提交版本，但新提交必须使用固定版本或重新评估（按策略）。

## 十、无人值守入库

### 10.1 自动化授权（Mandate）

人类 Owner/Lead 授权，包含：

- **范围**：工作区/作品/卷/章范围/模式/最大章数。
- **质量**：必须通过的门禁、是否允许豁免（建议不允许 AI 豁免）、抽样复核比例、缺陷处理。
- **模型**：允许的模型/供应商、本地或远程、最大 token/费用、单价未知时是否允许。
- **数据**：允许的上下文源；禁止未核验/待设计事实；是否允许远程嵌入。
- **时间**：生效/失效；可随时撤销。
- **责任人**：授权人、AI 主体、通知对象。

### 10.2 AI 主体

- 工作区内的服务账号；固定权限上限：生成、跑门禁、在授权内提交、请求豁免；不能批准豁免、不能改策略、不能管成员/计费。
- 所有动作归属于 AI 主体 + 授权人 + 策略版本；审计可追。
- 授权撤销后：停止新提交；已提交版本不回滚（回滚需人类另行决定）。

### 10.3 执行流程

1. 作业预检：授权有效、目标章存在、无冲突作业、模式可行性、预算、模型可用、备份可用。
2. 逐章：拿租约 → 装配上下文（只用允许来源/已核验事实）→ 生成提案 → 确定性审计/门禁 → 全过则自动提交；失败则暂存/待审。
3. 提交走统一提交链；提交者为 AI；记录策略/授权/模型/上下文/花费。
4. 发布/索引异步；投影显示进度；不伪造进度。
5. 作业结束：逐章结果（已入库/已暂存/门禁失败/结构不可能/无产出/需人工）、成本、复核任务。
6. 事后抽样：按策略复核；发现缺陷 → 人工回滚/修订 + 策略复盘；连续缺陷 → 自动暂停授权（按策略）。

### 10.4 硬规则

- AI 不能给自己授权、不能扩大范围、不能批准豁免、不能改门禁、不能删除审计。
- 自动提交必须全门禁通过；不得用“模型自评”代替门禁。
- 未核验/待设计事实不得进入自动生成的上下文作为既定事实。
- 远程模型/嵌入必须符合工作区数据策略与花费授权；否则只用本地。
- 人工可随时暂停/撤销授权；暂停后作业在检查点停止，不产生半提交。

### 10.5 复核与纠偏

- 抽样比例按风险：新模式/新模型/前 N 章 100%；稳定后降低；按策略配置。
- 复核任务带：章节、版本、门禁证据、上下文包、模型/花费、差异。
- 缺陷分级：事实错误/连续性/风格/结构；严重缺陷触发回滚与授权暂停。
- 每日/每周报告：自动入库数、豁免数（应为 0）、失败原因、成本、复核结果。

## 十一、作业引擎

### 11.1 状态

配置 → 预检 → 等待 → 运行（逐章检查点）→ 暂停/停止 → 完成/失败/中断 → 可恢复 → 已清理。

异常：预检失败、部分完成、需人工。

### 11.2 预检

- 模式合法；无冲突作业；目标章存在；模式可行性（门禁）；预算/授权；模型可用；租约可获得；备份可用；工作区配额。
- 结构上不可能：零调用拒绝，不先花钱。

### 11.3 检查点与幂等

- 每章：上下文已装配、提案已生成、审计/门禁已评、已暂存/已提交、索引已入队。
- 幂等键：作业 + 章节 + 阶段；重试不重复生成/提交。
- 恢复：只重做未完成/失败章；已有结果不重复；人工触发，不自动恢复。

### 11.4 保留

- 真实作业记录不可自动淘汰；干跑记录优先清理；已付费产出先取回再清理；清理需确认；审计保留。
- 作业历史按工作区保留策略；可导出。

### 11.5 并发

- 单工作区默认一个写作作业；按 GPU/模型容量限流；人工编辑优先于 AI 作业；AI 拿不到租约就跳过/排队。
- 多工作区共享模型网关时按配额/优先级调度。

### 11.6 Hermes 的位置

- Hermes 是执行器/提案者，不是状态机。
- 任务信封：任务类型、上下文包、约束、输出契约、授权/预算、相关章节/租约。
- 提案信封：内容、工具轨迹、用量、模型、警告、上下文引用。
- Hermes 的会话、记忆、Kanban 不作为章节/作业/正典真相源；作业状态留在云说作业引擎。

## 十二、模型网关与成本

### 12.1 唯一入口

- 界面、命令行、作业、MCP 工具、审阅/审计全部走网关；禁止直连供应商。
- 网关负责：路由、凭据、健康、限流、重试、故障转移、花费授权、数据策略、用量记账、审计。

### 12.2 花费授权

- 工作区预算 + 用户配额 + 作业/操作授权；远程调用必须有有效授权。
- 授权含：上限、币种、有效期、允许的模型/供应商、用途、授权人。
- 单价未知：显示“未知”，不得估算；按工作区策略决定是否允许未知价调用（建议默认拒绝远程未知价）。
- 本地调用：记录 token/GPU 时间；按工作区策略计入内部成本。

### 12.3 数据策略

- 默认本地模型；远程调用需工作区策略 + 明确同意。
- 嵌入也可能出站：远程嵌入同样受数据策略约束；敏感工作区只用本地嵌入。
- 上下文包记录发送给哪个模型/供应商；审计可追。
- 不把密钥暴露给界面、日志、导出；导入导出零密钥。

### 12.4 路由与可用性

- 五类场景路由：写作、推演、润色、审计、嵌入；可扩展。
- 多密钥轮询/随机/故障转移；限流与并发按供应商/工作区。
- 体检分级：可达 → 鉴权 → 模型列表 → 深度对话；未体检显示“未知”，不当绿灯。
- 模型切换会失效前缀缓存、影响成本；禁止静默切换；切换需记录。

### 12.5 用量与成本

- 每次调用记录：工作区、用户/AI 主体、作业、章节、模型、供应商、token、单价、费用、延迟、上下文包、提案。
- 成本账本真实；价格表可由 Billing Admin 维护；未知价显式。
- 按工作区/用户/作业/章节出报表；支持预算告警与暂停。
- 已实现（M5-B 阶段二）：工作区月度生成预算在每次 `chapter_proposal` 调用前按“已计费用 + 进行中预留”硬闸门，手工与自动生成同时受限；`embedding`/`embedding_query` 不阻断、单独计费。报表按用途、成员、作业、章节归属，多币种分组，未知费用单列且不摊入已知合计。预算与价表由 Owner/Billing 管理，Lead 只读报表。预算仍是估算，不是供应商账单；未知费用、流式中断与崩溃残留预留不保证被上限覆盖。供应商账单对账与发票导入已在 M5-B 阶段四实现（人工导入、逐模型估算对照、复核/争议），账单金额与本地估算分开且不回写预算；作者配额、自动分账与账单提醒未实现。

## 十三、上下文、检索与视角

### 13.1 上下文包

- 一等产物：段落（设定/角色/伏笔/结构/知识库/前章结尾/风格）、来源、版本、token 预算、实际使用、丢弃项及原因。
- 只从授权源读取；不读界面状态/旧快照。
- 与提案/模型调用/提交关联；可复现。
- 超预算时明确丢弃并标记；不静默截断。

### 13.2 事实验证态

- 已核验/未核验/待设计/已废弃。
- 128 条死律属“待设计”：不得水合为既定事实；只能作为“待设计”提示或排除。
- 上下文包只把“已核验”当约束；未核验需显式标注并受限使用；待设计不得进入自动生成。
- 设定变更走草案 → 差异 → 校验 → 应用 → 撤销；写入前备份、写入后回读。

### 13.3 视角

- 视角是设定属性，按作品/卷/单元/章解析；不是全局常量。
- 上下文包记录生效视角；门禁检查正文与视角一致性；冲突时提示/阻断。
- 混合视角必须显式声明范围，不能靠默认。

### 13.4 检索

- 词法 + 向量混合；可选交叉编码器重排；结果带来源/版本/段落锚点/可见范围。
- 语义覆盖不足主动退出并标注；索引过期显示。
- 检索遵守访问控制；草稿/私有分支不进入共享索引。
- 增量更新；重建可恢复；索引不是真相。

## 十四、事件、审计与观察

### 14.1 事件日志 + 投影

- 轻量 CQRS：命令进、事件出、视图读投影；不做完整事件溯源。
- 事件：章节计划/草稿/门禁/暂存/提交/回滚、账本/设定变更、作业状态、模型调用、授权/豁免、成员/权限、备份。
- 投影：章节生命周期、作业状态、成本、覆盖率、健康、待办/审阅。
- 投影可重建；不得作为写入依据。

### 14.2 审计

- 每条审计：工作区、主体（人类/AI）、角色、动作、对象、时间、来源（会话/IP）、关联事件、策略/授权、结果。
- 高严重度：正典提交/回滚/豁免、授权变更、成员/权限、密钥、预算、删除/清理、导出。
- 审计只追加；按工作区保留；导出受权限控制。

### 14.3 数据来源包

- 每个展示数字：值 + 来源 + 截至时间 + 新鲜度 + 验证态；缺失显示“未接入”。
- 不回落旧快照；不把演示数据混入真实指标。
- 模拟集群/拓扑：删除，或独立“演示模式” + 强制横幅；生产视图不可读演示数据。

### 14.4 错误模型

- 统一分类：校验/权限/冲突/不可用/预算/门禁/事务/内部。
- 每个错误带原因、影响、可采取的下一步、来源；界面一致呈现。
- 长任务进度来自事件，不伪造。

### 14.5 验收与运维

- 健康、单元/集成/端到端、文档一致性、静态闸门、备份、工作区边界、指纹/新鲜度。
- 持续集成必须覆盖提交链、权限、租户隔离、向量访问控制、自动入库护栏、回滚豁免。
- 文档数字带来源；基线对账可机械核验。

## 十五、安全、部署与运维

### 15.1 身份

- Studio：本地账号 + OIDC/SSO；会话、MFA（可选/按策略）、登录审计。
- Solo：本地账号；可无 OIDC。
- 成员邀请/停用；离职转移；API/服务账号（AI 主体）独立管理。

### 15.2 隔离与加密

- 工作区级数据隔离；数据库行级安全；对象存储前缀隔离；备份隔离。
- 传输 TLS；静态加密；密钥管理；日志脱敏。
- 供应商凭据工作区级；不返回界面；导出零密钥；导入保留本机密钥。

### 15.3 工具与沙箱

- MCP/技能/命令在沙箱执行；白名单；网络出口限制；资源/时间限额；变更类工具需确认。
- AI 主体只能调用授权工具；工具输出是提案/证据，不是正典。

### 15.4 备份与恢复

- 数据库全量 + 增量、导出快照、清单 + 哈希；异地/异盘；保留策略；定期恢复演练。
- 恢复后校验章节数、版本链、账本、索引可重建；RPO/RTO 按工作区策略。

### 15.5 部署

- Solo：单机；本地数据库；本地模型；可选远程。
- Studio：应用服务器 + 数据库 + 对象存储 + 模型网关 + 工作进程；可局域网/私有云；按工作区扩容。
- 多用户并发高时，模型层用 vLLM/SGLang 等批处理引擎；低并发可用 llama.cpp；网关屏蔽差异。

## 十六、迁移与切换

### 16.1 原则

- 先对账、后迁移；不做双写；按流程切换；旧系统只读保留；可回退。
- 不伪造门禁结论；缺失证据显示“未评估”。
- 迁移导入也走提交链（或专用导入通道，等价审计/版本）。

### 16.2 步骤

0. **基线对账**：203 章、8 卷、13 单元、24 实体、9 条账本、128 条待设计、31 技能；文件/元数据/索引/看板数字逐项比对；出差异报告；冻结写入。
1. **工作区与身份**：创建首个工作区、Owner、角色；后续邀请作者。
2. **正典导入**：203 章作为版本导入；内容哈希、作者/时间、来源；旧门禁证据若存在则导入，否则“未评估”；不伪造。
3. **设定/账本导入**：版本化；待设计事实保持待设计；不水合；对账数量。
4. **向量索引**：切块/嵌入当前正典；词法 + 向量；覆盖率报告；按章索引状态。
5. **模型网关**：迁移供应商/模型/密钥；所有调用改走网关；封直连；设置预算/授权。
6. **作业迁移**：历史作业只读导入；新作业用新引擎；保留规则生效。
7. **界面切换**：投影、角色、来源包、错误模型；移除旧快照/演示数据；按角色暴露入口。
8. **门禁迁移**：规则版本化；41 章逐章评估；定向补实体/人工修订/豁免三选一；可见。
9. **自动化试点**：小范围、本地、100% 复核；跑稳后扩大；AI 不得豁免。
10. **多作者试点**：邀请第二作者；租约/分支/审阅/审计；再扩。
11. **验收与演练**：提交链、权限、租户隔离、向量访问控制、自动入库、回滚豁免、备份恢复、文档一致性。

### 16.3 旧数据处理

- 正典文件保留为只读归档；数据库成为真相；导出可生成文件。
- 旧缓存/旧快照/演示指标不迁移；从投影重建。
- 旧作业历史只读；已付费产出保留；干跑可清理。
- 旧门禁结论如无证据，不当作通过；按迁移策略重评或豁免。

## 十七、验收标准与缺口映射

### 17.1 四项决策的验收

| 决策 | 必须证明 |
| :--- | :--- |
| 正典入向量库 | 正典版本/正文/向量同库；提交事务；版本不可变；索引可重建；检索访问控制；备份恢复 |
| 无人值守入库 | 每次自动提交有授权/门禁/主体/审计；AI 无豁免权；失败即暂存；可撤销；抽样复核 |
| 回滚显式豁免 | 回滚走提交链；豁免申请人≠批准人；新版本；界面显示豁免；审计完整 |
| 多用户作者 | 角色/权限矩阵生效；租户隔离；章节租约；分支/审阅；成本归属；离职/停用 |

### 17.2 十三条端到端流程的落点

| 流程（基线第 4 节） | 架构落点 | 四项决策下的关键规则 |
| :--- | :--- | :--- |
| 1 人工创作一章 | 章节生命周期 + 提交链（§7–8） | 保留逐次确认；正典与向量同库；租约防并发覆盖 |
| 2 AI 辅助创作一章 | 提案面 + 上下文包 + 模型网关（§10、§12–13） | AI 产出仍是提案；远程模型/嵌入受数据与花费授权；润色只返回不落盘 |
| 3 自动写作一批章节 | 作业引擎 + 自动化授权（§10–11） | 授权范围内可无人值守入库；全门禁通过；失败即暂存；结构不可能零调用拒绝 |
| 4 作业中断与恢复 | 作业状态机 + 检查点（§11） | 恢复必须人工触发；只重做缺失章；不自动续跑 |
| 5 世界观变更 | 设定/账本域 + 版本化变更（§4、§13.2） | 草案→差异→校验→应用→撤销；待设计不水合；写前备份、写后回读 |
| 6 伏笔闭环 | 账本域 + 上下文提示（§4、§13.1） | 账本版本化；冲突要求重读；目标章提示；章节相关的账本变更随正典提交同事务 |
| 7 章节修订与回滚 | 提交链 + 豁免（§8–9） | 修订/回滚同一条提交链；证据可复用，否则显式豁免；只产生新版本 |
| 8 模型接入与体检 | 模型网关（§12） | 唯一入口；未知价显式；体检分级；禁止静默切换 |
| 9 知识库建设与检索 | 正典与向量域（§6） | 正文/版本/向量同库；嵌入异步且版本绑定；访问控制先过滤；覆盖不足主动退出 |
| 10 工具调用 | 提案面 + 沙箱（§3.3、§15.3） | 白名单、出口限制、变更确认；工具输出只是提案/证据 |
| 11 分享、导出与发布 | 阅读与导出域（§6.5） | 导出是只读副本；不接第三方平台；阅读态按权限与署名策略 |
| 12 系统验收 | 观察面 + 验收（§14.5、§17） | 每次变更覆盖提交链/权限/隔离/自动入库/回滚；写作探针零计费 |
| 13 备份与恢复 | 备份域（§15.4） | 全量+增量+快照+哈希；异地副本；按工作区隔离；定期恢复演练 |

四条主循环对应：章节生产（流程 1–4、7）、设定与账本（流程 5–6）、模型与成本（流程 8）、质量与运维（流程 12–13）；检索（流程 9）、工具（流程 10）、阅读发布（流程 11）为支撑。

## 十八、风险与待确认

1. **向量库形态**：推荐正库 + pgvector；若必须专用向量库，需接受派生索引/最终一致。
2. **协同深度**：首版章节租约/分支，不做实时共写；是否接受？
3. **部署**：Studio 是局域网还是私有云？影响认证、备份、数据合规。
4. **认证**：本地账号 + OIDC 接缝，还是首版就 SSO？
5. **AI 自动入库范围**：哪些卷/模式/章节允许？建议从小范围、100% 复核开始。
6. **豁免审批人**：Owner/Lead；是否需要双人审批？建议高风险双人。
7. **远程模型/嵌入**：哪些工作区允许出站？默认本地。
8. **成本归属**：已定工作区统一月度预算（M5-B 阶段二）；按作者配额未实现，是否需要在目标架构中保留？
9. **回滚证据复用**：上下文指纹规则是否接受？
10. **41 章迁移策略**：定向补、人工修订、豁免的比例，需要作者定。

## 十九、一句话结论

**多用户不是加登录，无人值守不是去掉确认，向量化不是换一个数据库；它们的共同前提是：正典只有一个提交者、质量只有一个证据链、AI 只有被授予的提案权与提交权。**
