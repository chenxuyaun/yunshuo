# ADR-0004：L5 第一个用例选哪个

- **状态**：待拍板（Proposed）— **且与一条已拒收结论冲突，冲突未解不得开工**
- **来源**：分层设计 D4
- **阻塞**：L5
- **建议**：伏笔回收建议

## 背景

L5 的任务是"把第一个真实用例搬到循环上 + 规模对比"：同一个 prompt，单发跑一遍、循环跑一遍，看循环是否真的更好。选哪个用例决定这次对拍有没有说服力——如果用例的证据路径本来就是确定的，循环赢不了，这个负结果虽然合法但学不到东西。

## 选项

**(a) 伏笔回收建议。**

**(b) 门禁改稿定位。**

**(c) 章纲正文生成。**

## 建议与理由

**(a)**。三条理由：

1. **现有实现最弱**——伏笔回收是目前最依赖"人肉翻前文"的环节，改进空间最大。
2. **跨章证据最需要工具**——它天然要读多章正文与账本，正是工具循环的用武之地；换成单章内任务，循环与单发的差距会被任务本身的上限压平。
3. **写入面已被门框住**——M6-7 已经把它约束成"只写草稿"，即循环即便跑歪也进不了正典。

## 必须先解决的冲突

`docs/云说-M6覆盖分析结论汇总-2026-10-26.md:145` 的结论是 **"AI 建议质量评估 | 无评估集 | 不建评估集（原 §15.3 建议①不再排期）"**。而 L5 的"单发 vs 循环规模对比"**本质上就是一次质量评估**。

这个冲突不能靠"顺带恢复评估集"解决——同文档 `:124` 的规矩是"重启任一拒收项必须先重新决策，不能以'补一条测试'名义顺带恢复"。分层设计给出的口径区分是：

- **运行路径黄金集**（L2b/L5 的验收物）：固定输入 + 固定断言，验证"循环的路径与终止是否如设计所愿"，**不评文字质量**。
- **提示标定评估集**（已拒收）：用标注数据调提示与 token 系数，**不做**。

**拍 ADR-0004 时必须同时确认这个区分成立**，否则 L5 是在偷偷恢复一个已拒收项。详见威胁模型 §5.6。

## 回退

若循环质量不优于单发——**这是合法结论**，写进 README 的诚实边界，然后停在这里。前四层（可程序化调用的边界 + 轨迹 + 能力元数据）仍有独立价值。
