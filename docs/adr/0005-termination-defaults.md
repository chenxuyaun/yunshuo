# ADR-0005：终止默认值定多少

- **状态**：待拍板（Proposed）
- **来源**：分层设计 D5
- **阻塞**：L2b
- **建议**：保守 3 步起步

## 背景

L2b 的循环需要三重终止（分层设计 §二 L2b）：步数上限、单 run 成本上限、墙钟上限。三个数都得有个默认值，而这个默认值直接决定"注入驱动多次工具调用"能造成多大损失——它是威胁模型 §2.3 里"由程序锁死、模型无权改"的其中一项。

## 需要定的三个数

| 项 | 含义 | 建议 |
| --- | --- | --- |
| `max_steps` | 单 run 最多几步 | **3 步起步** |
| 单 run 成本上限 | 这一次 run 最多花多少 | 沿用已有预算闸门（见下） |
| 墙钟上限 | 这一次 run 最多跑多久 | 未标定，须如实标注 |

## 建议与理由

**`max_steps` 取 3。** 理由：这是**最保守的可用值**——足够完成"检索 → 再检索 → 生成"这种最小证据链，又不给注入留出长链条的空间。跑完 L5 有真实调用分布数据再谈调高。

成本上限**不新定一个数**：已有闸门（`budgetMaxTokens` 与 `reserveGenerationCall`）在每次调用前都过一遍预算，循环里每步都过即可，不需要另造一套。重复造一套就是第二个真相源。

墙钟上限**如实标"未标定"**。

## 一条硬规矩

分层设计原话：**"阈值要么可推导要么如实标'未标定'，不许拍脑袋当能力。"**

这条比数值本身重要。3 步是**保守起点**，不是"我们测出模型需要 3 步"——如果把它写成后者，就等于伪造了一个不存在的标定结论。界面与 README 上必须能看出哪个数是推导的、哪个是暂定的。

## 回退

`max_steps` 是 run 上的字段，调它不需要改代码。若 L5 发现 3 步普遍不够（大量 run 撞上限而非自然结束），先看**是不是工具面太窄**（该补 L1b 了），再考虑调数值——撞上限率高说明工具不够用，不一定是步数太少。
