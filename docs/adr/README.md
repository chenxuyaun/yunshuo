# ADR 目录 — 模型侧基座决策记录

这里记录**模型侧基座（L0–L7）**的架构决策。每条 ADR 一个文件，编号不回收、不重排。

## 状态口径

| 状态 | 含义 | 能不能开工 |
| --- | --- | --- |
| **待拍板（Proposed）** | 已列出选项与建议，但**没有人拍过板** | **不能** |
| 已接受（Accepted） | 已拍板，按此实施 | 能 |
| 已否决（Rejected） | 已拍板不做 | 不能 |
| 被取代（Superseded by ADR-xxxx） | 后来改了主意 | 看取代它的那条 |

**当前 11 条全部是「待拍板」。** 这不是格式问题——[分层设计](../云说-模型侧基座分层设计-2026-10-26.md) §四标题原文就是"需要你拍板的决策点"，里面的"倾向"是**建议**，不是决定。把建议写成决定等于伪造决策，所以这里一条都不标 Accepted。

## 与其它文档的关系

- **分层设计**（`../云说-模型侧基座分层设计-2026-10-26.md`）是这些 ADR 的来源，也保留逐层设计与回退表。ADR 只记"选哪个"，不重复"为什么盖这层"。
- **威胁模型**（`../云说-模型侧基座威胁模型-2026-10-26.md`）是这些 ADR 的**验收条件来源**：里面列的常驻规则违反即不得合并，与本目录的决策无关。
- **基座研究**（`../云说-模型侧基座研究-2026-10-26.md`）是权威口径与实测数字的来源。
- **覆盖分析结论**（`../云说-M6覆盖分析结论汇总-2026-10-26.md`）是已拒收能力的清单。ADR-0004 与它 `:145` 的"不建评估集"存在冲突，冲突未解前 L5 不得开工（见威胁模型 §5.6）。

## 一个 PR 一件事

`AGENTS.md` 第 13 条要求一个 PR 聚焦一件事。所以这些 ADR **可以逐条转 Accepted**，不必等 11 条一起拍——但 ADR-0007 必须先拍，否则 L0 不得开工。
