# 云说 · 技术选型与主流程实施（M1–M5-B 阶段四 + Studio 交付）

> 状态：本文是 M1 动工前的选型与实施设计；单章主流程已按本栈落地，实际结构、命令与验收结果见根目录 README。
> 目标：先跑通一条最小但真实的主流程，证明“章节生命周期 + 确定性门禁 + 唯一提交链 + 版本/审计”，不先铺 12 个工位，也不先做无人值守批处理。

## 一、选型结论

| 层 | 选择 | 理由 | 备选/何时换 |
| :--- | :--- | :--- | :--- |
| 语言/运行时 | TypeScript + Node 24 | 业务是工作流、CRUD、UI；前后端共享类型；AI 调用都是 HTTP | Python 后端只适合已有代码或重 NLP；Hermes 作为独立执行器接入 |
| 仓库 | pnpm workspaces | 模块化单体，领域/门禁/数据库/契约分包；不需要先上微服务 | Turborepo 在构建变慢后再加 |
| API | Fastify 5 + Zod | 轻、schema 驱动、插件生态足够；适合命令式接口 | OpenAPI 在需要外部 Agent 接入时补；NestJS 更重；tRPC 不利外部工具/Agent 调用 |
| 数据库 | PostgreSQL 17 + pgvector | 正典、版本、账本、权限、向量同库；事务、行级安全、备份成熟 | 纯向量库只能做派生索引；SQLite 不适合多用户/事务/向量同库 |
| ORM/迁移 | Drizzle ORM + SQL 迁移 | SQL 优先，事务可控，pgvector 类型与索引好接；迁移可审阅 | Prisma 对 pgvector/复杂 SQL 更绕 |
| 异步 | Postgres outbox + 轮询 worker | 少一个 Redis；提交与索引解耦；可重试 | pg-boss 在作业量上来后替换轮询 |
| 前端 | React 19 + Vite + TanStack Query + 原生 CSS | 本地 Web 应用，不需要 SSR；写作台用暖纸/墨色排版，不引入组件库 | Next.js 只有做公网/SEO 才需要；组件库在工位增多后再评估 |
| 编辑器 | textarea v0 → CodeMirror 6 | 先验证流程，不先解决富文本/协同 | 实时共写明确推迟 |
| 认证 | 会话 Cookie + 本地密码 + 单 IdP OIDC（PKCE） | 先保留身份接缝；M5 已补密码账号与 SSO，不引入外部身份 SaaS | MFA/SCIM/多 IdP 仍未实现，Studio 单机交付不做企业身份治理 |
| 模型 | 自建模型网关，转发 OpenAI 兼容端点 | 本地 llama.cpp/Ollama/vLLM 与远程 API 同一入口；可记账、可限流 | Hermes 作为作业执行器，不持有正典状态 |
| 测试 | Vitest + API 冒烟脚本 + 浏览器验收 | 领域/门禁/视图映射用单元测试；提交链用真实 Postgres 跑 `scripts/smoke.mjs`；UI 用浏览器人工验收 | 接入 Playwright 做 UI 回归、测试容器进 CI |
| 部署 | Docker Compose（开发/Studio）；Solo 后续打包 | 本机已有 Docker；先保证一键起 Postgres | 桌面安装器后置 |

**一句话**：TypeScript 模块化单体 + PostgreSQL/pgvector + React；先做单章闭环，不先做分布式。

## 二、主流程 M1 的范围

M1 不是“把 12 个工位都做出来”，而是把一条真实的主流程跑通：

```text
打开章节 → 拿租约 → 编辑/保存草稿 → 跑门禁 → 暂存
        → 二次确认提交 → 唯一提交链 → 正典版本
        → 版本历史/审计 → 索引 outbox（异步，可降级为未配置）
```

### 2.1 做

- 一个工作区、一个作品、卷/章节结构。
- 章节租约：同一章同一时间只有一个编辑者；过期可收回。
- 草稿分支与草稿修订；空草稿拒绝；手动保存（Ctrl/Cmd+S）。M1 不做自动保存，避免正文在门禁评估后静默漂移。
- 五道门禁的**框架**与版本化规则集；`dev-v0` 规则集用于跑通流程。
- 五类审计的展示；确定性的先做，未接入的如实显示“未接入”。
- 暂存：冻结草稿快照，绑定门禁证据。
- 唯一提交链：准备 → 校验 → 提交 → 发布 → 确认。
- 正典版本不可变；当前指针；版本历史。
- 审计日志与事件；来源标注。
- 索引 outbox：提交后异步处理；没有嵌入服务时索引显示“未配置”，检索只跑词法，不阻塞正典。
- 旧章导入：作为版本导入，缺失门禁证据显示“未评估”。

### 2.2 不做（后续里程碑）

- 批量自动写作、无人值守入库（M4）。
- 真实五门禁生产规则（需从现有系统迁移/作者确认）。
- 完整多用户邀请、OIDC、计费归属（M5）：本地密码账号、一次性邀请、成员角色与工作区切换已在 M5-A 实现；邀请邮件、密码修改与一次性重置已在 M5-B 阶段一实现；费用归属报表、工作区月度预算与计费管理员已在 M5-B 阶段二实现；单 IdP OIDC/SSO 已在 M5-B 阶段三实现；供应商账单对账与发票导入已在 M5-B 阶段四实现；Studio 单机部署与旧章导入已在交付收尾实现（见第二十节）。
- 实时协同编辑；首版用章节租约与草稿分支。
- 全量 12 工位、3D 星图、分镜/视频画布。
- 正典检索之外的设定集/角色/伏笔台账（M4-A 只做正典片段）。
- 第三方发布。

## 三、主流程时序

```text
作者            Web                 API                       数据库
 │ 打开第 2 章   │                   │                          │
 │──────────────>│ GET 章节+租约      │                          │
 │               │──────────────────>│ 获取/续租                 │
 │               │                   │─────────────────────────>│ chapter_leases
 │ 编辑/保存     │                   │                          │
 │──────────────>│ PUT 草稿           │                          │
 │               │──────────────────>│ 空稿拒绝；哈希/字数        │
 │               │                   │─────────────────────────>│ draft_revisions
 │ 跑门禁        │                   │                          │
 │──────────────>│ POST 评估          │                          │
 │               │──────────────────>│ 五门禁 dev-v0             │
 │               │                   │─────────────────────────>│ gate_evaluations
 │ 暂存          │                   │                          │
 │──────────────>│ POST 暂存          │                          │
 │               │──────────────────>│ 校验哈希+全门禁通过        │
 │               │                   │─────────────────────────>│ staged_drafts
 │ 提交正典      │                   │                          │
 │──────────────>│ 二次确认目标章     │                          │
 │               │──────────────────>│ 唯一提交链（单事务）       │
 │               │                   │─────────────────────────>│ 版本+指针+元数据
 │               │                   │                          │ +事件+审计+outbox
 │               │<──────────────────│ 版本号/提交结果            │
 │               │ 轮询索引状态       │                          │
 │               │──────────────────>│ index_status             │
 │               │                   │<─────────────────────────│ outbox worker
```

失败路径：

- 门禁未过：章节保持写作中，返回逐条原因；不能暂存。
- 内容在评估后变更：暂存/提交拒绝，要求重新评估。
- 并发编辑：第二个租约请求得到明确占用者与过期时间。
- 提交事务任一步失败：全部回滚，章节保持可重试；绝不报成功。
- 索引失败/未配置：正典仍是正典，索引状态如实显示。

## 四、最小数据模型

M1 核心表如下；向量块与嵌入表在 M4-A 增加。

| 域 | 表 | 作用 |
| :--- | :--- | :--- |
| 身份 | `users`、`workspaces`、`memberships`、`sessions` | 开发登录、工作区、角色 |
| 结构 | `works`、`volumes`、`chapters` | 作品/卷/章；章节含状态与当前指针 |
| 生产 | `chapter_leases`、`draft_branches`、`draft_revisions`、`staged_drafts` | 租约、草稿、冻结快照 |
| 正典 | `canon_versions`、`canon_current` | 不可变版本与当前版本 |
| 质量 | `gate_rulesets`、`gate_evaluations`、`waivers` | 规则版本、证据、豁免 |
| 提交 | `commit_intents`、`commits`、`events`、`audit_log`、`outbox` | 幂等、提交记录、事件/审计、异步 |
| 观测 | `index_status`、`chapter_metadata` | 索引状态、章节元数据 |
| 模型 | `model_providers`、`model_calls` | M3 用；M1 可空表 |
| 检索 | `canon_chunks`、`chunk_embeddings` | M4-A：版本绑定的正典块、词法文本与向量 |

关键约束：

- `canon_versions` 不可变；`version_no` 按章递增；只追加。
- `canon_current` 每章一行；提交时在同一事务更新。
- `gate_evaluations` 绑定 `content_hash + ruleset_id + context_hash`。
- `commit_intents.idempotency_key` 唯一；重试不产生重复版本。
- `events`、`audit_log` 只追加；审计带主体、角色、动作、对象、结果。

## 五、门禁 v0 的诚实边界

**生产五门禁的规则和阈值不在基线文档里，不能凭空编。** M1 的做法是：

1. 门禁接口按五道固定：字数、AI 腔调、核心实体连续性、章末悬念钩子、底层因果律。
2. 提供版本化规则集 `dev-v0`，规则是确定性的、可测的，但明确标注“开发规则，非生产”。
3. 规则集、阈值、上下文指纹都写入证据；改了任何一项，旧证据失效。
4. 门禁状态：通过 / 未通过 / 豁免 / 不适用 / 错误 / 未配置；“错误”和“未配置”都不算通过。
5. 未配置或未实现的门禁会阻止提交，除非有人类豁免；不能用“模型自评”代替。

`dev-v0` 的演示规则（仅用于跑通流程）：

| 门禁 | dev-v0 规则 | 生产迁移 |
| :--- | :--- | :--- |
| 字数 | 可配置下限；演示种子用 300 字，界面标注“演示阈值” | 作者确认真实门槛后写入新规则集 |
| AI 腔调 | 违禁短语表 + 句长分布；命中即失败 | 迁移现有检测规则/阈值 |
| 核心实体 | 章节计划中的必现实体必须在正文出现 | 接 24 实体与逐章计划 |
| 章末钩子 | 最后 200 字包含钩子标记或疑问/转折 | 迁移现有钩子规则 |
| 因果律 | 计划的“目标关键词/阻力关键词”必须出现 | 迁移现有因果规则 |

**原则**：演示种子、`dev-v0`、未接入的审计，都在界面上带标签；不把演示结果说成生产质量。

## 六、命令、状态与提交链

### 6.1 命令

| 命令 | 作用 | 关键校验 |
| :--- | :--- | :--- |
| `chapter.open` | 打开章节 | 工作区/权限 |
| `lease.acquire` / `lease.release` | 拿/放章节租约 | 未过期、同用户可续 |
| `draft.save` | 保存草稿修订 | 持租约、非空、哈希/字数 |
| `gates.evaluate` | 评估当前草稿 | 规则集版本、上下文指纹 |
| `audits.run` | 跑五类审计 | 只提示，不改正文 |
| `draft.stage` | 冻结快照 | 持租约、证据匹配当前哈希、全门禁通过 |
| `canon.commit` | 提交正典 | 幂等键、目标章、期望当前版本、证据有效 |
| `canon.rollback` | 回滚 | 目标版本、权限、证据复用或豁免、新版本 |
| `version.list` | 版本历史 | 只读、权限 |

### 6.2 章节状态（M1 最小集）

```text
planned → writing → staged → canon
              ↑         │
              └─────────┘（退回编辑）
staged → commit_failed → staged（重试）
canon → revision → writing
canon → archived
```

门禁失败不是章节状态，而是 `gate_evaluations.status = failed`；章节仍在 `writing`。

### 6.3 提交链

1. **准备**：取暂存快照、目标章、期望当前版本、门禁证据、幂等键；校验租约。
2. **校验**：证据哈希/规则版本/上下文指纹一致；全门禁通过或人类豁免；目标章显式确认；当前版本未被并发修改。
3. **提交**：单事务写版本、当前指针、章节状态、元数据、提交记录、事件、审计、索引 outbox；任一步失败全部回滚。
4. **发布**：outbox worker 处理索引；正典不等待索引；索引状态可查。
5. **确认**：回读版本哈希/指针/元数据；一致才报告正典；否则进入可重试的失败态并留审计。

**幂等**：同一 `idempotency_key` 已提交则返回原版本；失败可用同一键重试。**并发**：提交锁章节行，校验 `expectedCurrentVersionId`，不匹配返回 409。

## 七、代码结构

```text
apps/
  api/                 Fastify：命令、查询、会话、事务编排
  web/                 React + Vite：章节列表、写作台、门禁/审计、版本
  worker/              outbox 轮询：索引状态
packages/
  contracts/           Zod 契约与共享类型
  domain/              章节状态机、哈希、字数、领域错误（无框架依赖）
  gates/               规则集与五门禁评估器
  db/                  Drizzle schema、SQL 迁移、种子
docker-compose.yml     PostgreSQL 17 + pgvector
```

依赖方向：`domain` 不依赖框架/数据库；`gates` 只依赖 `domain`；`api`/`worker` 组合；`web` 只依赖 `contracts`。提交链的事务编排放 `apps/api/src/services`，不塞进路由。

## 九、M1 验收用例

1. 打开计划章 → 拿租约 → 保存非空草稿 → 门禁失败 → 不能暂存；修正后通过 → 可暂存。
2. 两个用户同时拿同一章租约：第二个收到占用者与过期时间；过期后可接管。
3. 评估后修改正文：暂存/提交拒绝，要求重新评估（哈希不匹配）。
4. 提交时模拟元数据写入失败：版本、指针、事件全不落；章节仍可重试；不报成功。
5. 用同一幂等键重复提交：只产生一个版本。
6. 并发提交/过期当前版本：409，不覆盖。
7. 导入旧章：来源“导入”，门禁“未评估”，不能被当作已通过。
8. 没有嵌入服务：正典提交成功，索引显示“未配置”，检索只跑词法并说明原因，不冒充混合检索就绪。
9. 审计日志能回答：谁、什么角色、在哪个工作区、对哪一章、做了什么、结果如何。
10. 界面所有数字带来源/时间；缺失显示“未接入”。
11. 未配置服务商时生成返回 `NO_MODEL_PROVIDER`，不返回假正文。
12. 生成中停止或断网：提案与模型调用都落失败/中止记录；编辑器内容不变。
13. 采用 AI 提案后：只标记未保存；未过门禁不能暂存；门禁失败时界面不再提示“可以暂存”。

## 十一、模型服务商登记、路由与计价（M3）

范围是“登记 + 模型列表拉取 + 连接测试 + 路由顺序 + 价表”；生成调用复用同一份服务商配置，见第十二节。

- 数据：`model_providers` 保存名称、基础地址、模型 ID、用途（`chat`/`embedding`）、启用状态、加密密钥、优先级（1–999）、价表与币种（CNY/USD），以及最近一次测试结果；`model_calls` 由每次生成/嵌入尝试写入。
- 用途：`chat` 与 `embedding` 分离，创建后不可修改；生成路由只取 `chat`，嵌入路由只取 `embedding`。同一端点可建两行；嵌入行可用 `reuseKeyFromProviderId` 复制密钥密文，不经过明文。
- 价表：`chat` 输入/输出价必须成对；`embedding` 只允许输入价，输出价必须为空。成本只在有价表且有 token 用量时计算，否则为未知。
- 权限：`owner` 新增/修改/删除/测试/拉取模型/嵌入探测；`lead` 查看/测试/拉取模型；其余角色 403，页头不显示入口。M5-B 阶段二起，`billing` 可通过计费接口维护价表（仅价格与币种），不能修改端点、模型、启用状态或密钥，见第十七节。
- 密钥：AES-256-GCM + HKDF 派生；密文格式 `v1.<iv>.<tag>.<ciphertext>`；接口只返回 `hasKey` 与尾号。首选 `MODEL_KEY_SECRET`；开发环境未设置时回退 `SESSION_SECRET` 并在界面提示；生产环境缺失或与 `SESSION_SECRET` 相同时 API/worker 拒绝启动。
- 模型列表：`POST /api/model-providers/discover-models` 请求 `GET {baseUrl}/models`，8 秒超时，`redirect: 'error'`，最多返回 200 个去重模型 ID。新增时可带刚输入的 API Key；编辑时未输入新 Key 且未显式清除时，通过 `providerId` 复用已保存的加密密钥。错误响应若回显密钥会被遮蔽。2026-10-23 起这些口径由 `apps/api/src/m4-retrieval.test.ts` 的三个用例钉住（响应形状五种提示、200 上限截断、密钥遮蔽、`ECONNREFUSED` 原因码、**8 秒超时收口**、owner/lead 权限、跨区 404、坏密文 400 `PROVIDER_KEY_UNREADABLE`、拉取不落库不写审计）；脱敏阈值与错误摘要优先级另有 `apps/api/src/m3-runtime.test.ts` 的两个纯函数用例。**仍未自动覆盖**：连接测试（`POST /api/model-providers/test`）自己那条超时分支——它复用同一个 `requestModelList` 与同一个 8 秒 `AbortSignal.timeout`，但有自己的文案，本轮只钉住了发现侧。
- 连接测试：同样请求 `GET {baseUrl}/models`，8 秒超时；不发送正文、不消耗生成额度。成功时报告模型数量并检查配置的模型是否在列表中。
- 嵌入探测：`POST /api/model-providers/probe-embedding` 只对所有者开放；发送固定短文本“云说嵌入连通性探测。”到 `{baseUrl}/embeddings`，10 秒超时、不重试、不创建或修改服务商。返回是否支持、维度、延迟与用量；只写审计，不含探测文本与密钥。
- 远程出站：嵌入服务商会把正典片段发送到外部端点；表单与检索面板均提示这一点。检索查询只发送计划关键词与作者补充要求，不发送草稿。
- 表单：模型 ID 输入框旁提供“拉取模型列表”，结果以可点选标签展示；基础地址、密钥或清除密钥变化后旧列表失效，避免点选到与当前端点不符的模型。优先级与输入/输出价同表单维护，价格两项必须同时填写或同时留空。
- 证据失效：基础地址、模型或密钥变化时清空旧测试结果；仅改名称、启用状态、优先级或价表不清空。删除被 `model_calls` 引用的服务商返回 409。
- 审计：`model_provider.create / update / delete / test`，metadata 只含名称、端点、模型、优先级、价表、是否保存密钥与测试结果，不含密钥与密文。
- 前端：页头入口 + 模态框；列表展示端点、模型、启用状态、优先级、价表/未知、密钥尾号与最近测试；新增/编辑表单支持留空保留密钥与显式清除密钥；删除使用行内二次确认。
- 路由：生成时按 `priority ASC, created_at ASC` 加载最多 3 个已启用服务商；密钥无法解密的服务商跳过并在提案上下文快照中记录，不尝试调用。

仍待决定：密钥轮换与重新录入流程、流式途中预算硬中断、流式 token 计费。调用前的预算门禁与费用归属报表已在 M5-B 阶段二实现，见第十七节；供应商账单对账已在 M5-B 阶段四实现，见第十九节。

## 十二、M3 AI 提案与运行时

目标是让 AI 只产出可审阅的提案，不绕过人工写作链；生成失败可恢复、可解释，成本不猜造。

数据：

- `ai_proposals`：工作区、章节、服务商快照（id/名称/模型）、模式（`continue`/`expand`）、补充要求、目标字数、基准草稿哈希、上下文包、正文与哈希、字数、状态（`generating`/`ready`/`failed`）、失败码/消息、token 用量、尝试次数、成本与币种、延迟、创建人。
- `ai_generation_locks`：章节主键、工作区、持锁用户、当前提案、取得时间、过期时间。跨用户与跨进程互斥，默认 5 分钟 TTL。
- `model_calls`：每次尝试一行，增加 `attempt_no`、`actor_id`、`purpose`、`proposal_id`、token、成本/币种、`error_code`、`error_message`、`completed_at`；状态 `streaming`/`ok`/`failed`/`aborted`。
- 审计：成功写 `ai.proposal.generate` success；失败写 failure。metadata 只含提案 id、服务商、模型、模式、延迟、token、尝试日志、成本、跳过服务商、字数、基准哈希，不含正文与密钥。事件 `chapter.ai_proposal` 同样不含正文。

调用链：

1. `POST /api/chapters/:id/ai/proposals` 先做权限、租约、章节状态、草稿与加厚长度校验；随后在一个事务里用事务级 advisory lock 串行化同一章的锁获取，再检查 `ai_generation_locks`：未过期则抛 409 `AI_GENERATION_IN_PROGRESS`；已过期则把旧提案与 `streaming` 调用标记为 `failed / AI_ABANDONED`，再写入新提案并 upsert 锁。提案先落库，锁的外键再引用提案。
2. 按优先级加载最多 3 个已启用服务商，逐个调用 `POST {baseUrl}/chat/completions`，`stream: true` 并请求 `stream_options.include_usage`；整体截止 120 秒，单次尝试的剩余时间不会超过该截止。
3. 重试规则：单服务商最多 2 次、总计最多 4 次，退避 600/1200/1800 ms。仅当尚未输出正文增量时可重试：HTTP 408/429/5xx、空输出、网络错误可在同服务商重试；401 等明确错误直接切换下一候选；若 HTTP 400 的响应明确指向不支持 `stream_options`，同服务商去掉该参数重试一次（此后用量可能缺失，成本记为未知）。超时与取消不重试。已输出正文后失败立即停止，保留部分正文与失败记录，不拼接不同来源的正文。
4. SSE 事件：`meta`（提案 id、首个候选、上下文包、基准哈希、候选/跳过数量）、`delta`（正文增量）、`attempt`（重试或切换及下一个服务商）、`done`（完整提案）、`error`（失败码与消息）；15 秒心跳注释防代理断开。
5. 每次尝试先插入 `streaming` 调用，结束后写 `ok`/`failed`/`aborted`、token、成本、延迟与错误。正常结束（成功、失败、客户端断开）都会释放锁；释放失败时依赖 TTL 回收；下一次生成会回收过期锁并标记旧记录为 `AI_ABANDONED`。
6. 输出上限 60,000 字；空输出、超限、超时、HTTP 错误、上游错误、客户端断开都落失败状态，不补造成功。
7. 成本：仅按服务商配置的每百万 token 输入/输出价与上游返回的 token 用量计算，保留四位小数；价表缺失或用量缺失时为 `null`，界面显示未知。它是估算值，不是供应商账单。M5-B 阶段二起，生成调用在发起前受工作区月度预算预留限制，见第十七节；流式途中不做硬中断。

上下文包：

- 本章计划（人物/目标/阻碍关键词）、作者补充要求、上一章正典结尾 1200 字、当前已保存草稿（续写取尾 3000 字；加厚取全文，上限 8000 字，超出拒绝）。
- 每段记录 `chars / usedChars / truncated`，界面以字符数展示；M4-A 增加正典检索片段，检索查询只用本章计划关键词与作者补充要求、排除当前章，引用格式 `[R1] 第N章《标题》·vX·第a-b段`。设定集、角色档案、伏笔台账仍未建库，显式标注，不假装已检索。
- 检索状态 `ok/lexical/unavailable`、原因、引用与覆盖度随提案上下文一起保存并展示；检索失败不阻断生成，`contextHashOf` 不变（检索是非确定性的展示上下文，不进入门禁证据）。
- 系统提示只要求中文小说正文、维持视角与既定事实、使用计划要素、结尾留钩子；不得提及 AI/提示词/上下文，不得编造冲突的硬事实。

人工边界：

- 提案永不自动写编辑器；用户点击采用后才追加/替换编辑区，且只标记“未保存”。
- 采用后仍走保存草稿 → 五门禁 → 暂存 → 提交；AI 不跑门禁、不暂存、不提交、不豁免。
- 提案基于旧草稿时二次确认；历史提案可回看，但同样要经当前草稿与门禁。
- 生成前要求编辑区无未保存修改，避免提案基准与编辑器内容错位；加厚必须有已保存草稿。

测试与验收（2026-10-20）：

- `apps/api/src/m3-runtime.test.ts` 使用真实数据库、`app.inject` 与本地 SSE/HTTP 桩服务，覆盖：同服务商 500 后重试成功并写成本；`stream_options` 不被支持时去掉参数重试；主服务商 401 直接切换备用；未过期锁返回 409 且不调用上游；两个并发请求只有一个取得锁；过期锁回收旧提案/调用；部分输出后断流不重试、仅保留失败记录。
- 单元测试覆盖成本计算与“缺价表/缺用量不伪造成本”；类型检查与全部 API 测试通过。

- 此前 Atria `Atria-Dawn` 流式生成成功；客户端停止与断连均落 `CLIENT_ABORTED`；第 4 章《追兵入巷》由人工采用提案、补写并通过门禁后提交为 v1（`source=human`）。第 3 章的两份提案分别因门禁与人工停止而未直接入库。

## 十三、M4-A 正典索引与混合检索

目标是让 AI 与作者都能检索“当前正典”，同时保证旧版本、草稿和未就绪索引不会被冒充成可检索内容。

数据与版本绑定：

- `canon_chunks`：工作区/作品/章节/正典版本、`chunk_index`、段落与字符起止、原文、CJK bigram 词法文本、内容哈希；`UNIQUE(version_id, chunk_index)`。
- `chunk_embeddings`：chunk 主键、provider、model、dimensions、无固定维度声明的 pgvector 向量；保留 `vector_dims(embedding) = dimensions` 校验。
- `index_status` 增加 `indexing`、`chunk_count`、`provider_name`、`model`、`dimensions`、`attempts`、`next_retry_at`、`last_error`。
- `outbox` 增加 `dedupe_key`（唯一）、`next_attempt_at`、`locked_at`；提交、回滚与手工重建统一用稳定键 `index:<versionId>:reindex`。已有 `pending/processing` 任务时不重复入队、不重置索引状态，返回 `alreadyQueued`；仅 `processed/failed` 允许重新激活。
- 旧版本块保留；检索 SQL 同时绑定 `canon_current.version_id`、`index_status.version_id + ready` 与块自身版本，旧版本不会返回；草稿从不入索引。
- `audit_log.metadata` 由 `0007_audit_metadata_object.sql` 规范化为 JSON 对象并加 CHECK；历史字符串若可解析为对象则还原，否则包成 `legacyValue`，字符串写入会被数据库拒绝。
- 迁移：`packages/db/migrations/0006_m4_retrieval.sql`、`0007_audit_metadata_object.sql`。

索引管线（`apps/worker/src/pipeline.ts`）：

1. 启动与 tick 回收 `processing` 超过 5 分钟的任务；只领取 `next_attempt_at <= now()` 的 pending 任务。
2. 复核任务中的章节/版本/工作区，确认仍是当前正典；落后任务直接消费，不覆盖新状态。
3. 切块目标 500 字、单块上限 800、相邻重叠 80；嵌入输入加“第 N 章 标题”前缀，但存储原文。
4. 每批 16 块、20 秒超时；同模型最多 3 个候选、每个 2 次尝试、退避 600/1200 ms；不同模型不混合故障转移，维度不一致直接失败。
5. 每次 HTTP 尝试写 `model_calls`（`purpose='embedding'`、章节、provider、model、token、成本、延迟、状态），不写正文。
6. 全部批次成功后单事务锁 `index_status`、复核当前版本、删除同版本旧块、写入 chunks/embeddings、置 `ready`；期间出现新提交或索引已 `ready` 则丢弃结果。
7. `ready` 是终态：`markIndexing`、失败/重试/未配置写回都带 `status <> 'ready'` 守卫；迟到的重复任务直接消费，不改状态、不重写片段、不重复调用嵌入。
8. 失败：无可用服务商 → `not_configured` 并消费任务；可重试错误 → outbox 回到 pending，按 1/5/15/60 分钟退避、最多 5 次；401、空正文、维度不符或次数耗尽 → `failed` 并保留原因。

检索（`apps/api/src/services/search-service.ts`）：

- `GET /api/search?q=&workId=&excludeChapterId=&mode=auto|lexical&limit=`，要求登录；工作区内所有成员可检索正典（当前没有章级 ACL）。`mode=lexical` 是诊断用强制词法模式，不调用嵌入服务并返回明确原因；默认 `auto`，AI 上下文检索使用默认值。
- 词法：应用侧生成 CJK bigram + 拉丁词，GIN 表达式索引 `to_tsvector('simple', lexical_text)`；最多 64 个 token，OR tsquery + `ts_rank_cd`；单字/无 token 使用转义后的 `ILIKE` 子串匹配。
- 向量：查询文本用当前启用的首个嵌入服务商嵌入，按 `model + dimensions` 过滤，精确余弦取前 30；查询嵌入失败只降级，不返回 5xx，并写 `model_calls(purpose='embedding_query')`。
- 相似度下限：`SEARCH_VECTOR_MIN_SCORE`（默认 0.4，限制在 0–1）逐条过滤向量邻居；最高分低于阈值时整条向量通道弃用，`semanticReason` 写明“向量最高相似度 X 低于阈值 Y”。该默认值来自本机 `bge-m3` 最初 13 条查询的实测分界（两条域外负例最高 0.385，正例最低 0.436）。后续 6 条近域/混合负例最高 0.508，与正例区间重叠，0.4 无法区分；它只是噪声下限，不是答案性判断。纯语义改写也可能低于近域负例（实测 0.473 vs 0.508），换模型或语料需重测，不能当作通用最优值。
- 融合：词法/向量各取前 30（向量先经相似度下限过滤），RRF(k=60) 取前 8；同章重叠段落只保留排名更高的一条。
- 覆盖度：ready/indexing/pending/failed/not_configured/stale、可检索块数、当前向量模型；没有向量索引、没有服务商、查询失败、模型不一致或最高相似度低于阈值时 `mode=lexical` 并给出原因，绝不标 hybrid；索引模型与当前模型不一致时提示重建。
- 返回：章节、versionId/versionNo、段落区间、摘要、双通道名次/分数、RRF。

AI 上下文与权限：

- 检索查询只用本章计划（实体/目标/阻碍关键词）+ 作者补充要求，不把草稿发给嵌入服务，并排除当前章。
- 取 top 6、总 2400 字、单块 500 字、每章最多 2 块；写入 `canon_retrieval` 段与 `[R1] 第N章《标题》·vX·第a-b段` 引用；提案上下文/历史显示状态、原因、引用与覆盖度。
- 检索失败不阻断生成；`contextHashOf` 完全不变，检索不进入门禁证据。
- 单章重建限所有者/主笔，工作区重建限所有者；重建只重算投影，不删除正典。

界面：

- 章节检查器索引卡：状态、版本、块数、模型/维度、服务商、尝试次数、下次重试、错误与重建按钮。
- 检索面板：覆盖度、搜索框、结果（章节/版本/段落/摘要/词法向量名次）、降级原因；点击结果切章。
- AI 提案面板：检索状态、原因、引用与覆盖度；历史提案同样展示。
- 服务商表单：用途选择、嵌入输入价、密钥复用、嵌入探测、远程出站提示；编辑时用途只读。

## 十四、M4-B 显式授权与无人值守作业

目标是在不削弱门禁的前提下，让所有者/主笔显式授权一段章节由系统逐章续写；系统只能使用授权内的作品、范围、章数、预算与远程策略，任一硬门禁失败都不入库。

数据与权限：

- `automation_mandates`：工作区、作品、`mode='continue'`、起止章号、`max_chapters`、`target_words`、续写指令、是否自动入库、是否允许远程模型、是否显式接受非生产门禁（`allow_non_production_gates`，默认 false）、可选预算/币种、状态（`active/revoked/expired`）、截止时间与创建/撤销人。
- `automation_jobs`：授权、作品、状态（`queued/precheck_failed/running/paused/stopped/completed/failed/interrupted`）、预检快照、计数（总章/入库/暂存/失败/跳过）、累计费用/费用未知、`runner_id`、心跳、暂停/停止标记、当前章、最后错误与结束时间。
- `automation_job_chapters`：逐章状态（`pending/running/committed/staged/gate_failed/no_output/failed/skipped/interrupted`）、原因、提案/评估/版本/费用。
- 仅所有者/主笔可创建授权、预检、创建/暂停/恢复/停止作业与撤销授权；作者/审阅者/读者/计费/AI 返回 403。AI 服务主体每个工作区一个（`kind='ai'`，`ai+<workspaceId>@service.yunshuo.local`），无成员关系、不能开发登录，只能作为 runner 的执行 actor。
- 迁移：`packages/db/migrations/0008_m4b_automation.sql`、`0009_automation_guards.sql`（非生产门禁确认）。

预检（`automation-service.runPreflight`）：

- `POST /api/automation/preflight` 只读数据库，不发起任何模型调用；创建作业前必须通过。
- 13 项检查：授权有效/未过期、章节范围、章节可写、无并发作业、门禁可行性（规则集与章节计划能否判定五门禁）、模型服务商、远程策略、预算、人工租约、自动入库策略、豁免权限（AI 无豁免）、备份、连通性。
- 当前唯一规则集 `dev-v0` 的 `is_production=false`。若授权开启自动入库但未显式接受非生产门禁，`gate_feasibility` 失败并阻止创建作业；已接受则给提醒，说明入库仍按该规则集判定；仅暂存时只提醒，不阻止。
- 授权未允许远程模型时，候选服务商出现非本机端点即失败；设置了预算但服务商未定价或币种不一致也失败；无预算、未定价、备份未接入、连通性未验证为提醒项。
- 预检失败时 `createJob` 直接返回 409 与完整预检快照，不落地作业；`precheck_failed` 状态保留在 schema 中。

runner（`apps/api/src/services/automation-runner.ts`）：

1. API 启动时默认启用，`AUTOMATION_RUNNER=0` 可关闭；每 `AUTOMATION_POLL_MS`（默认 2000 ms）领取一个 `queued` 作业，写 `runner_id` 并每 20 秒心跳。
2. 每次只处理一章：校验授权仍有效、预算未达上限、章节仍在授权范围且可写；有他人有效租约时跳过（`external_state`）。领取作业后还会重新加载规则集：若自动入库使用非生产规则集而授权未显式接受，直接把作业置为 `failed`，不再生成，防止预检后修改授权绕过。
3. 以 AI 主体取得章节租约，调用生成提案 → 保存草稿 → 跑五门禁；未输出/空正文记 `no_output`，生成失败记 `failed`，门禁未通过记 `gate_failed`，均保留提案与评估但不入库。
4. 门禁通过后暂存；`allowAutoCommit=false` 时停为 `staged`（等待人工提交），否则以 `job:<jobId>:<chapterId>:commit` 幂等键提交正典，来源 `batch`。
5. 章与章之间检查暂停/停止标记；暂停、停止不会打断正在进行的模型调用，在下一边界生效。撤销授权会停止其下排队/暂停的作业。
6. 心跳超过 5 分钟视为 `interrupted`，不自动重试，只能人工恢复；API 重启导致的在途章节同样如此。
7. 预算在每次模型调用前计算：读取授权累计已花费金额，按服务商输入/输出价与保守输入预留（2 token/字 + 64）推导本次可用的 `max_tokens`，并把手工默认上限与剩余额度取小。低于 128 个输出 token 时以 `BUDGET_INSUFFICIENT` 在调用前中止，章节释放回 `pending`，作业暂停；价表、币种或用量未知时以 `BUDGET_GUARD_UNAVAILABLE` 同样暂停。失败尝试的已计费用会从剩余额度扣除；检查点仍累计花费。**它依赖服务商遵守 `max_tokens`，输入 token 是估算值，不是供应商账单级硬保证，也不能中断已发出的调用。**
8. 同一工作区同一时间只允许一个 `queued/running/paused` 作业；没有多 runner 抢占调度。

界面：

- 页头“自动作业”仅所有者/主笔可见；弹窗分“作业”和“授权与预检”两页。
- 授权表单限定作品、章号范围、章数、目标字数、指令、有效期、预算、自动入库、远程模型与“接受非生产门禁规则集”确认；界面明确标注只支持续写、AI 无豁免、预算为调用级 `max_tokens` + 章节检查点估算、备份需手动执行。
- 授权卡片与启动器摘要显示“已接受非生产门禁”或“未确认非生产门禁”徽标，避免把确认状态藏在表单里。
- 作业启动器只列出授权范围内“规划中/写作中”的章节；必须先运行预检，展示 13 项结果与服务商/预算明细；通过后才允许启动。
- 作业详情展示进度、入库/暂存/失败/跳过、累计费用、授权状态、心跳、每章状态与原因，以及暂停/恢复/停止/撤销；诊断文案明确“AI 不申请、不批准豁免”“门禁失败不入库”“备份需手动执行”。

## 十五、M5-A 本地账号、邀请与工作区

目标是在不引入 OIDC/邮件服务的前提下，让工作区具备可用的本地账号、一次性邀请、成员角色与多工作区切换，并保持“谁、在哪个工作区、什么角色”可审计。

数据与迁移（`packages/db/migrations/0010_m5_identity.sql`）：

- `users.password_hash`、`password_updated_at`；`users_email_lower_key` 保证邮箱大小写不重复。
- `sessions.workspace_id`（非空，工作区删除级联）、`auth_method`（`dev`/`password`）；迁移时按最早成员关系回填旧会话，无法回填的会话删除。
- `workspace_invites`：工作区、邮箱、角色、`token_hash`、邀请人、到期、接受人/时间、撤销人/时间；部分唯一索引保证同工作区同邮箱只有一个未接受未撤销邀请。
- 角色集合：`owner / lead / author / reviewer / viewer / billing`，另有系统 `ai` 主体；`canViewMembers` 限所有者/主笔，`canManageMembers` 限所有者，`canInviteRole` 允许所有者邀请任意人类角色、主笔邀请非 owner/lead 角色。

登录与会话：

- `POST /api/auth/login`：带 `password` 时走本地密码；不带时仅在 `DEV_AUTH=1` 下走开发身份。密码路径对未知邮箱执行 dummy scrypt，成功/失败不泄露账号是否存在；统一失败码 `LOGIN_FAILED`。
- 限流在 `login-rate-limit.ts`：键为 `email|ip`，窗口 10 分钟，失败上限 8，超限 `LOGIN_RATE_LIMITED`；成功登录清空。键表有上限，超出时先清理过期项、再淘汰最旧键，避免任意邮箱把内存撑大。它是单进程内存实现，不跨重启/实例共享。
- 会话 Cookie `yunshuo_session`：签名、httpOnly、SameSite=Lax、7 天、生产 Secure。每次 `requireAuth` 通过 `sessions.workspace_id` 连接当前工作区成员关系，所以角色变化立即生效，不需要重新登录；成员被移除时会话被删除。
- `GET /api/me` 返回当前工作区与角色；`GET /api/auth/workspaces` 返回用户全部非 AI 成员关系；`POST /api/auth/workspace` 仅更新当前会话的工作区绑定。切换不存在成员关系的工作区返回 403。
- 开发身份：`GET /api/dev/users` 与无密码登录仅在 `DEV_AUTH=1` 时可用，否则返回 `DEV_AUTH_DISABLED`；`NODE_ENV=production` 下无论 `DEV_AUTH` 如何设置都强制关闭。生产环境缺少 `SESSION_SECRET` 时启动直接失败。

邀请与成员：

- 创建：`POST /api/workspace/invites`，所有者/主笔；令牌 `randomBytes(32).toString('base64url')`，入库仅 SHA-256；返回 `acceptUrl` 只在本次响应出现。有效期 1–168 小时，默认 72；同邮箱已有待接受邀请返回 `INVITE_PENDING`，已是成员返回 `ALREADY_MEMBER`，AI 邮箱返回 `AI_ACCOUNT_NOT_INVITABLE`。创建时会把已过期未撤销的同邮箱邀请标记为撤销。并发创建由部分唯一索引兜底，唯一冲突映射为 409 `INVITE_PENDING`，不会落成 500。
- 预览/接受：`GET /api/invites/:token` 返回工作区、邮箱、角色、到期与账号是否存在；预览时无效 `INVITE_INVALID`，已用/已撤销/过期均为 410（`INVITE_USED`/`INVITE_EXPIRED`）。`POST /api/invites/:token/accept` 可以带现有会话，也可以无会话接受：账号不存在时创建账号（称呼 + 至少 10 位密码）；账号已存在时要求密码，在邀请事务内校验通过后直接使用该账号加入工作区，不再要求先登录。这样被移出全部工作区的账号也能通过新邀请回归；未带密码的已有账号会收到 409 `ACCOUNT_EXISTS`。密码校验失败的 401 `LOGIN_FAILED` 会计入 `invite-accept|token|ip` 限流（8 次/10 分钟），已登录接受不受影响。接受时已用/已撤销返回 409 `INVITE_USED`、过期返回 410 `INVITE_EXPIRED`；接受后会话切到目标工作区。密码哈希在邀请状态与账号存在性校验通过后才计算；并发注册同一新邮箱由邮箱唯一索引兜底并返回 409 `ACCOUNT_EXISTS`，并发加入同一工作区由成员主键兜底并返回 409 `ALREADY_MEMBER`。若两个并发请求都提供了同一密码，二者可以分别加入各自的工作区，但仍只会创建一个账号。
- 成员列表：所有者/主笔；包含 `kind='human'|'ai'`，AI 主体显示为不可变。
- 改角色/移除：仅所有者；先在事务内 `SELECT ... FOR UPDATE` 锁工作区行，再锁目标成员关系；这会让所有改变所有者数量的操作串行化，避免两名所有者并发降级/移除时把所有者清零。最后一名所有者不能降级或移除（`LAST_OWNER`）；AI 成员返回 `AI_MEMBER_IMMUTABLE`；移除时同步删除该工作区会话。改角色写 `member.role.update`（before/after），移除写 `member.remove`。
- 邀请撤销：所有者/主笔可撤销本工作区未接受未撤销邀请；不存在/已接受/已撤销返回 `INVITE_NOT_FOUND`。审计写 `member.invite.revoke`，不含 token。

前端：

- 登录页：邮箱密码表单 + `DEV_AUTH` 开启时的开发身份卡片；开发列表按邮箱去重（同一账号在多个工作区只显示一次）；开发接口不可用时如实提示，仍可密码登录。
- 邀请页 `/invite/<token>`：预览工作区/邀请邮箱/角色/到期；未登录且无账号时填写称呼与密码注册；已有账号时直接填写该账号密码并调用接受接口，成功后会话直接绑定到邀请工作区；登录邮箱不匹配时提供退出；接受成功后回到写作台并切到新工作区；错误码映射为可读文案。
- 页头：多工作区时显示选择器（`名称 · 角色`），切换后章节与权限随会话变化；所有者/主笔显示“成员与邀请”。

## 十六、M5-B 阶段一：邮件、密码修改与重置

范围是本阶段可本地完整验收的部分：邮件投递三模式、邀请邮件、密码修改与一次性重置、账号级安全事件与投递元数据。本阶段不含计费归属（已由阶段二补齐）与 OIDC/SSO（已由阶段三补齐），也没有占位界面冒充已接入。

数据与迁移（`packages/db/migrations/0011_m5b_account_security.sql`）：

- `auth_events`：账号级安全事件（`password.change / password.reset.request / password.reset.complete`，成功/失败），含 `user_id`（可空，用户删除后保留事件）、IP、UA、对象 metadata 与时间；与工作区级 `audit_log` 分开，不记录密码、哈希或令牌。
- `password_reset_tokens`：`token_hash` 唯一、请求 IP、到期与使用时间；部分唯一索引保证每个用户同时只有一个未使用令牌。
- `mail_messages`：收件人、模板（`workspace_invite / password_reset`）、provider、状态、错误码/消息与发送时间；**没有正文列，也不存邀请/重置令牌**。工作区/用户外键删除时置空，保留投递记录。

邮件模式：

- `smtp`：nodemailer 真实发送；至少需要 `MAIL_HOST`，`MAIL_FROM` 默认 `云说 <no-reply@yunshuo.local>`。发送失败返回 `failed` 与截断到 300 字的错误消息，不抛出到业务事务。
- `memory`：非生产默认；只把正文放入 API 进程内数组（最多 50 封），状态 `captured`，不真实投递。生产设置 `memory` 会在启动时失败。
- `off`：生产默认；状态 `not_configured`、错误码 `MAIL_DISABLED`，邀请与重置仍可生成链接。
- 状态语义：`sent / captured / failed / not_configured`；界面直接显示对应文案，不把 `captured` 或 `not_configured` 写成“已发送”。`smtp` 缺配置时返回 `not_configured`（`MAIL_NOT_CONFIGURED`）。
- 开发邮箱：`GET /api/dev/mailbox` 仅在 `DEV_AUTH=1` 且 `MAIL_MODE=memory` 时开放，否则 404 `DEV_MAILBOX_DISABLED`；API 绑定 127.0.0.1，登录页按需读取并可直接打开邀请/重置链接。

邀请邮件：

- 创建邀请在同一事务成功后调用 `sendMail`；邮件失败不回滚邀请，响应仍返回 `acceptUrl`，`mail` 字段携带 provider、状态与错误码。
- 邮件正文包含邀请人、工作区、角色、有效期与一次性接受链接；`mail_messages` 只记录元数据，令牌仍只在创建响应出现一次。

密码修改：

- `POST /api/auth/password/change`，需登录；校验当前密码，新密码至少 10 位且不能与当前密码相同；无密码账号返回 409 `PASSWORD_NOT_SET`。
- 成功后在同一事务内：以旧哈希为条件更新密码（并发修改返回 409 `PASSWORD_CHANGED_CONCURRENTLY`）、删除该账号除当前会话外的全部会话、作废全部未使用重置令牌，并写 `password.change` 成功事件（含撤销会话数）。
- 当前密码错误返回 400 `CURRENT_PASSWORD_INVALID` 并写失败事件；按“用户+IP”复用登录限流（8 次失败/10 分钟），成功后清空。

忘记密码与重置：

- `POST /api/auth/password/reset-request`（202）：无论邮箱是否存在、是否孤儿账号，均返回同一提示；只对 `kind='human'` 且至少属于一个工作区的账号生成令牌与邮件。
- 令牌 32 字节随机 base64url，只存 SHA-256，30 分钟；重新申请会在事务内作废旧令牌；链接为 `${WEB_ORIGIN}/reset/<token>`。
- 限流：邮箱+IP 5 次/15 分钟、IP 30 次/15 分钟；每次请求都计数，超限返回 429 `RESET_RATE_LIMITED`；开发邮箱开关随响应返回（仅 DEV_AUTH + memory）。
- `POST /api/auth/password/reset`：事务内 `FOR UPDATE` 锁令牌，复核未使用且未过期，更新密码、标记该用户全部令牌已用、删除全部会话，并写 `password.reset.complete` 事件（含撤销会话数）；令牌一次性，过期令牌会被标记已用并返回 400 `RESET_TOKEN_INVALID`。无效尝试按 IP 20 次/15 分钟限流，成功后清空。

前端：

- 登录页增加“忘记密码”模式：提交后显示统一提示；DEV_AUTH + memory 时显示“开发内存邮箱”，按需读取并打开链接。
- `/reset/<token>`：设置新密码与确认；成功后提示所有旧会话与未使用链接已失效，返回登录。
- 页头“账号”：显示邮箱与当前工作区角色，修改密码并在成功后显示撤销的其他会话数；提示种子账号需先用“忘记密码”设置密码。
- 团队面板：邀请创建后显示邮件状态与一次性接受链接；列表仍是最近 50 条邀请，可撤销。

测试与验收（2026-10-21）：

- `apps/api/src/m5b-account-security.test.ts` 11 个用例，覆盖邀请邮件与元数据边界、密码修改撤销会话与作废重置令牌、重置一次性/过期/重复申请、未知/孤儿/已知邮箱同提示、重置限流、`MAIL_MODE=off` 状态与无密码账号。当时全量 **119 项**通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 72 + worker 10），类型检查 9/9 通过。
- 浏览器验收使用独立测试库与 3101/5176 实例（`MAIL_MODE=memory`、`DEV_AUTH=1`、关闭 runner）：无密码账号申请重置 → 登录页开发邮箱读取邮件 → 设置新密码 → 新密码登录 → 账号内修改密码 → 旧密码被拒、新密码可用 → 邀请成员并显示“已写入开发内存邮箱，未真实投递”。临时用户/工作区/会话/邀请/邮件/安全事件/重置令牌与临时进程已清理，测试库恢复到 4 用户/1 工作区基线。
- 浏览器验收只证明状态流转与界面口径；SMTP 真实发信路径尚未对真实邮件服务器验收，内存模式明确不真实投递。

诚实边界：

- 邮件正文与令牌不落库，但 SMTP 服务商、收件人邮箱与错误消息属于投递元数据，会保留在 `mail_messages`；生产部署需自行评估日志与数据保留策略。
- 开发内存邮箱不是邮件服务，进程重启即清空，最多 50 封；生产禁止使用。
- 重置令牌 30 分钟、一次性；没有“记住此设备”、MFA、密码历史或密码强度字典校验，只要求至少 10 位。
- 账号级安全事件与工作区审计分表；当前没有告警、邮件通知或管理员事件查看界面，只能查库。
- 登录、密码修改、重置与邀请接受限流都是单进程内存实现，重启清空、多实例不共享。

## 十七、M5-B 阶段二：费用归属、工作区预算与计费管理员

范围是工作区月度生成预算、调用前预算预留与清算、费用归属报表、`billing` 计费管理员角色与服务商价表维护。供应商账单对账与发票导入已由阶段四补齐，作者配额与自动分账未做（OIDC/SSO 由阶段三补齐），也没有占位界面冒充已接入。

数据与迁移（`packages/db/migrations/0012_m5b_billing.sql`）：

- `workspace_budgets`：工作区主键、月度上限、币种（CNY/USD）、最后修改人与时间。上限可以为 0；清除预算即删除该行，回到“未设置预算”。
- `model_calls` 增加 `job_id`（无人值守调用按作业归属）、`reserved_cost` 与 `reserved_currency`；预留字段成对写入，金额非负；部分索引只覆盖存在预留的调用。
- 预留只在调用进行中存在；成功、失败、中止或超时回收后清空。已发生费用写入 `cost/cost_currency`，不把预留当实际账单。

预算闸门：

- 只有 `chapter_proposal`（手工提案与无人值守作业）占用和受限于工作区月度预算；`embedding` 与 `embedding_query` 不阻断、不占生成额度，费用单独计入报表。
- 未设置预算行时不阻断生成，调用照常记录估算费用；报表状态 `not_configured`，并明确提示“预算不会在额度耗尽时阻断”。
- 设置预算后，调用前在事务内 `FOR UPDATE` 锁定预算行，要求服务商输入/输出价完整且币种与预算一致，否则以 `BUDGET_GUARD_UNAVAILABLE` 阻止本次调用。
- 可用额度 = 月度上限 − 本月已计生成费用 − 进行中生成预留。输入 token 按“2 token/字 + 64”保守估算；输出上限取请求上限与剩余额度可买的 token 数中较小者，最低要求 128 个输出 token。预留成本按输入估算费 + 输出上限费用计算，向上保留四位小数。
- 额度不足、只能买到低于 128 个输出 token、或预留本身超过可用额度时，以 `BUDGET_INSUFFICIENT` 在调用前阻止，并写入一条 `status='blocked'` 的 `model_calls`（错误码、说明、费用 0）。上游没有被调用，也不伪造用量。
- 每次重试都重新预留；失败尝试的实际已计费用从本次运行剩余额度中扣减。上游未返回可计费用量或币种不一致时停止后续尝试，记为 `BUDGET_GUARD_UNAVAILABLE`。并发预留由预算行锁串行化；测试确认预算 2.5 时两笔 1.8 预留只有一笔成功。
- 超过 15 分钟仍为 `streaming` 的调用在预算计算、报表读取与下一次生成预留时回收为 `failed / CALL_STALE`，清空预留并标注“实际费用未知”；该清算不依赖工作区是否配置预算。
- 设置预算后，不完整价表、币种不一致或已耗尽都会阻止生成；清除预算才会关闭强制。价表变更只影响之后的估算，历史调用保留已记录金额。
- 币种切换：存在其他币种的在途预留时，修改预算币种返回 409 `BUDGET_CALLS_IN_PROGRESS`，避免旧币种预留脱离新预算；阻断调用不参与“其他币种调用”统计。

费用归属报表（`GET /api/billing/report`）：

- 固定为当前自然月，返回预算与预算用量、服务商价表状态、按币种汇总的已计/预留/进行中调用，以及按用途、成员（含 AI 主体）、作业、章节四个维度的归属。
- 未知费用单列，不摊进已知合计，也不猜造价格；未知判定为“无费用、无预留、非进行中/阻断、且错误码不属于 `BUDGET_*`”。列表最多展示 50 条，另有总数。
- 阻断调用不计入费用合计，单独给出 `blockedCallTotal`；进行中调用单列预留，避免把预留冒充已花费。
- 多币种分组展示，不换算；价表返回名称、模型、用途、优先级、价格、币种与“完整/不完整”，不返回端点或密钥。
- 权限：所有者、主笔与计费管理员可读；仅所有者与计费管理员可改预算与价表。计费管理员不能读章节/草稿/检索/AI 提案/服务商配置/自动化授权，也没有正文入口；报价接口只覆盖价表字段。

价表与审计：

- `PATCH /api/billing/prices/:id`：生成服务商输入/输出价必须同时填写或同时留空；嵌入服务商只允许输入价；不允许通过该接口修改端点、模型、密钥或启用状态。
- `billing.budget.update` 审计记录修改前后上限与币种；`billing.provider_price.update` 只记录服务商名称、模型、用途与修改前后价格，不含端点与密钥。清除预算也写审计。

无人值守作业：

- 预检新增 `workspace_budget`：未设预算为提醒；已设预算但没有启用的生成服务商、价表不完整、币种不一致或额度耗尽为失败；本月存在未知费用为提醒。
- runner 在章节检查点再次复核工作区预算，失败时以“工作区预算保护”为原因暂停作业；授权预算与工作区预算独立，取更严格者。
- 预算只约束调用前与章节边界，不做流式途中硬中断；单次调用另有 M4-B 的 `max_tokens` 上限。

前端：

- 所有者与主笔页头显示“计费”；所有者/计费管理员可设预算、维护价表；主笔只读报表。
- `billing` 角色登录后进入独立计费台，不加载章节目录，不显示服务商、自动化或正文入口。
- 预算卡片显示未设置/正常/已耗尽/存在未定价调用，以及已计、预留、剩余、未知调用与其他币种调用；报表按用途、成员、作业、章节分栏，未知费用有独立表格。
- 价表不完整时明确显示“生成成本将显示为未知”；预算提示同时说明“嵌入检索不受影响”。

测试与验收（2026-10-21）：

- `apps/api/src/m5b-billing.test.ts` 8 个用例：角色读写边界与内容隔离、预算审计、价表成对/嵌入只允许输入价与端点密钥不可见、计费管理员访问章节/AI 提案/检索/服务商/自动化被拒、报表归属与未知/阻断费用、并发预留与嵌入不占生成预算、有在途预留时不能切换预算币种且阻断调用不计入其他币种、未设置预算时不阻断且不伪造预留成本。
- 并发用例暴露并修复了预算预留重复扣除输入费用的问题（`afterPrompt` 与含输入费的预留成本重复比较）；修复后 7/7 通过。
- 全量 **151 项**通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 104 + worker 10），类型检查 9/9 通过。
- 浏览器验收：临时 `billing` 用户只看到计费台，无章节、正文、服务商与自动化入口；报表如实显示已计、未知与阻断调用；预算可保存/清除，价表可临时填写并还原；所有者可见计费入口，主笔只读，作者无入口。临时账号、会话、成员关系、审计、预算与价表修改已清理，演示状态恢复。

诚实边界：

- 预算是按价表与 token 用量的估算，不是供应商账单。未知费用调用不会被预算覆盖，实际支出可能超过上限；没有作者配额或告警阈值；供应商账单导入与估算对账见第十九节。
- 流式途中不能硬中断：`max_tokens` 只在发起前限制。进程崩溃留下的预留 15 分钟后才回收，期间既可能低估当月支出，也可能暂时阻断新调用；回收后实际费用仍未知。
- 嵌入与检索不占生成预算，可能在预算耗尽后继续产生费用，报表会单独显示。
- 自动作业只在章节检查点复核预算，正在生成的章节不会因中途超额而停止。
- 计费管理员的正文隔离是应用层权限与路由限制，数据库没有 RLS；清除预算会立即关闭强制，改价表会影响后续估算。

## 十八、M5-B 阶段三：OIDC/SSO 登录与账号绑定

范围是“一个部署接一个 OIDC IdP”的登录闭环：授权码 + PKCE、state/nonce、ID Token 校验、稳定身份绑定、邀请自动开户。不实现多 IdP、MFA 策略、SCIM、IdP 单点登出或企业域名发现。

配置（`apps/api/src/env.ts`）：

- 必填：`OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_REDIRECT_URI`；启用后缺少任一项启动失败。
- 可选：`OIDC_CLIENT_SECRET`（缺省按公共客户端 PKCE）、`OIDC_SCOPES`（默认 `openid profile email`，必须包含 `openid`）、`OIDC_PROVIDER_NAME`（登录按钮文案）、`OIDC_AUTO_PROVISION`（默认关闭）。
- `NODE_ENV=production` 时 issuer 与 redirect URI 必须是 HTTPS，拒绝带用户名/密码的 URL；客户端密钥只从环境变量读取，不入库、不回显。

流程（`apps/api/src/services/oidc-service.ts`、`apps/api/src/routes/auth.ts`）：

1. `GET /api/auth/config` 公开返回 `oidcEnabled / oidcProviderName / oidcAutoProvision`，不返回 issuer、client id 或任何密钥。
2. `GET /api/auth/oidc/start` 生成 32 字节随机 `state` 与 `nonce`、PKCE S256 `code_verifier`，把 `{state, nonce, codeVerifier}` 放入 10 分钟有效的签名 httpOnly Cookie（`yunshuo_oidc_state`，SameSite=Lax），再 302 到 IdP 授权端点。
3. `GET /api/auth/oidc/callback` 先核对 query `state` 与 Cookie，再清除 Cookie；用授权码换 ID Token（支持 `client_secret_basic`、`client_secret_post` 与公共客户端 `none`）。随后通过 discovery 的 JWKS 验签，并校验 issuer、audience、exp/iat、nonce；算法白名单只含非对称算法，显式拒绝 HS*。失败只重定向到 `/?oidc_error=<CODE>`，服务端只记录错误码。
4. 成功后沿用现有签名会话 Cookie 建立会话，`auth_method='oidc'`；会话仍绑定工作区，成员关系每次请求重载。

身份绑定：

- 迁移 `0013_oidc_identity.sql` 新增 `user_identities`：`user_id`、`provider`、`subject`、`email`、`email_verified`、`last_login_at`，`(provider, subject)` 唯一。`sessions.auth_method` 约束扩展为 `dev / password / oidc`。
- 已有 `(issuer, sub)` 绑定优先，IdP 更改邮箱不会把登录串到其他账号；只更新展示邮箱与最后登录时间。
- 首次登录要求 `email_verified=true`，按小写邮箱关联既有人类账号并写入绑定；未验证邮箱直接拒绝，不建号。
- 无既有账号时，只有 `OIDC_AUTO_PROVISION=1` 且存在该邮箱的待接受邀请才创建用户、成员关系并接受邀请；同一邮箱用 `pg_advisory_xact_lock(hashtext('oidc:<email>'))` 串行化，避免并发建号。否则返回 `OIDC_ACCOUNT_NOT_FOUND`（无邀请）或 `OIDC_INVITE_REQUIRED`（未开自动开户）。
- 数据边界：不保存 ID Token、access token、授权码或客户端密钥；不把 OIDC 登录写入工作区正文相关表。

前端（`apps/web/src/components/LoginScreen.tsx`）：

- 登录页读取公开配置；启用时显示“使用 {providerName} 登录”，与密码表单之间用分隔线区隔；未启用时不显示 SSO 区块，不放置假按钮。
- `?oidc_error=` 按码映射为可读提示（如账号未开通、邀请缺失、令牌校验失败、状态过期），未知错误只提示“登录未完成”，并清理 query 参数。
- 文案说明首次登录需要已验证邮箱、既有账号或待接受邀请；不承诺自动开通。

测试（2026-10-22）：

- `apps/api/src/m5b-oidc.test.ts` 9 个用例，使用本地模拟 IdP（discovery、JWKS、authorize、token）走真实 HTTP 回调：公开配置不泄露密钥；既有邮箱账号登录；IdP 改邮箱后 subject 仍绑定原账号；已验证邀请身份自动开户并接受邀请（审计 metadata `{via:'oidc', accountCreated:true}`）；无邀请不建号；未验证邮箱拒绝；state/Cookie 篡改拒绝；错误 audience 与 nonce 拒绝且不写绑定；授权码重放不产生第二份会话。
- 全量 **151 项**通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 104 + worker 10），类型检查 9/9 通过。
- 模拟 IdP 只验证协议与绑定逻辑，尚未对真实 IdP 做浏览器验收；SSO 按钮、错误提示与回调跳转仍需在真实 IdP 租户上复验。

诚实边界：

- 不调用 IdP 的 end-session 端点，退出只注销本地会话；用户在 IdP 侧仍保持登录。
- 不支持多 IdP 并存、组织域名发现、MFA 策略、SCIM 供给或组映射；角色仍由本地邀请/成员管理决定，IdP 声明不直接授予工作区角色。
- `email_verified` 的可信度取决于 IdP；首次绑定依赖邮箱，绑定建立后以 subject 为准。
- 客户端密钥只存在 API 进程环境变量中；轮换密钥需要重启 API。
- OIDC 登录与其他登录方式共用单进程内存限流边界；多实例部署仍需共享限流与 CSRF/Origin 加固。

## 十九、M5-B 阶段四：供应商账单对账与发票导入

范围是把供应商账单 CSV 导入系统，与本地按价表/token 估算逐模型对照，并由人工标记复核或争议。不做发票 OCR、税务合规、自动分账、付款或供应商侧核实。

数据与迁移（`packages/db/migrations/0014_provider_bills.sql`）：

- `provider_bills`：工作区、服务商、服务商名称快照、发票号、账期起止（date）、币种（CNY/USD）、可空申报总额 numeric(18,6)、状态 imported/reviewed/disputed、复核说明/人/时间、导入人、时间戳。`(workspace_id, provider_id, invoice_no)` 唯一，`period_end >= period_start`。
- `provider_bill_lines`：账单、行号、模型、可空输入/输出 token、非负金额、备注；`(bill_id, line_no)` 唯一。删除账单级联删除明细；删除已被账单引用的服务商被 RESTRICT。
- 数据库不保存 CSV 原文件、发票文件或任何密钥，只保存解析后的账单行。

导入（`POST /api/billing/bills/import`）：

- 请求：服务商 ID、发票号、账期、币种、可选申报总额、CSV 文本。CSV 表头固定 `model,input_tokens,output_tokens,amount,note`（note 可空），支持 BOM、CRLF、带引号逗号与双引号转义；最多 5000 行、1MB；金额最多 6 位小数，token 非负整数。
- 校验失败返回 `BILL_CSV_INVALID` 并带行号；账期格式或倒置返回 `BILL_PERIOD_INVALID`；服务商必须属于当前工作区。整批在事务内写入账单、明细与 `billing.bill.import` 审计，任一行失败不落库。
- 同一工作区+服务商+发票号重复返回 409 `BILL_ALREADY_IMPORTED`，不覆盖原账单。
- 权限：所有者与计费管理员可导入；主笔只读；作者/审阅者/读者/AI 403。

对账（`GET /api/billing/bills/:id/reconciliation`）：

- 固定使用账单所属服务商，按账期 `[period_start, period_end + 1 day)` 的服务器本地日期查询本地 `model_calls`，按模型聚合已定价调用、费用、token 与费用未知/其他币种/预算阻断计数。
- 账单行按模型聚合（允许同一模型多行）。同模型两侧都有时：币种一致则比较金额（容差 1e-6）与 token；两侧币种不同标 `currency_mismatch`；本地只有未知费用时标 `local_unknown`；仅账单有行标 `bill_only`；仅本地有调用标 `local_only`。
- 响应同时给出：账单明细合计、申报总额与明细差、本地已知估算合计、账单−本地差、差异模型数、未知费用/其他币种/阻断计数。只有阻断调用、没有账单行且没有本地已知费用的模型不出现在明细中，但阻断计数仍在汇总里。
- 所有金额按币种分组，不做汇率换算；本地金额是估算，账单金额是人工导入；差异不会回写调用记录、价表或预算。

复核（`PATCH /api/billing/bills/:id`）：

- 只能把状态改为 reviewed 或 disputed；disputed 必须填写说明（`BILL_REVIEW_NOTE_REQUIRED`），reviewed 说明可选。行锁内更新并写 `billing.bill.review` 审计，记录前后状态与说明；导入人与复核人分别记录，界面显示最近复核人/时间。
- 查看权限为所有者、主笔、计费管理员；复核权限仅所有者与计费管理员；跨工作区账单一律 404 `BILL_NOT_FOUND`。

前端（`apps/web/src/components/ProviderBillsSection.tsx`）：

- 计费弹窗“发票导入与估算对账”：服务商下拉、发票号、账期（默认当月）、币种、可选总额、CSV 文件选择（≤1MB）或粘贴文本。导入成功后自动刷新列表并选中新账单。
- 账单列表展示状态（待复核/已复核/有争议）、账期、行数、明细合计与申报总额；选中后展示汇总卡片、逐模型对照表（账单/本地/差额/token/异常）与复核表单。
- 未定价、其他币种与预算阻断分别计数，不把它们混入“差异”金额；界面明确说明账单来自人工导入、本地金额为估算、差异不改账。

测试与验收（2026-10-22）：

- `apps/api/src/m5b-billing-reconciliation.test.ts` 7 个用例：角色边界（作者 403、主笔只读、导入 403、所有者可读）；导入返回总额/明细合计/行数与审计 metadata；重复发票 409；对账覆盖 match、amount_mismatch、local_unknown、bill_only、currency_mismatch、预算阻断与汇总差额；CSV 表头/金额精度/列数/token 格式与账期错误全部拒绝且不落库；主笔复核 403、争议无说明 400、争议有说明成功并写审计、所有者改已复核后列表同步；跨工作区账单 404 与跨工作区服务商导入 404。
- 全量 **151 项**通过（domain 4 + model-gateway 5 + retrieval 20 + gates 8 + API 104 + worker 10），类型检查 9/9 通过。
- 浏览器验收（开发库）：所有者导入 Atria 账单 2 行，页面显示明细合计 ¥15.00、申报总额 ¥15.20、与明细差 +¥0.20、本地费用未知 5 次、2 个差异模型；保存“已复核”与说明后，状态、复核人周所有者与时间正确回显。验收账单、明细与审计已清理，开发库 `provider_bills` 为 0。

诚实边界：

- 账单金额完全来自人工导入，系统不验证发票真伪、税额、抬头或付款状态，也不抓取供应商 API。
- 本地金额是价表与 token 用量估算；未知费用不猜造。对账只做提示，不自动调整调用记录、价表、预算或会计账。
- 账期按服务器本地日期解释；跨时区供应商账单可能落在相邻日，需要人工判断。
- 不做自动分账、作者配额、账单提醒、发票文件归档或 OCR；CSV 不落库，原始文件需另行保存。
- 工作区隔离仍是应用层条件，未启用数据库级 RLS。

## 二十、Studio 单机部署与旧章导入（交付收尾）

范围是让一台全新主机通过 Docker Compose 启动数据库、迁移、首个所有者、API、worker 与 Web，并能从空工作区导入旧稿进入单章主流程。交付的是**单机试点**，不是高可用生产平台；完整操作手册见 `docs/云说-Studio部署说明.md`。

交付文件：

- `deploy/api.Dockerfile`：API/worker 共用镜像，容器内用 `tsx` 运行 TypeScript；迁移与 bootstrap 复用该镜像。
- `deploy/web.Dockerfile` + `deploy/nginx.conf`：Vite 构建静态资源，nginx 提供 SPA 回退、`/api` 反代、SSE 关闭缓冲、安全响应头与 20MB 请求体上限。
- `docker-compose.studio.yml`：`db / migrate / bootstrap / api / worker / web` 六个服务；只有 `web` 发布宿主机端口，数据库与 API 不对外；`migrate` 成功退出后才启动 API/worker，API 还要求 `bootstrap` 成功退出，`web` 等待 API healthy；worker 显式注入与 API 相同的 `MODEL_KEY_SECRET`。
- `.env.studio.example`：密钥、公开地址、首个所有者、邮件与 OIDC 配置模板；真实 `.env.studio` 被 gitignore 与 dockerignore 排除。`BOOTSTRAP_OWNER_PASSWORD` 只在首次创建所有者时必需，已有所有者后可以留空。
- `apps/api/src/bootstrap.ts`：幂等创建首个所有者账号、工作区与 owner 成员关系；已存在时只警告，不重置密码、不改角色。密码、称呼与工作区名称的校验和 scrypt 哈希只在确认需要新建账号后执行，避免已有部署因删除密码而无法重启。
- 生产密钥守卫：API 在 `NODE_ENV=production` 下要求 `SESSION_SECRET` 与独立于它的 `MODEL_KEY_SECRET`；worker 缺少 `MODEL_KEY_SECRET` 时在连接数据库前退出 1。migrate 与 bootstrap 不加载模型密钥。

健康检查与排障：

- API `GET /api/health` 含一次 `SELECT 1`，数据库不可达返回 503 `degraded`；Web `/healthz` 由 nginx 返回；worker 无 HTTP 健康端点，以进程存活与日志判断。
- nginx 使用 Docker 内置 DNS 重新解析 `api`，API 容器重建换 IP 后无需重启 web；生产 Cookie 带 `Secure`，非 localhost 必须经 HTTPS。
- 备份复用 `scripts/backup-db.sh`（`YUNSHUO_DB_CONTAINER=yunshuo-studio-db`），恢复需先停 API/worker；dump 内含加密后的服务商密钥，必须使用同一个 `STUDIO_MODEL_KEY_SECRET`。自动定时备份与恢复演练未接入。

旧章导入（补齐全新部署的内容入口）：

- 入口：页头“导入旧章”与空工作区引导按钮；所有者、主笔、作者可见，审阅者/读者/计费管理员被 API 403 拒绝。
- 解析：前端按 `## 第N章 标题` 分章（只识别阿拉伯数字章节号），支持 UTF-8 的 Markdown/文本；批次最多 1000 章，前端单文件 18MB、提交前 JSON 请求体 20MB，服务端与 nginx 上限 20MB。非 UTF-8 文件显式报错，不再静默替换为乱码。可指定卷名与卷号，每个卷只创建一次；卷号已存在但卷名不同返回 409 `VOLUME_TITLE_MISMATCH`。
- 写入：每章在单事务内创建 `source='import'` 的正典 v1、当前指针、事件与审计（`chapter.import`，evidence `not_evaluated`），`evaluation_id=NULL`。索引状态取决于工作区是否已有启用的 `embedding` 服务商：有则置为 `pending` 并写入 `index.chapter` outbox（可能产生嵌入费用），无则 `not_configured`。整批在事务内写入，任一章冲突（章号重复、跨卷同号、卷名不一致）返回 409，整批不落库。
- 门禁与检索：界面如实显示“未评估”；没有嵌入服务商时显示“未配置嵌入服务”。导入不会补造门禁结论，也不冒充已通过；导入后仍需走修订 → 草稿 → 五门禁 → 暂存 → 提交才能产生新版本。配置嵌入服务商后，旧导入章不会自动补排队，需要在检索面板重建。
- 并发：同一工作区的导入使用事务级 advisory lock 串行化；两个并发请求导入同一作品与章节号时，一个成功、一个返回 409，作品/卷/章节都只写入一份。
- 测试：`apps/api/src/chapter-import.test.ts` 8 个用例覆盖所有者/作者导入、来源与审计证据、卷复用、卷名不一致、同卷重复章号、并发导入、已配置嵌入服务时排队索引与 outbox、审阅者/计费管理员 403、跨工作区隔离。

验收（2026-10-22，Docker Desktop for Windows）：

- `docker compose config --quiet` 通过；镜像构建成功；`migrate` 退出码 0；`bootstrap` 首次创建 1 个所有者/1 个工作区，第二次运行跳过且不修改密码。

诚实边界：

- 单数据库、单 API、单 worker、单 runner；没有多副本、负载均衡、零停机升级或故障转移，没有内置 TLS/WAF/DDoS 防护，镜像未做签名、SBOM 或漏洞扫描。
- 没有自动备份、异地存放与恢复演练；迁移只向前，不提供自动回滚；数据库隔离仍是应用层 `workspace_id`，未启用 RLS。
- API/worker 镜像含开发依赖，用 `tsx` 直接运行 TypeScript，不是最小化生产运行时；worker 没有 HTTP 健康端点。
- 导入只按章节标题切分，不做正文清洗、去重或格式修复；只接受 UTF-8 与阿拉伯数字章节号；前端文件上限 18MB、服务端 20MB。1000 章 / 20MB 边界已在指向 `yunshuo_test` 的独立实例上用合成正文实测（单事务 4939ms，同一配置另有三次独立运行 4413/4735/4157ms，四次都无超时无 500；见 `docs/m6-perf-max-payload.json`），但那是宿主机单实例读数，不代表 Studio 容器内的表现；导入章门禁“未评估”，不能当作质量通过。
